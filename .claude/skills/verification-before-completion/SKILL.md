# 完了を宣言する前の検証

「テストが通った」ことは必要条件であって十分条件ではない——モックの漏れやカバレッジの不足により、
テストスイートは緑のまま実際の機能は壊れている、ということが起こり得る。これはTDDに限らない。
完了の宣言はすべて、コードを読んで推測したことではなく、このターンで実際に確認したことに
裏付けられているべきである。

## ルール

- **何かを実行せずに「完了」「直った」「動いている」と言わない。** コードを変更したら、
  このターン内で関連するテストやコマンドを実行し、出力を見てから成功を報告する。
- **Greenは必要条件であって十分条件ではない。** TDDのGreenフェーズ後は、
  `.claude/rules/30-testing.md` に従って `run` スキルを推奨する——テストが通ることは、
  機能がエンドツーエンドで正しく動作することをそれ自体で証明するものではない。
- **フロントエンド（Livewire）の変更**: `.php`（Livewireコンポーネント）や `resources/views/livewire/`
  のBladeを読んだだけで「動く」と主張しない。実際に動作している画面を見てから完了を報告する。
- **バグ修正**: 修正前に再発防止テストが失敗し、修正後に通ることの両方を示す——最終的に
  通った状態だけを示さない。
- **このセッション内で検証できない場合**（アプリを実行する手段がない、テストハーネスが
  存在しない、人間による目視・手動確認が必要な場合など）は、成功を主張するのではなく
  その旨を明示的に伝える。これはこの環境でのUIテストに関する既存ルールと同じであり、
  このスキルはそれをあらゆる種類の完了宣言に一般化するものである。
- **コード以外の成果物にも適用する。** このターンで実際にコードを読んで確認していないのに、
  ドキュメントが「コードと一致している」と主張しない。
