# ADR-0001: フロントエンド技術選定（Livewire採用）

## Status
Accepted

## Date
2026-08-15

## Context

本プロジェクトは楽天証券のCSVエクスポートを取り込み、テクニカル/ファンダメンタルズ指標を計算して、保有銘柄の利益確定タイミング判断・セクターリバランス・新規投資判断を支援する個人利用ツールである。

利用者は本人1人のみで、チームによる並行開発やAPIの外部再利用（モバイルアプリ連携等）は想定していない。一方で、以下の理由から画面は必須となる:

- 楽天証券にはAPIが提供されておらず、CSVファイルのアップロードが唯一のデータ連携手段
- 「銘柄一覧 → 銘柄詳細」の画面遷移の中で、テクニカル指標・ファンダメンタルズ指標・利確シグナル・自由記述メモを確認しながら判断する体験を重視したい
- 銘柄ごとのメモ欄（LLMとの壁打ち内容を手動転記する想定）の保存や、シグナル一覧の絞り込み表示を、画面遷移を挟まずに行いたい

`meta/adr/ADR-0005-frontend-stack.md` の選定フレームワークに基づき、Gate 0 Step 1a としてフロントエンド技術を選定する。

## Decision

**Livewire** を採用する。

## Rationale

- 個人利用の小規模ツールであり、JS専任フロントエンドを構築・維持するコストを避けたい
- 銘柄一覧の絞り込みやメモ欄の保存など、部分的な画面更新が中心であり、Livewireのサーバー駆動リアクティブUIで十分に実現できる
- Laravel標準のバリデーション・認可の仕組みをそのまま活用でき、API層を別途設計する必要がない

### 採用しなかった代替案

- **Blade**: シンプルだが、メモ欄の保存やシグナル絞り込みのたびにフルリロードが発生し、「銘柄中心で判断に集中する」体験を損なう
- **Vue 3 + Inertia.js + Pinia**（デフォルト推奨）: SPA的なUXやチームでのフロントエンド専任開発が必要な場面向け。個人利用ツールにはオーバースペックであり、JS資産の学習・保守コストに見合わない
- **React + Inertia.js**: Vue案と同様の理由で不採用。加えてチームにReact経験者がいるわけでもなく、採用理由がない
- **Vue/React SPA + Laravel API**: モバイルアプリ・外部パートナー連携等でAPIを独立させる必要がある場合向け。本プロジェクトでは不要な運用負荷（CORS・APIバージョニング等）が増えるだけ

## Consequences

### メリット
- JS専任リソースなしで、部分更新を伴うリアクティブなUIを実装できる
- Laravelの認証・認可・バリデーションをそのまま活用でき、学習コストが低い

### デメリット・リスク
- Livewireコンポーネントの`wire:model`の使い方次第でサーバーへのリクエスト頻度が増え、DB負荷につながる可能性がある（`.claude/rules/15-frontend.md`でスコープを絞る方針を明記）
- 将来的にチーム開発やAPI再利用の必要が生じた場合は、再度フロントエンド技術選定をやり直す必要がある
