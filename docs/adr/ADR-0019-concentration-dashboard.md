# ADR-0019: 集中度ダッシュボード（相関・PC1寄与率・実効ベット数・対SOXベータ・上位5銘柄ウェイト）

## Status
Accepted（2026-09-30、Gate 1〜3 本人承認。D3の実効ベット数の算出式・D4の除外基準・D6の判定/目安値を出さない方針を含め提案どおり確定）

## Date
2026-09-30

## Context

`requirements.md` 1章は「保有銘柄がAI・フィジカルAI・半導体関連に偏っている」ことを課題に挙げている。既存の偏り検出は UC-005（セクター配分）だけで、これは業種ラベルの比率しか見ていない。業種が違っても同じ要因（半導体サイクル）で一緒に動く銘柄は、UC-005 では分散しているように見える。さらにセクター分類は JP 保有146銘柄中7銘柄しか埋まっていなかった（候補M・CHG-0023 で取得処理は修正済みだが、埋まり具合の回復は未確認）。

外部調査ベースの改善提言（`docs/original-docs/stock-auto-order-recommendations-detail.md` 提言5、299〜319行）は、価格データだけで算出できる集中度指標を並べて見せることを勧めている。

> 見えないリスクは取り続けてしまう。可視化そのものが規律として働く。UC-005（セクター偏り検出）の自然な拡張。

提言5が挙げる表示項目は、相関行列（直近N週の週次リターン）・PCA第1主成分の寄与率・実効ベット数（ENB）・対SOXベータ・上位5銘柄の合計ウェイトの5つ。ただし**N週の値、ENBの算出式、閾値、SOXのデータ取得元はどの資料にも書かれていない**。本ADRはそれらを決める。

CHG-0020（ADR-0017）で `weekly_prices`（銘柄の週足終値、分割遡及調整済み・配当未調整）と `index_weekly_prices`（nikkei225 / sp500）が保存されるようになったため、新しい価格取得なしに着手できる（SOX を除く）。

## Decision

### D1 計算窓は52週、全銘柄共通の週にそろえる

- 週次リターン `r_t = close_t / close_{t-1} − 1` を、直近53個の `week_date`（52リターン）で計算する（2026-09-30 本人確認）
- 窓の終点は、最新スナップショットの対象銘柄が持つ `weekly_prices.week_date` の最大値とし、そこから52週さかのぼった53個の月曜を窓とする
- **窓内の53週がすべてそろった銘柄だけを計算対象にする**（全銘柄共通の週で計算する）。銘柄ペアごとに共通する週だけで相関を取る方式は採らない。ペアごとに期間が違うと相関行列が半正定値にならず、固有値が負になって ENB の対数計算が壊れるため

### D2 SOX 指数を追加する（Yahoo `^SOX`）

- `MarketIndexClient::SYMBOL_MAP` に `'sox' => '^SOX'` を追加し、`index_weekly_prices.index_name` の enum に `'sox'` を追加する（2026-09-30 本人確認）
- 取得・保存は `FetchExternalMarketDataAction`（CSV取込）だけで行う。保有銘柄の週足はCSV取込でしか更新されないため、ウォッチリスト一括更新（`RefreshWatchlistMarketDataAction`）には配線しない
- **SOX の取得失敗で取込の分析処理を止めない**。nikkei225 / sp500 と違い、SOX は本機能のためだけに足す取得なので、例外を捕まえて警告ログだけ出す（`safeFetchIndex()` と同じ形）。取得できなかった週は、画面のSOXベータを「取得不可（—）」と表示する
- SOX はUSD建ての価格指数（配当を含まない）。`weekly_prices` の銘柄終値も配当未調整なので、価格同士の比較として一貫する（ADR-0017 D5 と同じ前提）
- 出来高の扱い（2026-09-30 実レスポンスで確認）: `^SOX` の出来高は null ではなく**全行 0**（106行中106行）。`YahooFinanceChartClient` が捨てるのは出来高 null の行なので、行は消えない（104週取得）。末尾の仮置き行の除去は「出来高0**かつ**終値が前週と同じ」ときだけ働くため、SOX の最新週（終値が前週と異なる）は誤って捨てられない。クライアントの変更は不要。SOX の出来高は使わない

### D3 指標の定義

対象銘柄数を N、窓のリターン数を T（=52）、対象銘柄の週次リターン行列を R（T×N、列ごとに平均を引いたもの）、対象銘柄内で正規化した評価額ウェイトを w（Σw=1）とする。

| 指標 | 定義 |
|---|---|
| 相関行列 | 対象銘柄のうち評価額上位20銘柄のピアソン相関（表示用。計算対象全体の相関は下の2指標の中で使う） |
| PC1寄与率 | 各列を標準偏差で割った Z（相関の基になる行列）について、相関行列の最大固有値 ÷ 固有値の合計（=N）。「保有全体の値動きのうち、単一の共通要因で説明できる割合」 |
| 実効ベット数（ENB） | Meucci（2009）の分散化尺度。共分散行列 Σ = RᵀR/(T−1) を固有分解し（固有値 λ_i、固有ベクトル e_i）、主成分ごとの分散寄与 v_i = λ_i (e_iᵀw)² を求め、p_i = v_i / Σv_i として `ENB = exp(−Σ p_i ln p_i)`（p_i=0 の項は除く）。「独立した賭けが実質いくつあるか」。全銘柄が完全に連動していれば1、N 個が独立で均等なら N に近づく |
| 対SOXベータ | 銘柄 j ごとに `cov(r_j, r_sox) / var(r_sox)`（同じ52週）。ポートフォリオのベータは Σ w_j β_j |
| 上位5銘柄ウェイト | 最新スナップショットの**全保有（ETF・投資信託を含む）**の評価額合計に対する、評価額上位5銘柄の合計の比率 |

- **ENB は相関行列ではなく共分散行列で計算する**。ウェイトは標準化前のリターンに掛かるため、相関行列の固有ベクトルとウェイトを組み合わせると式が整合しない。PC1寄与率は慣例どおり相関行列で計算する（変動の大きい銘柄に引っ張られないようにするため）
- **固有分解は双対形（T×T のグラム行列）で行う**。N > T なので Σ（N×N）はランクが T−1 以下に落ちる。グラム行列 G = RRᵀ/(T−1)（52×52）の固有値は Σ の0でない固有値と一致し、G の固有ベクトル u_i から `e_i = Rᵀu_i / √((T−1)λ_i)` で Σ の固有ベクトルに戻せる。200×200 の対称行列をPHPのJacobi法で毎回解くと数秒かかるが、52×52 なら軽い。PC1寄与率も Z のグラム行列で同様に求める
- 固有値分解は対称行列用のJacobi法を自前実装する（数学ライブラリは導入しない）

### D4 計算対象・除外・カバー率

- 計算対象は、最新スナップショットの保有のうち `instrument_type` が `stock` で、窓内53週の終値がすべてそろっている銘柄
- 除外した銘柄は理由付きで一覧表示する。想定される理由は次の2つ（ADR-0009 D5 の「取得不可（—）」と同じく、表示は止めない）
  - 株式以外（ETF・投資信託。週足を保存していない）
  - 窓内の週足が欠けている（上場から52週未満、または直近の取得に失敗）
- ENB・ポートフォリオベータのウェイト w は計算対象の中で正規化し直す。**計算対象の評価額が全保有の評価額に占める割合（カバー率）を画面に出す**。上位5銘柄ウェイトだけは全保有を母集団とする
- 計算対象が2銘柄未満なら、相関・PC1・ENB は「算出不可」とし、上位5銘柄ウェイトだけ表示する

### D5 リターンは現地通貨建て

- 各銘柄のリターンは `weekly_prices.close` の通貨（JP株は円、US株はUSD）で計算する。円建ての為替要因は含まない
- USDJPY は `market_indicator_snapshots` にスナップショットごとの1点しかなく、週次の系列が無い。為替を含めた円建てリターンは、USDJPY の週次系列を保存する別の変更が必要になるため今回は行わず、画面に注記する
- ウェイト（評価額）は取込時に円換算済みの値を使うので、通貨の問題は無い

### D6 表示

- 新ルート `/concentration-dashboard` とし、セクター配分画面（`/sector-dashboard`）の上部からリンクする。グローバルナビのタブは増やさない（`docs/product/ui-guidelines.md` のタブ数6を維持。UC-014 と同じ扱い。2026-09-30 本人確認）
- 画面上部に5指標の値と、窓の期間（開始週〜終了週）・計算対象の銘柄数・カバー率を出す
- 相関行列は**評価額上位20銘柄のみ**表示し、表示しなかった銘柄数を添える（2026-09-30 本人確認）。保有が85〜219銘柄あり、全銘柄の行列は画面で読めないため
- 銘柄ごとの対SOXベータ一覧（評価額順）と、除外銘柄の一覧（理由付き）を出す
- 注記: 現地通貨建てであること（D5）、銘柄数が週数を上回るため相関・PC1・ENB の推定誤差が大きいこと
- **健全・警告の判定やバッジは付けない**。提言5に評価基準が無いため。提言§2.3 の目安（平均相関0.6〜0.7、PC1寄与率60〜75%、ENB 2〜5）も判定基準ではないので画面には出さない。値の解釈は本人が行う

### D7 合成スコア・ランキングにしない

5指標は横に並べて見せるだけで、1つのスコアにまとめない。銘柄ごとの「集中度への寄与」のランキングも作らない。`accuracy-improvement-backlog.md` の「採用する『やらないこと』」（保有銘柄全体の総合スコア・ランキングは、実効ベット数2〜5に対して統計的意味を持たない）に従う。

## Rationale

- **52週にした理由**: 保有期間の目安（3か月〜1年）に合い、直近の連動の変化を反映しつつ、52本のリターンで推定できる。104週は安定するが、半導体サイクルのような局面の変化が薄まる。26週は標本が少なすぎる
- **全銘柄共通の窓にした理由**: 行列が必ず半正定値になり、PC1・ENB が数学的に壊れない。代わりに窓内に欠けのある銘柄は丸ごと外れるが、`weekly_prices` は104週さかのぼって保存されるため、外れるのは上場直後の銘柄と取得失敗くらいで、影響は小さい見込み（Gate4 Cycle2 で実測する）
- **Meucci の ENB を選んだ理由**: 提言§2.3 が ENB の根拠として Meucci を挙げている。相関構造と実際のウェイトの両方を反映するため「10銘柄持っているつもりが実質3本」という提言の趣旨に合う。ウェイトだけで決まる `1/Σw²`（ハーフィンダール型）は相関を無視するため、半導体に偏っているかどうかを表せない
- **SOX を ^SOX で取る理由**: 既存の `MarketIndexClient`（Yahoo v8 chart API）にティッカーを1つ足すだけで済む。ETF（SOXX 等）の方が出来高は確実に付くが、指数そのものを使う方が提言の意図（半導体サイクルへの感応度）に近い
- **判定を付けない理由**: 基準の無いところに閾値を置くと、叩き台の数字が独り歩きする（ADR-0017 D7 が「データを見てから基準を決めない」と事前固定したのと逆の問題）。基準が必要になったら、蓄積した値を見てから別の変更で決める
- **採らなかった案**: 全銘柄の相関行列の表示（読めない）、ペアごとの共通週での相関（行列が壊れる）、相関行列の固有ベクトルでの ENB（式が整合しない）、N×N での直接の固有分解（遅い）、円建てリターン（USDJPY の週次系列が無い）、グローバルナビへのタブ追加（タブ数の上限）、ウォッチリスト側への SOX 配線（不要な外部コール）

## Consequences

- DB 変更は `index_weekly_prices.index_name` の enum に `'sox'` を追加するマイグレーション1本だけ。既存の値はそのままで後方互換。`20-mysql.md` の「カラム型変更」に当たるが、対象は約200行の小さな表で、enum の末尾への値の追加は MySQL 8 ではメタデータだけの変更で済む。Laravel 13 のネイティブな `->change()` で書き、生SQLは使わない
- CSV取込で外部APIの呼び出しが1回（`^SOX` の週足）増える。失敗しても取込は止まらない
- 新しい純ロジック（`app/Services/Concentration/`）とJacobi法の自前実装が増える。期待値は手計算できる小さな行列でテストを固定し、双対形の結果が N×N の直接計算と一致することを回帰テストで確かめる
- 銘柄数が週数を上回るため、相関・PC1・ENB の推定誤差は大きい。値は目安として見る前提で、画面に注記する
- 候補N（エクスポージャー管理、SOX のトレンドで半導体比率の上下限を調整）は、本ADRで保存が始まる SOX の週次系列を使える
