# ADR-0022: 無料の一次情報を軸にしたメガトレンド候補の発見経路

## Status
Accepted（CHG-0031の進行方針として2026-10-03に本人確認。同日、Gate 1と4週試行の順序を分離する方針に改訂。Gate 1は同日本人承認・2026-10-04に正式反映。共通処理UC-016とUC-012受け渡し差分は2026-10-04にGate 2本人承認済み。Gate 3／4は未承認。4週後の品質再精査をPLANに残し、今回のモックは本人指示により省略）

## Date
2026-10-03

## Context

UC-012は楽天証券お気に入りCSV由来の未保有銘柄を分析する。変更前の`requirements.md`では市場からの発見がOUTに含まれていた。本変更ではF-016の調査候補発見をINに加え、トレンド予測・有望性の自動選定はOUTに残した。一方、本人は半導体・AI基盤、電力、フィジカルAI、医療AIなどのメガトレンドに関係する上場企業を幅広く見つけ、専門家の解説やSNSで得た仮説を裏付けたい。

無料データにも用途の境界がある。J-Quants Freeの株価は12週間遅延し、今週の日本株ランキングには使えない。Alpha Vantageの米国株ランキングは各区分上位20件の入口であり、無料枠は1日25リクエストである。動画・ニュースレター・SNSは探索に有用だが、同じ発表の転載を独立した証拠として数えると確信度を誤る。日本のTDnet公開画面は無料閲覧できる一方、自動収集を控えるよう明示している。

## Decision

1. **現行UC-012と分離した変更案件として進める。** 未登録の上場企業を調査候補として発見する目的と、元資料・銘柄同定・本人確認の境界を[Gate 1草案](../product/megatrend-discovery-gate1-requirements-draft.md)で先に示す。Gate 1の人間承認後、情報源に依存しない候補管理と人手確認のUCをGate 2で検討できる。登録済み候補の週次ダイジェストは副次的に試す。Gate 2以降の必要な承認を得てから実装する。
2. **情報源に役割を付ける。** 専門家・動画・ニュースレター・SNSは仮説の発見、業界団体・公的統計は需要や供給制約の観測、規制・調達・企業開示は製品・事業者・業績の確認に用いる。フォロワー数や話題量を根拠の強さに変換しない。
3. **候補を証拠の鎖で管理する。** `テーマの変化 → 必要な工程・製品 → 提供企業 → 上場主体・銘柄コード → 採用/受注/売上等の証拠 → 反証`を1件の調査カードに記録する。証拠は元の発表単位で重複を除く。会社名が似ている、子会社と親会社が混ざる、非上場であるなどの未解決点があれば銘柄コードを確定しない。
4. **無料で合法的に扱える経路のみ試す。** 公式API・RSS・ダウンロードが明示された資料は利用条件を確認して取得する。閲覧のみの情報源は手動でURLと自分の要約を残す。動画の字幕、有料メルマガ本文、X/LinkedIn投稿、TDnet公開画面を非公式手段で一括取得しない。
5. **研究候補と売買候補を分ける。** 情報源から挙がった企業を自動で`holdings`、`watchlist_items`、売買シグナルへ書き込まない。本人が企業・銘柄コードと一次証拠を確認した候補だけを、UC-016からUC-012へ直接渡す（2026-10-04 Gate 2承認）。保存設計は[ADR-0025](ADR-0025-research-candidate-storage.md)と[データモデル](../architecture/data-model.md)のGate 3草案に記す。
6. **ソースの採否は試行結果で決める。** [情報源選定案](../product/megatrend-source-selection.md)を候補台帳とし、初回は3テーマ・5源に絞る。公開頻度の低い源を4週の新着だけで評価せず、過去12か月の固定サンプルと4週間の前向き確認を組み合わせる。テーマ別の固有企業発見数、一次証拠到達率、上場主体同定の誤り、既存ウォッチリストとの重複、調査時間、反証発見を記録する。[試行ログ](../investment-research/megatrend/source-pilot-log.md)の「3社・2テーマ・2元発行主体」は情報源の実用性と定期取得対象を判断する基準であり、Gate 1の要件審議の前提条件にはしない。情報源固有の自動取得フローをGate 2で確定するには、試行結果と利用条件の確認が必要。試行を経ない機械的な確信度スコアは作らない。

## Rationale

信頼性が高い統計だけでは個別銘柄を拾いにくく、専門家だけでは発言の独立性や利益相反を検証しにくい。先に専門家で変化を見つけ、一次資料で企業と収益の接点を確認する組み合わせが、無料条件のもとで網羅性と誤認防止を両立しやすい。

発見機能の目的や「本人が確認するまで売買系へ渡さない」という境界は、4週間の更新頻度を待たなくても確認できる。一方、どの源を定期取得するかは新着率と調査負荷の実測が必要。両者を分ければGate 1の要件審議を先に進めつつ、未検証の取得源を実装対象として確約せずに済む。

### 採用しなかった代替案

- **J-Quants Freeだけで日本株の今週の出来高・売買代金ランキングを作る**: 12週間遅延のため目的の時点に合わない。
- **Alpha Vantageのランキングから米国株の母集団を作る**: 上位20件ずつの短い入口であり、医療AIなどのテーマ網羅や全銘柄の詳細分析には足りない。
- **SNSの拡散数や専門家の推奨銘柄をスコア化する**: 同じ情報の再投稿、発信者の利害、人気の偏りが銘柄評価に混入する。
- **最初から全情報源を常時自動収集する**: 取得条件の異なる媒体が混在し、調査価値が未測定の段階で保守対象が広がる。
- **既存候補のダイジェストだけを先に要件化する**: 未登録企業の発見という本人の目的を達成できず、試行結果より先に実装範囲を固定してしまう。
- **4週間の試行完了までGate 1の審議を止める**: 情報源の採否には有用な期間だが、発見機能の目的・証拠・本人確認の境界まで保留する理由にはならない。

## Consequences

### メリット

- 市場の変化から未登録企業を探索しつつ、UC-012の既存判定や購入判断への誤接続を避けられる。
- 情報源ごとの成果と費用を測り、無料枠の範囲で継続対象を絞れる。
- 日本株・米国株に共通する「上場主体の確認」と「収益への距離」を明示できる。

### デメリット・リスク

- 手動試行では見落としが残る。自動化しても公的リストの非網羅性や公開遅延は残る。
- Gate 1を先行しても、定期取得する源・頻度・利用条件は未確定。Gate 2で源固有の取得フローを確定する際に試行結果を反映する。
- 企業発表は当事者の主張であり、採用・規制承認・売上の各段階を別資料で確認する必要がある。
- 共通処理のGate 1／2は承認済み。実装へ進むには保存設計のGate 3とTDDのGate 4を通す。源固有の自動取得は試行後にUC差分を再レビューする。
