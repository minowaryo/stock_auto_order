# ADR-0022: 無料の一次情報を軸にしたメガトレンド候補の発見経路

## Status
Proposed（CHG-0031。Gate 1以降の承認は未取得）

## Date
2026-10-01

## Context

UC-012は楽天証券お気に入りCSV由来の未保有銘柄を分析する。市場全体から注目テーマや未登録銘柄を見つける機能は、現行`requirements.md`のOUTに明記されている。一方、本人は半導体・AI基盤、電力、フィジカルAI、医療AIなどのメガトレンドに関係する上場企業を幅広く見つけ、専門家の解説やSNSで得た仮説を裏付けたい。

無料データにも用途の境界がある。J-Quants Freeの株価は12週間遅延し、今週の日本株ランキングには使えない。Alpha Vantageの米国株ランキングは各区分上位20件の入口であり、無料枠は1日25リクエストである。動画・ニュースレター・SNSは探索に有用だが、同じ発表の転載を独立した証拠として数えると確信度を誤る。日本のTDnet公開画面は無料閲覧できる一方、自動収集を控えるよう明示している。

## Decision

1. **現行UC-012と分離した変更案件として進める。** 第1段階は登録済み候補に対する週次の調査ダイジェストを手動で試行する。第2段階の市場全体からの発見は、情報源の成果と取得条件を確認してから要件・UCを起こす。いずれも本ADRのProposed段階ではアプリ機能に含めない。
2. **情報源に役割を付ける。** 専門家・動画・ニュースレター・SNSは仮説の発見、業界団体・公的統計は需要や供給制約の観測、規制・調達・企業開示は製品・事業者・業績の確認に用いる。フォロワー数や話題量を根拠の強さに変換しない。
3. **候補を証拠の鎖で管理する。** `テーマの変化 → 必要な工程・製品 → 提供企業 → 上場主体・銘柄コード → 採用/受注/売上等の証拠 → 反証`を1件の調査カードに記録する。証拠は元の発表単位で重複を除く。会社名が似ている、子会社と親会社が混ざる、非上場であるなどの未解決点があれば銘柄コードを確定しない。
4. **無料で合法的に扱える経路のみ試す。** 公式API・RSS・ダウンロードが明示された資料は利用条件を確認して取得する。閲覧のみの情報源は手動でURLと自分の要約を残す。動画の字幕、有料メルマガ本文、X/LinkedIn投稿、TDnet公開画面を非公式手段で一括取得しない。
5. **研究候補と売買候補を分ける。** 情報源から挙がった企業を自動で`holdings`、`watchlist_items`、売買シグナルへ書き込まない。本人が企業・銘柄コードと一次証拠を確認した候補だけを、既存のお気に入りCSV等を通じてUC-012へ渡す。直接登録が必要なら別途UC・データモデルを設計する。
6. **ソースの採否を試行結果で決める。** [情報源選定案](../product/megatrend-source-selection.md)の初期セットで4週間の手動試行を行い、テーマ別の固有企業発見数、一次証拠到達率、上場主体同定の誤り、既存ウォッチリストとの重複、調査時間、反証発見を記録する。試行を経ない機械的な確信度スコアは作らない。

## Rationale

信頼性が高い統計だけでは個別銘柄を拾いにくく、専門家だけでは発言の独立性や利益相反を検証しにくい。先に専門家で変化を見つけ、一次資料で企業と収益の接点を確認する組み合わせが、無料条件のもとで網羅性と誤認防止を両立しやすい。

### 採用しなかった代替案

- **J-Quants Freeだけで日本株の今週の出来高・売買代金ランキングを作る**: 12週間遅延のため目的の時点に合わない。
- **Alpha Vantageのランキングから米国株の母集団を作る**: 上位20件ずつの短い入口であり、医療AIなどのテーマ網羅や全銘柄の詳細分析には足りない。
- **SNSの拡散数や専門家の推奨銘柄をスコア化する**: 同じ情報の再投稿、発信者の利害、人気の偏りが銘柄評価に混入する。
- **最初から全情報源を常時自動収集する**: 取得条件の異なる媒体が混在し、調査価値が未測定の段階で保守対象が広がる。

## Consequences

### メリット

- 市場の変化から未登録企業を探索しつつ、UC-012の既存判定や購入判断への誤接続を避けられる。
- 情報源ごとの成果と費用を測り、無料枠の範囲で継続対象を絞れる。
- 日本株・米国株に共通する「上場主体の確認」と「収益への距離」を明示できる。

### デメリット・リスク

- 手動試行では見落としが残る。自動化しても公的リストの非網羅性や公開遅延は残る。
- 企業発表は当事者の主張であり、採用・規制承認・売上の各段階を別資料で確認する必要がある。
- 実装へ進む場合はOUTの改訂を含むGate 1、UCのGate 2、必要に応じてデータモデルのGate 3、TDDのGate 4を別途通す。
