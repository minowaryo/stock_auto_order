# ADR-0024: 売却後とシグナル発生後の週足追跡をF-017に統合する

## Status

Proposed（2026-10-04）。本人指示によりCHG-0033 / F-017の要件へ追跡対象の追加と既存週足保存の共用を反映。Gate 2〜4は未承認で、実装は未着手。本ADRは追跡の詳細設計案とADR-0017 D2の改訂方針を記録する。

## Date

2026-10-04

## Context

UC-014（CHG-0020、2026-10-03 mainマージ `a10e706`）は、`signal_occurrences` の発生後+4／+13／+26週の対市場超過リターンを `weekly_prices` / `index_weekly_prices` から読み取り時に計算する。週足取得は現在の保有銘柄と未保有のウォッチリスト銘柄が対象のため、売却等で双方から外れた銘柄は記録が止まる。期間が確定しても終点価格がなければ「算出不可」となり、シグナルに従って売った例が系統的に評価から抜ける。

F-017は売却後の保有継続比較のため+26週までの価格追跡を既に要件に含む。本人の指示により、この追跡をUC-014の生存バイアス対策にも共用する。PLAN.mdのCHG-0020別CR候補(a)をCHG-0033へ取り込み、(b)年ごとの符号チェックと(c)少数結果の「異常を疑う」判定は含めない。

## Decision

### D1 対象と期限を銘柄単位に統合する

- 売却履歴を根拠に追跡する銘柄に、**`signal_occurrences`に直近26週以内の発生記録がある銘柄**を加える。保有・ウォッチリストへの所属、裁量／定型の分類、売買理由の入力有無で価格取得を止めない。シグナルのみの対象に取引履歴CSVの提出を要求しない。
- シグナルは `take_profit` / `buy` / `watchlist_buy` の全種別を対象とする。期限の起点は `created_at` ではなく `observed_week`。銘柄識別は既存の `holding_id`（市場・銘柄との対応）を使い、口座別の約定や同一銘柄の複数発生を重複取得しない。
- 追跡期限は `max(最後の売却から+26週, 最後のシグナル発生から+26週)`。片方しかなければその期限を採用し、新たな売却・発生で延長する。売却日の評価週への対応はF-017のGate 3で確定する。UC-014の週定義は既存の `WeekDateNormalizer` と `observed_week` を維持する。
- **終了は終点週の確定後の取得・保存まで含む**。暦上26週が経っただけで除外しない。26週目の途中の取得では終値が確定していないため、直近26週の抽出条件から外れる翌週も完了待ち対象を保持する。取得・保存失敗は完了扱いにせず再試行する。上場廃止等の取得不能は理由を残し、正常完了や0円に置き換えない。完了待ちの保持方式、再試行上限・間隔、取得不能時の停止・再開方法はGate 3で確定する。

### D2 既存の保存処理を共用し、価格だけを追加取得する

- 週1回、既存の株価クライアントで104週系列を取得し、`WeeklyPriceRecorder::recordHolding` で `weekly_prices` にUPSERTする。新しい価格テーブルやUC-014専用の追跡系統は作らない。
- 保有・ウォッチリスト経路ですでに必要な確定週を取得・保存できていれば再利用する。単に当週の実行済み印があるだけでは終点の確定後取得が済んだとみなさない。追跡対象を `holding_id` でまとめ、同じ週次実行での二重取得を避ける。
- 追跡だけの銘柄にファンダメンタル取得・シグナル判定を実行しない。追跡自身が `signal_occurrences` を追加して期限を延ばし続けることを防ぐ。
- UC-014は発生記録の `holding_id` に対応する保存済み週足を読むため、**コード変更不要の見込み**。起点・終点の株価と指数が揃えば、次回閲覧で既存処理が再計算する。確定済み期間の欠損は現行どおり「算出不可」。画面・判定ロジック・閾値は変更しない。
- UC-014の確定境界には指数の最新週も必要。既存の `recordIndex` / `index_weekly_prices` の週次更新と実行順を整合させる。売買履歴CSVが未提出の週にも追跡が動く起動方法・重複排除・指数更新との配線はGate 3で決める。
- `recordHolding` は保存例外をログに残して処理を継続する実装のため、メソッドが戻っただけでは成功とみなさない。終点の保存確認と、必要な確定後取得の完了確認を終了条件に含める。

### D3 ADR-0017 D2の部分改訂と担当

ADR-0017 D2の「新規の外部APIコールは発生しない」は、CHG-0020当初の保有・ウォッチリスト対象に限る前提へ改訂する。F-017では対象外に残った売却済み・シグナル対象銘柄の追加コールを認める。`weekly_prices` / `index_weekly_prices` の保存形式と104週UPSERTは維持し、ADR-0017全体はsupersedeしない。

**本文の追記担当はF-017（CHG-0033）側とする。2026-10-04にADR-0017 D2へ改訂方針と本ADRへの参照を追記した。CHG-0020側での重複編集は不要。** 詳細設計の承認・実装が済んだことを意味しない。

### D4 追加取得量の見積もり

1回の株価リクエストで1銘柄の104週系列を取得する前提で、通常週の追加量を次のように見積もる。

- `S`: 売却を理由に期限内の銘柄集合
- `G`: 直近26週のシグナル発生を理由に期限内の銘柄集合
- `P`: 終点の確定後取得・保存が未完了で保持している銘柄集合
- `R`: 既存の保有・ウォッチリスト更新で必要週の取得・保存が済んだ銘柄集合
- **追加株価リクエスト数／週 = `N = |(S ∪ G ∪ P) − R|` × 週1回**。再試行の追加分は別計上。売却とシグナルの重なりも1銘柄と数える。

| 既存取得との重複を除いた追加銘柄数 N | 通常週の追加リクエスト数 | 104週すべて返った場合のUPSERT対象行数／週 |
|---|---:|---:|
| 20 | 20 | 2,080 |
| 50 | 50 | 5,200 |
| 100 | 100 | 10,400 |

例えば売却対象40銘柄、シグナル対象30銘柄、両者の重複10銘柄、既存経路で取得済み20銘柄、完了待ち0銘柄なら、追加は **40リクエスト／週、最大4,160行のUPSERT／週**。これは仮定例で、現在DBの実測値ではない。UPSERT対象行数は新規に増える行数とは異なる。

株価とは別に、既存経路で指数を更新できない週に共通追跡が指数も取得する配線なら、日経225・S&P500の最大2リクエスト／週を加える（既存更新を共用できれば追加0）。再試行・ティッカー再解決等は上記の定常見積もりに含めない。Gate 3で実対象数、API制約と実行時間、指数更新の配線を確認し、実装時には追加対象数・成功／失敗・再試行の件数を確認できるようにする。

### D5 初回の一括補完（2026-10-04 本人選択による追加）

F-017の株式部分の年率（時間加重リターン）、売却・買付・推定乗換えの比較、過去の売買の価格系指標の事後再計算には、売買履歴の開始（国内2022-07、米国2024-08）より前の52週を含む週足が要る。既存の104週（`range=2y`）では足りないため、次を**初回に1回だけ**行う。

- 対象: 売買履歴に現れた全銘柄（2026-10-03時点で国内95・米国48の約143銘柄）、日経225、S&P500、ドル円の週足。合計約146リクエスト。
- 期間: 2021-07以降（Yahoo Finance chartの `range=5y` 相当）。既存の `YahooFinanceChartClient` に取得期間の指定を足し、保存は `weekly_prices` / `index_weekly_prices` へのUPSERTを共用する。ドル円の週足の保存先はGate 3で決める（既存の `fx_rate_used` はスナップショット時点の値だけで週次系列はない）。→ [ADR-0027](ADR-0027-trade-history-storage.md) D5 で `index_weekly_prices` の `usdjpy` とする案（Gate 3承認待ち）。追跡状態は同 D7 の `price_tracking_targets`。
- 以後の週次は D2・D4 の104週UPSERTのまま。新しい売買履歴で未知の銘柄が現れたときだけ、その銘柄を同じ方法で補完する。
- 上場廃止等で取得できない銘柄は「取得不能」と記録し、F-017側で評価額比率に応じて判定保留にする。
- Yahooの終値は分割調整済みのため、売買履歴の株数も分割調整後に揃えて使う。

## Rationale

売買判断とシグナル検証は同じ銘柄・週の価格を必要とする。対象集合と期限を共通化し、既存の保存処理・読取処理を使えば、二重取得を避けつつ売却後の観測欠落を減らせる。

### 採用しなかった代替案

- **UC-014専用の追跡機構**: F-017と対象・価格が重なり、期限管理と外部取得が二重になる。
- **本人が売却銘柄をウォッチリストに残す運用**: 登録忘れに依存し、観測欠落の偏りが残る。
- **保有・ウォッチリストのみを取得し、算出不可を除外する現状維持**: 売った例が系統的に抜ける問題を解消できない。
- **全銘柄を無期限に取得**: +26週評価に必要な範囲を超えた外部取得が増える。

## Consequences

### メリット

- F-017とUC-014が共通の週足を使い、非保有になった銘柄も評価終点まで観測できる。
- UC-014の計算・画面を変更せずデータ供給を補える見込みで、欠損の回復は既存の読み取り時算出に反映される。

### デメリット・リスク

- 対象銘柄数に比例して外部取得が増える。重複排除、確定後取得、保存失敗を検出する終了管理が必要。
- 上場廃止・ティッカー変更・API欠損は継続取得だけで必ず解消できない。理由付きの算出不可を残し、生存バイアスを完全に解消したと断定しない。
- 104週取得は全期間CSVの古い約定時点の価格復元を保証しない。今回の継続追跡とは別に、古い比較期間の取得可否を確認する。
- 本変更は文書上の要件・設計案。追跡実装が稼働するまで現行の欠落は残る。

### Gate 4で確認するテスト候補

UC-018／UC-014: 売却のみ・シグナルのみの非保有銘柄、期限の前後両ケース、対象の重複、終点確定前後、取得／保存失敗、新しい発生による期限延長、追跡自体が発生を作らないこと、価格補完後の既存UC-014による再集計。[UC草案](../product/trade-decision-effect-gate2-uc-draft.md)で具体化する。テストケース承認・実装は本変更に含めない。
