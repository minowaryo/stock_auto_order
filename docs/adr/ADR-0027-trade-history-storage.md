# ADR-0027: 売買履歴の保存設計と、比較結果を読み取り時に算出する方針

## Status

Accepted（2026-10-04、本人がGate 3承認）。UC-017・UC-018はGate 2承認済み、UC-019はGate 2保留。マイグレーションはGate 4（テストケース承認）後に作る。

## Date

2026-10-04

## Context

F-017（売買判断の対ガチホ効果検証）では、楽天証券の国内株・米国株の全期間売買履歴CSVを毎週取り込み、次を手入力なしで出す（UC-018、Gate 2承認済み）。

- 株式部分の直近52週の時間加重リターン（修正ディーツ法・配当除く）と、年率20％／25％の判定、対ガチホ差
- 売却単独、推定乗換え（同一市場・5営業日以内・参考）、買付と比例買増しの+4／+13／+26週比較
- 売買前に保存済みだったシグナル・指標・保有状況の紐付け

制約は次のとおり。

- CSVには取引IDも約定時刻もない。完全に同じ内容の行が国内39行・米国32行あり、同一内容を1件にまとめると株数が崩れる。毎週「全期間」を再提出するので、再取込は冪等でなければならない。
- 週足の終値（Yahoo）は分割遡及調整済みで、分割のたびに過去の値が変わる（ADR-0017 D5）。
- `technical_indicators`／`fundamental_indicators` は現在値キャッシュで毎週上書きされる。売買時点の業績指標は、今保存を始めない限り後から復元できない。
- 米国株のドル決済の受渡金額と評価額を円で揃えるには、週次のドル円が要るが保存先がない（`holding_snapshots.fx_rate_used` は取込時点の1点だけ）。

## Decision

### D1 売買履歴は「内容のハッシュ＋出現回数」で一意にする

`trade_executions` の一意キーを `(market, content_hash, occurrence_index)` とする。`content_hash` は正規化した行内容のSHA-256（ファイル名・行番号は含めない）、`occurrence_index` は同じファイル内で同一内容が何番目に出たか。全期間履歴を再提出しても同じキーになり、行は増えない。同一内容の複数約定は別行として残る。最新の全期間履歴から消えた行は削除せず `missing_in_latest` にして確認待ちにする。

### D2 比較結果は保存せず、読み取り時に算出する

年率・対ガチホ差・売却／乗換え／買付の差は、`trade_executions`・`stock_splits`・`weekly_prices`・`index_weekly_prices` から画面表示のたびに計算する。ADR-0017 D4（シグナル結果を保存しない）と同じ方針。

UC-018本文の「比較結果と状況記録を保存」のうち、**比較結果は「根拠データを保存し、結果はそこから再現する」と読み替える**ことを本ADRで明確にする。保存するのは、元データ（売買履歴）、取得状態（`price_tracking_targets`）、判断の根拠（`trade_switch_allocations`・`trade_context_records`）だけとする。

### D3 推定乗換えの割り当ては、版付きの派生データとして保存する

`trade_switch_allocations` に `rule_version` 付きで保存する。取込確定のたびに同じ版の行を作り直し、ルールを変えるときは新しい版で追加して旧版を残す。1つの売却・1つの買付それぞれの割り当て合計は受渡金額を超えない（二重割り当ての防止）。

### D4 売買時の状況は追記のみで残し、当時記録と事後再計算を区別する

- `indicator_observations` に、既存の週次処理（保有CSV取込・ウォッチリスト一括更新）が得た指標を毎回追記する。**後から遡って作れないため、UC-018の他の実装より先に保存を始める**。
- `trade_context_records` は `origin`（`recorded`／`recomputed`）と `rule_version` を持ち、過去の状況を最新値で上書きしない。`recorded` は約定日の開始より前・8日以内の記録だけを使う。`recomputed` は売買週の前週までの週足だけで価格系7項目を計算する。

### D5 ドル円の週足は `index_weekly_prices` に `usdjpy` として保存する

ADR-0024 D5で保留していた保存先を決める。`index_name` の enum に `usdjpy` を末尾追加する。指数ではないが、既存の `recordIndex` と週の正規化（`WeekDateNormalizer`）をそのまま使え、変更は `sox` 追加（CHG-0026）と同じ後方互換なenum拡張で済む。

### D6 株式分割は専用の表で持ち、読み取り時に株数を揃える

`stock_splits` に Yahoo chart の分割イベントと、米国株CSVの分割入庫を保存する。約定時の株数・単価は、この表で分割調整してから分割調整済みの終値と掛け合わせる。両者が食い違えば「分割情報欠損」として算出不可にする。

### D7 価格追跡の状態は銘柄ごとの状態テーブルで持つ

ADR-0024 の追跡期限・終点確定後の保持・連続失敗・初回補完の済み状況を `price_tracking_targets` に1銘柄1行で持つ。`completed` は保存の確認ができたときだけ設定する（`recordHolding` は例外を握りつぶすため、戻っただけでは成功とみなさない）。

## Rationale

- **結果を保存しない**: 価格は分割の遡及調整で過去の値が変わる上書き型の時系列である。結果を保存すると、価格が直っても古い結果が残り、どちらが正しいか分からなくなる。根拠を保存し結果を再現する形なら、常に最新の価格に揃う。
- **派生データに版を持たせる**: 推定乗換えは仮定に基づく参考値で、ルールを後で見直す可能性が高い。版を残せば、見直し前後の結果を比べられ、「結果を見てルールを変えた」ことも追跡できる。
- **指標の追記保存を先行させる**: 業績指標の「当時の値」は、記録を始めた日以降の分しか得られない。UC-019の判断（実件数を見てから）を待つと、その間の記録が永久に欠ける。

### 採用しなかった代替案

- **比較結果を週次で保存する**: 表示は速くなるが、分割調整・価格補完のたびに再計算と整合確認が要る。まず読み取り時算出で始め、遅ければGate 4で週次評価額の派生キャッシュを追加する。
- **約定行の内容ハッシュだけで一意にする**: 同一内容の複数約定（国内39行・米国32行）が1件にまとまり、復元した株数が残高と合わなくなる。
- **ファイル名・行番号で一意にする**: 毎週の全期間再提出で行番号がずれ、同じ約定が重複登録される。
- **ドル円専用のテーブルを作る**: 意味は明確になるが、保存処理と週の正規化を二重に持つことになる。
- **状況記録を `signal_occurrences` だけで済ませる**: シグナルが出なかった週の指標が残らず、「シグナルなし」と「記録なし」を区別できない。

## Consequences

### メリット

- 全期間履歴の再取込が冪等になり、同一内容の複数約定も株数を崩さずに残る。
- 価格の補完・分割調整があっても、比較結果が自動で最新に揃う。UC-014と同じ考え方で保守できる。
- 業績指標の当時記録が今週から蓄積される。

### デメリット・リスク

- 表示のたびに数万行を読むため、画面が遅くなる可能性がある（Gate 4で計測し、必要なら派生キャッシュを追加する）。
- `index_weekly_prices` に指数でない系列が入る。2026-10-04時点の参照箇所は `ShowSignalOutcomesAction`（UC-014、`whereIn` で nikkei225／sp500 に限定）と `ShowConcentrationDashboardAction`（UC-015、`sox` に限定）の2つで、いずれも `usdjpy` を拾わないことを確認済み。UC-007は別テーブル（`market_indicator_snapshots`）。今後この表を全件読む処理を作る場合は指数名で絞り込む。
- `indicator_observations` は週あたり約300行（保有＋ウォッチリスト）、年約1.5万行増える。

### Gate 4で確認するテスト候補

- 同じ全期間履歴を2回取り込んでも行数が変わらない（実データでは国内39行・米国32行が同一内容の重複で、最大3回の出現）。数値の桁区切りや日付書式の違いで別行にならない。同一内容の行は出現回数で別行になる。前回あった行が消えると `missing_in_latest` になり削除されない。
- 分割の前後をまたぐ売却で、分割調整後の株数×調整済み終値が正しい評価額になる。CSVの分割入庫とYahooの分割が食い違うと算出不可。
- 推定乗換えの割り当て合計が売却・買付それぞれの受渡金額を超えない。版を変えると旧版の行が残る。
- 状況記録が約定日の開始以降の指標を使わない。8日より古い記録は使わず「状況不明」になる。
- `usdjpy` 追加後も、UC-007・UC-014・UC-015の既存の指数の表示・計算が変わらない。
