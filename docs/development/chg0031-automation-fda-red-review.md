## 新しい公開操作のテスト契約案

実装を拘束する最小の画面操作を次のとおり具体化した。既存の承認を新ケースのGate 4承認へ流用しない。

| 操作/入力 | 検証する契約 |
|---|---|
| `research:discover-candidates` | 既存の取得確認後に保存済み入力から処理。共有ロック、200件上限、カーソルと保存の一体化。設定で停止可能 |
| `showDraft(id)` | 版付き確認内容を読み、確認欄を毎回OFFにする。閲覧でHTTPしない |
| `draftReview` | サーバーで保持する確認時点（id/lock_version/document_version_id/catalog_import_ids/imported_candidate_lock_version）。LivewireのLockedでクライアントからの改変を拒否 |
| `draftConfirmed` / `importDraft()` | 本人のチェックが必須。期待版と取り込み先を再確認し、原子保存・再送時に同じ調査記録へ収束 |
| `draftNote` / `draftExistingEventId` / `draftExistingEntityId` | 本人追記と、本人が選んだ既存元発表/法人への接続。資料由来の値と分離 |
| `reconfirmDraft()` | 取り込み後の資料差分を本人が確認。資料確認版と候補版/履歴を一体更新し、初回取り込み版/本文/主張を自動更新しない。未確認の主張は未確認のまま |
| `correctDraft(id, expectedVersion, overrides)` | 本人訂正と変更履歴を保持し、取得更新で消さない |
| `changeDraftDisposition(id, expectedVersion, disposition, reason)` / `restoreDraft(id, expectedVersion)` | 理由付き保留/見送りと本人による復元。どの操作もPolicyと期待版を検証 |

照合元の欠測/古さ/失敗を画面で伝える文言は「照合元欠測」「照合元が古い」「照合元の取得失敗」と具体化。候補提示を上場確定へ変換せず、欠測時に未登録・未保有を断定しない。

## 実行と失敗原因

- 新画面26失敗: 新しい区分表示がない1件、追加アクションが存在しない25件。存在確認は未実装を認証/コンテナ例外やテスト用DDL不足と混同しないため。
