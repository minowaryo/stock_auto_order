## メインセッションへ渡す要点

本人の期待は、**Web情報を取得して企業を抽出・スクリーニングし、出典付きの候補として確認できること**。企業名・テーマとの関係・URL・要約を本人が一から入力する画面とのずれを指摘された。

このセッションでは、計画、情報源ごとの追加仕様、静的3画面モックまで作成した。**アプリの実装・DB変更・実画面への適用は行っていない。企業候補自動生成・新画面の追加Gate 2/3/4は未承認。** 取得元の追加だけで完成とせず、取得済み項目の再入力なしで候補確認から監視登録へ進めることを完了条件とした。

作成物は現在のmainにはなく、`chore/harness-sync-loop-stage1-clean`の**退避コミット`3fbc3fb`**に保存されている。NEDO側の別作業は`feat/chg0031-nedo-source`の**退避コミット`9e4bc14`**。両方を確認してから再開する。

**最新状況:** 追加Gate 2/3は2026-10-19に承認済み。FDA追加79件はGate 4承認済み、初期Green（関連301件/E2E1件成功）。実JPX差異の追加3件も別途承認→Green、関連304件/E2E1件成功。以下の初期記録は経緯として残し、最新の承認状態とGreen結果は末尾12章を参照。

## 4. 追加仕様の中心と、まだ決めること

目指す通常経路は `起動時のWeb取得 → 企業候補下書きの自動生成 → 出典付き一覧で確認 → 調査記録 → 本人確認後の監視登録 → UC-012の指標更新`。

- スクリーニングはテーマとの関係・企業の役割・日米上場の対応・登録/保有状況の整理。財務条件や押し目判定は監視登録後のUC-012を再利用する案。**この範囲/順序はユーザーの最終レビュー前**で、候補段階の財務スクリーニングまで期待されているか、レビュー時に確認する余地がある。
- FDAのCompany/Device/申請番号等から候補を作る。企業欄から上場主体・親会社・売上を自動確定しない。決定日と公開日を混同しない。
- NEDOは結果一覧だけでは企業名が足りないため、結果HTMLの「実施予定先」等を限定取得する追加案。10月16日に公式ページで、HTML本文に法人名・再委託先がある例を確認した。元URLは追加仕様に記載。
- NEDO追加案は一覧1回＋後続で結果HTML最大3件/回、直列・時間/サイズ/間隔上限、未解析の待ち行列。**既存の「1源1リクエスト・本文非取得」の境界を変えるので別の仕様/設計承認が必要。** PDF/動画の自動取得は含めていない。
- 公開noteはRSS題名から根拠付きで抽出できる範囲。企業名を特定できないものは「資料のみ」とし、企業候補数へ混ぜない。今回のRSS直URLの再確認はブラウズツールのエラーで未確認だった。
- 上場主体は公式銘柄情報・確認済み別名で照合。日本株JPX・米国株SECの公開情報を照合先候補として確認したが、具体的な取込/更新/保存の設計は残る。
- 自動説明を「自分の要約」、取得日を「本人の確認日」にしない。本人の訂正・保留・見送りを再取得で上書きしない。
- 初回の過去資料も候補表示するが、新着件数へ加算しない。資料数と企業数、成功0件と取得失敗/未解析を分ける。
- 新しい保存設計・マイグレーション・アプリ実装・テストコードは、このセッションでは作成していない。LLM/有料サービス導入も実施していない。

既存情報源台帳は[メガトレンド情報源候補](../product/megatrend-source-selection.md)。一次12系統・専門家5源・照合先7系統があり、最初の試行5源はOCP・NEDO・FDA・ものづくり太郎・中島聡。新しく調査を始め直さず、既存メモと実装を使う。
