## 作成者セルフチェック（マージ前）

作成者セルフチェックは `docs/development/review-guidelines.md` の「レビュー前確認（作成者）」に
一本化している——`prepare-merge` はマージのたびにそのリストを実行する。

---

## レビュアーチェック

### 機能・設計
- [ ] 実装がuse-casesの意図に沿っているか
- [ ] 既存の設計パターンと整合しているか
- [ ] 不要なファイルを変更していないか

### セキュリティ
- [ ] 認可チェックが適切か（Policy/Gate経由か）
- [ ] バリデーションが十分か
- [ ] secrets が含まれていないか

### パフォーマンス
- [ ] N+1クエリの疑いがないか
- [ ] 重いクエリはindexが効いているか

### テスト
- [ ] テストが実際に失敗するケースをカバーしているか
- [ ] テスト名が日本語で意図が伝わるか
- [ ] E2Eテストが「クリティカルフローのみ」の範囲に収まっているか（網羅目的の乱用がないか）

### ドキュメント
- [ ] 設計変更がdocsに反映されているか
