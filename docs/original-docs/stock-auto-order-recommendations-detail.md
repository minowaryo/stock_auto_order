## 1. 対象システムと前提

### 1.1 システム概要

楽天証券の保有銘柄CSVを取り込み、テクニカル・ファンダメンタルズ指標を算出してシグナル判定し、画面に提示する個人用の意思決定支援ツール。自動発注・バックテストは `requirements.md` 2章で明示的にスコープ外。

- 利用者1人、資産規模 約2,000万円、保有期間 3か月〜1年
- 保有内訳: JP 146 / US 72 / 投信 6（計224、ADR-0015記載の実測値）
- ポートフォリオはAI・フィジカルAI・半導体関連に集中（`BACKGROUND.md` 記載の課題）
- 目標: 積立・長期保有に対する追加収益 年率+5%程度

### 1.2 本調査の経緯

日本株スイング戦略の設計検討の過程で、8件の外部調査（学術文献・実務資料・データソース調査）を実施した。その結果が既存システムの設計前提と複数箇所で衝突したため、既存システムへの適用可能性を検証した。

## 3. 提言別の実装詳細

### 提言1: PEG判定の「山側」ガード【最優先・小規模】

#### 現状

ADR-0015 D3により、**成長率が低い（暫定閾値5%以下）銘柄**でPEG判定（`peg_overvalued` / `peg_undervalued`）を評価対象から除外し、代替として `PER ≤ 15 かつ 配当利回り ≥ 3%` を用いる。**成長率が高い銘柄側の判定（閾値2.0/1.0）は不変**（ADR-0015 D3 明記）。

対象コード（要現物確認）:
- `app/Services/Analysis/SignalDeterminationService.php` の `determinePegOvervalued()`（閾値2.0）
- `app/Services/Analysis/BuySignalDeterminationService.php` の `determinePegUndervalued()`（閾値1.0）

#### 問題

PEG = PER ÷ 成長率 は、**分母が大きいときにも歪む**。シクリカル銘柄では利益が株価に先行して動くため:

| 局面 | 利益(E) | PER | 成長率 | PEG | 判定 |
|---|---|---|---|---|---|
| サイクルの山 | 最大 | 低い | 高い（例40%） | 例 12÷40 = **0.3** | `peg_undervalued`（PEG≤1.0）が**発火** |
| サイクルの谷 | 崩壊 | 高い（例60） | マイナス | 成長率5%以下でD3により除外 → 代替条件 `PER≤15 かつ 配当≥3%` に半導体は非該当 | **何も出ない** |

結果として **天井で買い増し候補に現れ、底では沈黙する**。ポートフォリオが半導体に集中しているため、この誤りは実害に直結する。

D3が是正したのは商社・資源株など「低成長だが健全」な側であり、**山側は未対処**。

#### 変更方針（案）

D3と同型の条件追加で対応できる。以下のいずれか、または組合せ:

1. **成長率の上限ガード**: 成長率が異常に高い場合（例: 30%超）もPEG判定から除外する。D3の下限ガードと対称
2. **`peg_undervalued` にPER水準の下限ガードを併用**: PEGが低くてもPERが業種平均比で極端に低い場合は「シクリカルピークの疑い」としてフラグを立てる
3. **利益の持続性チェック**: `financial_statements` の複数期データ（JP株は平均8期保存済み、ADR-0015記載）から、直近利益が過去N期の最高水準にあるかを判定し、該当する場合は `peg_undervalued` を抑制

**推奨は1（最小変更）**。2・3は効果は高いが設計コストが上がる。

なお ADR-0015 D8 は「growth銘柄側のPEG合否基準の明文化・成長率の上限レンジ」を**スコープ外として `accuracy-improvement-backlog.md` に記録済み**。本提言はその候補に該当し、優先度引き上げを提案するもの。

#### テスト観点

- 高成長かつ低PERの銘柄で `peg_undervalued` が発火しないこと
- 従来の「適度な成長＋適度なPER」の銘柄では判定が変わらないこと（回帰）
- 閾値境界（成長率ちょうど30%など）での挙動
- US株（Finnhubの `pegTTM` 経由、負値ガードはADR-0012 D4で対応済み）でも同じ分岐が働くこと

#### 注意

- 閾値（30%）は暫定。**実装前に実データで影響銘柄数を実測すること**。ADR-0015・0016はいずれも実測後に設計変更しており、その運用を踏襲する
- `determinePegUndervalued()` と `determinePerUndervalued()` が同一PER値で重複発火する既知事象がある（`PLAN.md` 2026-09-21エントリ記載、プロダクトロジックは両方とも正当な仕様として不変と判断済み）。本変更がこの重複に影響しないか確認すること

### 提言2: セクターデータ取得の修復【前提条件・中規模】

#### 現状（ADR-0015に記録された実測値）

> JP保有146銘柄中 `sector_classification_id` が入っているのは**わずか7銘柄**。`FetchExternalMarketDataAction` は毎週 `fetchSectorInfo()` を呼んでいるが直近取込後もほぼ埋まっていない。**原因未調査・本CRのスコープ外**

#### 影響範囲

1. ADR-0015 D4（`relative_strength_vs_sector` へのフォールバック）が当面ほぼ機能しない（ADR-0015自身が明記）
2. **提言4・5（エクスポージャー管理・集中度可視化）の前提が成立しない。** セクター配分が分からなければセクター配分は管理できない
3. UC-005（セクター偏り検出）の精度そのものに影響する

#### 調査の起点（案）

- `FetchExternalMarketDataAction::fetchSectorInfo()` の呼び出し結果と保存経路
- J-Quants `/equities/master`（または `/listed/info`）のレスポンス実体と、`Sector17Code` / `Sector33Code` のマッピング
- 例外が握り潰されていないか（戦略メモ5.2の「取得失敗はエラーフィールドに格納して処理継続」という設計方針が、失敗を不可視にしていないか）
- 銘柄コードの型。**2024年1月以降 `130A` のような英字入りコードが存在する。** 整数として扱っている箇所があると一部銘柄で照合が失敗する

#### 代替案（修復が長引く場合）

半導体エクスポージャー管理に限れば、J-Quantsの業種分類に依存せず**SOX構成銘柄リストまたは手動タグ**で代替できる。提言4を先行させる場合はこちらを検討する。

#### 推奨業種粒度

17業種を使う。33業種は銘柄数の偏りが大きく統計が薄くなる（中立化・集計用途では17業種が標準）。

### 提言3: シグナルの結果追跡と価格履歴の永続化【最重要・中規模】

#### 現状

- `signals` / `buy_signals` は `created_at` 付きの追記型だが、**再実行のたびに全削除→再作成**される（`FetchExternalMarketDataAction` 内、要行番号確認）
- `backtest` / `outcome` / `accuracy` に相当するカラム・テーブルは**存在しない**（全走査でゼロヒット）
- `technical_indicators` はマイグレーションのコメント自体が「history table ではなく `holding_id` 1:1 のUPSERTキャッシュ」と明記。**価格履歴は永続化されていない**
- 毎回2年分（104週）の週足を外部取得し、指標算出後に**破棄**している

つまり、システムは毎回「今この瞬間の意見」を生成しては捨てており、**過去に何を言ったか・それが当たったかを一切覚えていない**。

#### なぜ最重要か

1. 全シグナルの閾値（RSI 70、PEG 2.0/1.0、PER 15、ROE 10%、営業利益率 10% 等）が**未キャリブレーションの叩き台**であることを、`accuracy-improvement-backlog.md` 自身が認めている。検証機構なしにこれを確定する方法がない
2. 本書の他の提言（前提Bの是非、営業利益率フィルタの是非、低ボラの導入可否）が**すべて「測れば決着する」問題**。現在は決着させる手段がない
3. `BACKGROUND.md` の要求「判断基準は本人が根拠を目視で理解できる、**信頼できる**ものであること」に対し、信頼は指標の知名度ではなく実績から来る。「RSI70を割ったので売り」より「この条件は過去37回発生し、20日後の平均リターンは-1.2%、的中率61%」の方が要求を満たす

#### 実装が安価である理由

- 分析ロジックが**純粋関数でDB・HTTP非依存**に書かれている（`TechnicalIndicatorCalculator` 等）。過去データを流し込めばそのまま再計算できる
- 価格履歴は既に毎回取得している。**捨てずに貯めるだけ**
- 既に739ケースのテストがあり、回帰の検知能力が高い

#### 変更方針

**(a) 価格履歴テーブルの新設**

週足OHLCV（または少なくとも終値・出来高）を銘柄×週で永続化する。`technical_indicators` のUPSERTキャッシュとは別テーブルにする（用途が違うため統合しない）。

**(b) シグナルの結果追跡**

`signals` / `buy_signals` の削除・再作成をやめ、発生時点のスナップショットとして保持する。あるいは別途 `signal_outcomes` 相当を設ける。記録する項目:

| 項目 | 内容 |
|---|---|
| 銘柄・シグナル種別・発生日時 | 既存 |
| 発生時点の株価 | 新規 |
| 発生時点の判定根拠（各指標の実測値） | 新規。後から「なぜ出たか」を再現するため |
| N営業日後の株価・リターン | 新規。バッチで後埋め |
| 同期間の市場リターン（対TOPIX / 対S&P500） | 新規。超過リターンで評価するため |

Nは複数設定する（20 / 60 / 120営業日）。保有期間が3か月〜1年のため、20日だけでは短すぎる。

**(c) 集計表示**

シグナル種別ごとに、発生件数・平均超過リターン・中央値・的中率・期間別の安定性を表示する。

#### 評価指標（最初から固定すること）

| 区分 | 指標 |
|---|---|
| 主 | シグナル発生後の**超過リターン**（対市場）の平均、その t値 |
| 副 | 的中率、リターンの中央値、期間別（年次）の符号の安定性 |
| **使わない** | **RMSE・決定係数**。ノイズが支配的な対象で誤差指標を見ると判断を誤る |

#### 判定基準（事前に固定すること）

| 判定 | 基準 |
|---|---|
| 機能している | 超過リターンの符号が期待通り、t値 > 2.0、3年中2年以上で符号が一致 |
| 判断保留 | 有意でないがサンプル数が不足（発生30件未満） |
| 機能していない | 符号が期待と逆、または年によって符号が反転 |
| **異常を疑う** | 効果量が過大（月次Rank IC換算で0.10超相当）。**成功ではなくバグ・リークを疑う** |

#### 注意

- **後埋めバッチは「その時点で取得可能だったデータ」だけを使うこと。** 決算データは開示日基準（15:00以降の開示は翌営業日から利用可）
- 過去の価格を遡って取得する場合、**分割調整の扱いを明示的に確認すること**（§3の提言6参照）

### 提言4: エクスポージャー管理エンジン【中規模】

#### 考え方

答えるべき問いを **「どの銘柄を買うべきか」から「今、半導体に資産の何%を置くべきか」へ移す。**

根拠は§2.3の集中度の数学と、§2.4のテーマ逆風に対する唯一の実証的緩和策（エクスポージャー総量の管理）。

#### 判定ロジック（案）

**時系列モメンタム**（対象をその対象自身の過去と比較）を使う。横断面モメンタム（銘柄間比較）とは別物であり、後者と違って強い実証がある。

```
判定対象: SOX指数、日経平均（または TOPIX電機）

  条件A: 200日移動平均より上にあるか
  条件B: 直近12か月リターンがプラスか

  A・B 両方成立 → 半導体エクスポージャーを上限まで許容
  いずれか一方   → 上限の半分
  両方とも不成立 → 下限まで縮小
```

上限・下限の具体値は本人判断（未決事項、§5参照）。

#### 既存の戦略メモとの差異（重要）

`docs/original-docs/stock_auto_order_strategy_notes.md` の③マクロ・セクター文脈層は、既にSOX指数に着目している。ただし用法が:

> SOX指数・日経平均の**52週高値からの下落率**で「セクター全体の**底打ちシグナル**の有無」を判定

これは**逆張り**（下落したら買い）の使い方。§2.2の実証が支持するのは**トレンド追随**（下降トレンドなら縮小）であり、**方向が逆**。

両者は排他ではない（底打ち検知は「いつ戻すか」、トレンド判定は「いつ減らすか」）が、**どちらの用法を採るかは明示的に決める必要がある**。エビデンスの強さでは後者。

#### テスト観点

- 3つの状態遷移が正しく判定されること
- 指数データ取得失敗時に「前回値を保持」するか「判定不能として安全側に倒す」かを明示的に設計し、テストすること（戦略メモ5.2の障害耐性方針と整合させる）
- 状態が頻繁に往復する（ホイップソー）ケースの挙動。必要ならヒステリシス（復帰条件を厳しくする）を検討

### 提言5: 集中度ダッシュボード【小規模】

#### 表示項目

| 項目 | 意味 |
|---|---|
| 保有銘柄の相関行列（直近N週の週次リターン） | 実際にどれだけ一緒に動いているか |
| PCA第1主成分の寄与率 | 単一要因への依存度 |
| **実効ベット数（ENB）** | 「10銘柄持っているつもりが実質3本」を数値化 |
| 対SOXベータ | 半導体サイクルへの感応度 |
| 上位5銘柄の合計ウェイト | 単純な集中度 |

#### なぜ効くか

見えないリスクは取り続けてしまう。**可視化そのものが規律として働く。** UC-005（セクター偏り検出）の自然な拡張であり、既存機能の延長線上に置ける。

なお `overlap_rate`（新規候補の重複度）は既に実装済みで、エビデンス上ほぼ唯一の「無料の昼食」（分散管理）に該当する。本提言はその強化。

#### 注意

提言2（セクターデータ修復）に依存する項目がある。相関・PCA・ENB・対SOXベータは**価格データのみで算出可能**なので、セクターデータ修復を待たずに実装できる。

### 提言6: 前提・フィルタの見直し【要人間判断】

以下は**いずれも提言3（検証機構）が入れば実測で決着する**。検証機構より先に変更しないことを推奨する。

#### 6.1 前提B（`relative_strength_vs_market >= -5.0`）

**現状**: `BuySignalDeterminationService::preconditionsSatisfied()` 内。日経/S&P比の**素の13週リターン差**。**日米に同一適用**。

**論点**:
- 横断面モメンタムは日本で機能しない（Asness: Sharpe 0.03）。米国では機能する → **日米で符号が異なる要因に同一ルールを適用している**
- 素の相対リターンであり、日本で唯一再現する**残差モメンタムではない**
- 同一業種内での相対強度は米国でも残らない（Moskowitz-Grinblatt: 個別モメンタムの60〜73%は業種モメンタムで説明される）→ **CHG-0017系で「対市場13週相対リターン」を序列に追加する方針は、この観点でも不利**

**選択肢**: (a) 日米で分ける、(b) 残差化する、(c) 外す、(d) 検証機構で実測してから決める（推奨）

#### 6.2 `FundamentalHealthEvaluator::MIN_OPERATING_MARGIN = 10.0`

**現状**: UC-005/008/009/010/011 の5機能でゲートとして機能。

**論点**: ADR-0016の実測検証で、**トヨタ自動車・住友商事・住友電工・森永乳業・アイシン・横河ブリッジHD・DCM HD** が営業利益率4.4〜9.4%で `failed` になることが確認されている。ADR-0016はこれを「伝統的薄利業種」と解釈したが、別の解釈が成り立つ:

- クオリティ指標（RMW/CMA）は**東証で有意でない**（Kubota & Takehara 2018）
- 営業利益率10%の要求は、**日本で唯一頑健なバリュー銘柄群を系統的に除外する**方向に働く

**選択肢**: (a) 閾値を下げる、(b) 業種内相対に変える、(c) 必須条件から外して減点要素にする、(d) 検証機構で実測してから決める（推奨）

#### 6.3 低ボラティリティの未使用

**現状**: 判定にもゲートにも使われていない。

**論点**: 高イディオシンクラティックvol→低リターンの効果は**日本が国際比較で最強**（Ang et al.）。月次リバランスでもコスト控除後にプラスのアルファ（証券アナリストジャーナル 2025年4月号）。**日本で最も強い要因が未使用**という状態。

**実装コスト**: 週足終値シリーズは既に取得済みのため、標準偏差の算出のみ。新規の外部データ取得は不要。

**注意**: 計測窓は用途と分離すること。リバーサル・押し目判定が短期窓（13週等）を使うなら、ボラは長めの窓（60〜120日相当）で「その銘柄の性格」を測る。短期窓だと「最近下げたから荒い」を拾ってしまい、両者が打ち消し合う。

#### 6.4 注目テーマの扱い

**現状**: `ShowImportSummaryReportAction`（要行番号確認）が `WatchedTheme` 名でセクターを `whereHas` 絞り込みしており、**テーマ非該当銘柄が候補から構造的に排除される**。UC-009の合成スコアも入力に「注目テーマ合致状況」を含む。

**論点**:
- テーマ型は設定後5年でリスク調整後 約-30%（Ben-David et al. 2023）。原因は**人気化時点で既に割高**であること
- 現在の用法は実質的な**加点**であり、エビデンスとは逆向き
- さらに `BACKGROUND.md` の当初課題「AI・半導体関連に偏っており分散が課題」と**逆方向に作用する**

**推奨**: 機能自体は残し、**用法を「加点」から「集中の警告」へ反転させる**。「このテーマに寄りすぎています」という提示ならエビデンスと整合する。

### 提言7: データ品質の防御【小規模】

#### 7.1 分割調整の前提を明示・固定する

**現状**: `YahooFinanceChartClient` は `chart.result[0].indicators.quote[0].close` を読んでおり、`indicators.adjclose[0].adjclose` を参照せず、`events=split` も付けていない。`app/` 全体を `adjust|split|分割|権利落ち` で走査してコーポレートアクション処理は**1行も存在しない**。

**実害の見込み**: Yahooの `quote.close` は**一般に分割遡及調整済み**とされるため、実害は最悪ケースより小さい可能性が高い。ただし:

- コードはこの前提を**どこにも明示・検証していない**
- **テストがない**
- 非公式APIの挙動変化に対する**防御がゼロ**
- プロジェクト自身の詳細な自己監査文書（既知課題C〜Kを列挙）にも**分割の項目がなく、完全な盲点**

**推奨**: 実害の有無にかかわらず、**前提をテストで固定する**（既知の分割銘柄で期待値を検証する回帰テストを置く）。提言3で価格履歴を貯め始めると、この前提が長期に効いてくるため優先度が上がる。

**参考実例**: NTT（2023年7月・25分割）、ファーストリテイリング（2024年3月・3分割）。未調整なら -96% / -67% の架空リターンが発生する。

#### 7.2 銘柄コードの型

**2024年1月以降、`130A` のような英字入りコードが存在する。** 整数として保持・比較している箇所があると該当銘柄で照合が失敗する。提言2（セクターデータ未取得）の原因候補でもある。

#### 7.3 調整済み価格と未調整価格の使い分け

- **リターン計算** → 調整済み
- **株価水準の判定**（単元金額・呼値・価格フィルタ） → 未調整（実際の株価）

混同すると、過去の「株価1,000円以上」判定が現在のデータでは再現しない等の不整合が生じる。
