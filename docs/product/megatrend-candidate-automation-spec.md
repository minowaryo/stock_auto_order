## 2. 2026-10-16の公開資料確認と、追加取得の境界

FDAの[公式一覧](https://www.fda.gov/medical-devices/artificial-intelligence-enabled-medical-devices/list-artificial-intelligence-enabled-medical-devices)では6列とCSV配布を確認した。[サイト方針](https://www.fda.gov/about-fda/about-website/website-policies)の個別例外を尊重し、[robots](https://www.fda.gov/robots.txt)と既存ADR-0032の取得間隔を維持する。決定日は公開日ではない。新たに全件数や更新速度を測ったとは扱わない。

NEDOは[AI一覧](https://www.nedo.go.jp/koubo/2026_list_05_03.html)の結果リンクから、[マルチモーダル基盤モデルの調査](https://www.nedo.go.jp/koubo/CD3_100437.html)と[分散情報処理技術の調査](https://www.nedo.go.jp/koubo/CD3_100433.html)を確認した。両方にHTML本文の実施予定先があり、前者は再委託先の追記もある。**「結果一覧から本文を1段たどり、企業名・役割を抽出する」経路は構造上可能**と判断した。これは採択先が受注・製品売上を得たことの証明ではない。

NEDOの[利用案内](https://www.nedo.go.jp/qinf/copyright.html)は私的使用・引用等と第三者著作物の条件を示す。無制限の収集許可とは解釈しない。個人利用で必要最小限のフィールド・根拠箇所だけを保存する追加案とし、既存の「本文非取得・1源1リクエスト」を変更するためGate 2で範囲を確認する。

- FDA: 既存の週168時間、直近試行からの最低間隔、5MiB、1リクエストを継続。既存パーサを再利用する。
- NEDO追加案: 一覧は24時間以上空けて1回、企業抽出は別の後続処理で結果HTMLを最大3件/回、各1MiB・15秒、全体120秒、直列・最低1.5秒間隔。同じ結果の再取得も24時間以上空ける。
- 年度一覧にある結果URLを待ち行列に残す。初回は結果日の新しい順に3件、残りは「未解析」で件数を表示する。後続起動で続き、全件完了前に全範囲を確認済みと表示しない。更新済み資料の再確認もこの上限内で回し、一覧取得日時と本文解析日時を別に持つ。
- 結果ページの見出しから必要な節だけを解析し、採択先/再委託先を区別する。PDF・画像・動画の自動取得、任意リンクの再帰探索、本文全体の永続保存は本差分に含めない。
- H02は既存24時間/1MiBを継続。[noteの公式案内](https://www.help-note.com/hc/ja/articles/4402395202841)でRSSによる更新表示を確認したが、今回のRSS直URL確認はブラウズツールのエラーで未確認。既存実装の動作と混同せず導入検証に残す。

NEDOの追加取得は既存起動時の一覧確認と別の仕事として直列実行し、価格追跡やウォッチリスト更新を同時に増やさない。詳しい保存・実行設計はGate 2後のADR/data-model差分で確認する。

## 3. 企業候補の作り方

1. **資料を取得**: 情報源・外部ID・URL・日付・取得時刻と必要フィールドを保存する。全体の取得成功と個別の解析待ちを区別する。
2. **企業を抽出**: FDAはCompany、NEDOは実施予定先/再委託先の節、H02は題名中の確認済み別名を使う。連絡先や審査委員を候補企業にしない。
3. **テーマの根拠を付ける**: FDAは医療AI一覧掲載という理由、NEDOは事業コード/事業名との対応、H02は題名のテーマ語と企業名の双方があることを根拠にする。分類ルールは固定版で追跡する。曖昧なものは未分類へ残す。
4. **企業と上場主体を照合**: 日本株は既存の正規銘柄データの利用可能範囲と[JPX一覧](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html)を確認して使う。米国株は[SEC公開ティッカー対応](https://www.sec.gov/files/company_tickers_exchange.json)を公式照合候補とし、[取得条件](https://www.sec.gov/about/developer-resources)を守る。JPX月末データ・SEC対応表だけで上場廃止や企業間の資本関係を完全に確定しない。
5. **登録状況を照合**: 市場・コードが対応したものを最新の保有/CSV/ウォッチリストと比較し、参照時点を表示する。未同定は未登録と断定しない。
6. **一覧へ自動表示**: 元発表×言及法人の下書きを作り、同じ企業の資料を束ねる。再取得しても本人の確認・訂正・見送りを上書きしない。

法人名は前後空白等の表記整理と確認済み別名だけを使い、似た文字列だけで統合しない。子会社・ブランド→親会社の対応は公式根拠と確認記録のある対応だけを使う。自動で一致した場合も「上場先候補」であり、本人確認済みにはしない。日米外と公式に分かるものは対象外、分からないものは要確認として残す。

**候補生成の必須条件**は出典URL・言及法人・抽出方法/根拠の存在。テーマ・上場先・元発表日の欠測は許し、欠けた項目を表示する。システムによる説明は取得フィールドから構成し、LLMの導入を必須にしない。

## 4. 確認・監視登録の流れ

`自動抽出 → 未確認 → 確認中 → 調査記録へ取り込む → 調査中/保留/見送り → 条件を満たしたら監視登録`

下書きは本人確認前のデータとして既存の調査記録と区別する。取り込みでは企業名・資料名・URL・元フィールド・分類理由を再入力させない。「資料からの要点」と「本人の追記」は別にし、本人の確認日を取得日で埋めない。確認済みの主張・反証チェックや監視登録理由は既存UC-016と同様に本人が確認・記録する。

保留・見送りは取り消せる。再取得で復活・重複生成しない。同じ下書きの二重取り込みは既存調査記録へ関連付ける。資料が変わったら差分・再確認を示し、監視登録先の変更は本人に委ねる。未登録・未保有の断定や監視追加は確定時に再照合する。

## 5. 画面（追加Gate 2承認済み・2026-10-19）

静的モックは架空データを使い、実際に取得・登録できる画面とは区別する。

| 画面 | 構成と動作 |
|---|---|
| [候補一覧](mockups/screen-UC016-research-candidate-discovery.html) | 説明→ウォッチリスト/調査候補切替→更新状況→企業候補数・未登録・上場要確認・参照資料数→企業候補表。企業名・テーマ/抽出理由・役割/段階・登録状態・元資料・次の確認を出す。既定は検出日降順で20件。テーマ/市場/登録状態/新着・初回取得を絞り込める |
| [候補詳細](mockups/screen-UC016-research-candidate-review.html) | 自動入力済みの企業・テーマ・資料由来の要点・出典・日付、上場先候補と照合根拠、未確認事項をまとめる。本人は資料を開き、内容を確認して調査記録へ取り込む。確認チェックは初期OFF |
| [状態別表示](mockups/screen-UC016-research-candidate-states.html) | 初回取得中、初回の過去資料、取得成功0件、企業未抽出、取得失敗、照合元欠測、上場先不明、対象外/保留を別に表示する |

情報源ごとの詳細は折りたたみ、企業候補を画面の主役にする。「資料のみ」は候補表と別枠、「手動で記録」は最下部の補助操作。「この画面からの自動売買」や投資順位は追加しない。

集計は現在の絞り込み範囲と一致させ、同企業の複数資料を企業数で二重に数えない。未同定同士の法人同一性を確定できなければ仮の候補数であると示す。新着は前回取得以降の初検出、初回取得の過去資料は別区分。元資料発表日・決定日・初検出日を分け、「今週の発見」は元発表も今週と確認できた場合だけ使う。
