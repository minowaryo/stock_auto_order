# CHG-0031: メガトレンド情報源からの候補発見（変更案件草案）

> 状態: Proposed。2026-10-03時点でGate 1〜4の承認・実装は行っていない。関連する設計判断は[ADR-0022](../adr/ADR-0022-megatrend-source-radar.md)。

## 背景

[現行要件のOUT](requirements.md)はメガトレンドの自動発見・予測・選定を対象外とし、[UC-012](use-cases.md)は楽天証券お気に入りCSVにある未保有銘柄の分析までを扱う。本人は、半導体・AI基盤、電力、フィジカルAI、医療AIなどから、未登録の日本株・米国株を広く見つけ、信頼できる無料情報源で確度を上げたい。既存の判断ロジックと混ぜず、変更案件として段階的に進める。

## 第1段階: 既存候補の週次ダイジェスト

- [情報源台帳](megatrend-source-selection.md)の一次資料と公開専門家記事を手動で確認し、既存ウォッチリスト候補に関する新しい出来事と反証を週1回まとめる。
- 表示・記録するのは`銘柄 / 出来事 / 元資料URL / 発表日 / 証拠段階 / 反証・不明点 / 確認日`。株価ランキングや自動買い推奨は含めない。
- まず4週間は[調査カード](megatrend-research-card-template.md)と[試行ログ](megatrend-source-pilot-log.md)で手動試行し、重複率、一次資料到達率、所要時間を測る。アプリ内ダイジェストの要件・UCは試行後に確定する。

## 第2段階: 市場から未登録銘柄を発見

- 公式統計・補助採択・規制一覧・公開規格・業界記事から、テーマに関連する工程・製品と企業名を拾う。日本株・米国株の両方を対象にする。
- `元の出来事 → 企業の役割 → 法人・上場親会社 → 市場・ティッカー → 採用/受注/売上 → 反証`をカードに残す。子会社、同名企業、非上場企業、上場廃止・ティッカー変更は未確定として人手確認へ回す。
- 複数の媒体が同じ発表を紹介した場合は1件に束ねる。専門家・SNSの評価を証拠数や売買スコアにしない。
- 本人が候補の上場主体と元資料を確認し「監視する」と選んだ場合のみUC-012へ受け渡す。現行UC-012の入口は楽天証券お気に入りCSVなので、アプリからの直接追加が必要なら新UC・データモデルで明示する。

## 受け入れ条件の草案

1. 各候補に元資料URL・発表日・取得/確認日・証拠種別が表示され、公開記事のコピー本文を保持しない。
2. 発見経路の媒体が複数あっても、同一の元発表は1件として記録される。
3. 上場主体・ティッカー未確定の企業は、UC-012にも売買シグナルにも自動で入らない。
4. 本人が監視を選ばなかった候補は既存ウォッチリストを変えない。
5. 規制承認、補助採択、設備計画は売上・利益確認と別欄に表示され、欠けた段階は`未確認`と示す。
6. 取得源ごとに無料閲覧・公式API/配布ファイル・手動URL登録を区別し、利用条件を満たす経路だけを実装する。
7. 情報源の欠測や遅延が分かるようにし、古い情報を「今週の新情報」と誤表示しない。

## 変更範囲と順序

| 段階 | 対象 | 完了条件 |
|---|---|---|
| 今回 | 情報源台帳、調査カード、ADR、CHG追跡 | 5領域の無料情報源と制約、受け渡し境界がレビュー可能 |
| 手動試行 | 週次調査記録 | 4週分の固有企業数・一次証拠到達・誤同定・反証・所要時間を集計 |
| Gate 1 | `requirements.md` | OUTの改訂範囲と第1/第2段階の機能要件を本人が確認 |
| Gate 2 | `use-cases.md` | ダイジェストと発見の別UC、入力・出力・例外・人手確認を確定 |
| Gate 3 | `data-model.md`（保存が必要な場合） | 情報源、元発表、証拠、候補、銘柄対応の保存と削除・更新を確定 |
| Gate 4 | UC名に沿ったRedテスト | 出典重複、銘柄誤同定、未承認昇格、欠測・遅延を含むテストの承認後に実装 |

現行UC-012のシグナル判定、`holdings`、`watchlist_items`、既存の株価取得や外部APIはこの草案段階では変更しない。J-Quants Freeの12週遅延とAlpha Vantageの上位20件・無料枠により、株価ランキングを市場全体の発見源には採用しない。情報源の成果が低ければ第2段階の自動化対象を減らす。

## 主なリスクと評価

- **網羅性**: 公的一覧も非網羅、専門家は扱う企業が偏る。日本・米国、4テーマの源別発見数を測り、穴を可視化する。
- **銘柄誤同定**: 補助先・子会社・製品開発者が上場主体と異なる。親子関係・ティッカーを公式資料で確認する。
- **過大評価**: プレスリリース、規制承認、落札は利益の証明ではない。収益への距離と反証を記録する。
- **取得条件**: TDnet公開画面、動画字幕、有料メルマガ、SNS全量取得には制限がある。条件確認前の自動収集を要件化しない。

テスト候補は第1段階の新UC「既存候補の週次ダイジェスト」と第2段階の新UC「市場からの調査候補発見」のタイトルから命名する。番号はGate 2のUC策定時に割り当てる。既存UC-012については受け渡し後も現在の分析条件が保たれることを回帰確認する。
