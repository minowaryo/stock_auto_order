# CHG-0031: メガトレンド情報源からの候補発見（変更案件草案）

> 状態: Gate 1は2026-10-03本人承認済み、2026-10-04に正式要件F-016へ反映。[UC-016](use-cases.md#uc-016-市場からの調査候補発見確認)とUC-012受け渡し差分は2026-10-04にGate 2本人承認済み。[保存設計](../architecture/data-model.md)と[ADR-0025](../adr/ADR-0025-research-candidate-storage.md)は2026-10-04にGate 3本人承認済み。Gate 4は未承認。本人指示により今回のモックは省略。4週後の品質再精査を[PLAN](../../PLAN.md)に残す。旧案（お気に入りCSV内のみ）は撤回済み。関連: [ADR-0022](../adr/ADR-0022-megatrend-source-radar.md)。

## 背景

**4週後の再精査（2026-10-03本人指示）:** 情報源の正確さ・裏付けやすさと発見への実用性を確認し、2026-11-02以降を目安に[Gate 1草案の再精査メモ](megatrend-discovery-gate1-requirements-draft.md#4週間の情報源試行後に再精査するメモ2026-10-03本人指示)に沿って要件を見直す。先行する要件審議によって試行後の修正を妨げない。

変更前の要件はメガトレンドの自動発見・予測・選定を対象外としていた。[現行要件](requirements.md)ではF-016の調査候補発見をINへ加え、[UC-012](use-cases.md)は楽天証券お気に入りCSVにある未保有銘柄の分析までを扱う。本人は、半導体・AI基盤、電力、フィジカルAI、医療AIなどから、未登録の日本株・米国株を広く見つけ、信頼できる無料情報源で確度を上げたい。既存の判断ロジックと混ぜず、変更案件として段階的に進める。

## 情報源試行（Gate 2以降の共通処理の検討と並行）

- **主成果は既存ウォッチリストにない上場企業の発見**とする。既存候補の週次ダイジェストは副次的に記録するが、これだけで本人の目的を達成したと扱わない。
- [情報源台帳](megatrend-source-selection.md)は広域候補として維持し、最初はAI基盤（半導体・電源/冷却を含む）・フィジカルAI・医療AIの3テーマと、OCP、NEDO、FDA、ものづくり太郎の公開動画、中島聡さんの公開noteの5源に絞る。
- [調査カード](megatrend-research-card-template.md)と[試行ログ](../investment-research/megatrend/source-pilot-log.md)で、過去12か月の固定サンプルと4週間の新着を分けて測る。元資料・上場主体・反証・ウォッチリスト重複・確認時間を記録する。
- 遡及確認と4週間の新着を合わせ、既存ウォッチリスト外の上場企業を3社以上、2テーマ以上、2つ以上の独立した元発行主体から確認できたかを、**定期取得する情報源の選定条件**として判定する。Gate 1の目的・範囲の審議はこの結果を待たない。これは情報源の最低限の実用性確認であり、市場の網羅性や投資成果を保証しない。詳細な数え方と未達時の扱いは試行ログに記す。

## Gate 1で先に定めるアプリ機能の範囲

- [Gate 1要件変更草案](megatrend-discovery-gate1-requirements-draft.md)で、未登録企業の発見をINに加える範囲と、テーマ予測・有望度の自動判定をOUTに残す境界を本人が承認した。具体的な取得源を承認したことにはしない。
- Gate 1承認後、情報源に依存しない出典管理・銘柄同定・候補表示・人手確認のUCをGate 2で検討する。源固有の自動取得フローは、4週試行と取得条件の確認後に確定する。

## Gate 2以降に具体化するアプリ機能

- **未登録銘柄を調査候補として発見する機能を優先**する。公式統計・補助採択・規制一覧・公開規格・業界記事から、テーマに関連する工程・製品と企業名を拾う。日本株・米国株の両方を対象候補にする。具体的な定期取得対象は試行で有効と確認した経路から選ぶ。
- `元の出来事 → 企業の役割 → 法人・上場親会社 → 市場・ティッカー → 採用/受注/売上 → 反証`をカードに残す。子会社、同名企業、非上場企業、上場廃止・ティッカー変更は未確定として人手確認へ回す。
- 複数の媒体が同じ発表を紹介した場合は1件に束ねる。専門家・SNSの評価を証拠数や売買スコアにしない。
- 本人が候補の上場主体と元資料を確認し「監視する」と選んだ場合のみUC-012へ受け渡す。UC-016からの直接登録はGate 2承認済みで、保存設計はADR-0025とdata-model.mdに明示し、2026-10-04にGate 3本人承認済み。
- 既存候補の週次ダイジェストは、試行で価値と確認時間を測り、別機能にするか判断する。未登録銘柄の発見と混ぜて先に実装するとは決めない。

## 受け入れ条件の草案

1. 各候補に元資料URL・発表日・取得/確認日・証拠種別が表示され、公開記事のコピー本文を保持しない。
2. 発見経路の媒体が複数あっても、同一の元発表は1件として記録される。
3. 上場主体・ティッカー未確定の企業は、UC-012にも売買シグナルにも自動で入らない。
4. 本人が監視を選ばなかった候補は既存ウォッチリストを変えない。
5. 規制承認、補助採択、設備計画は売上・利益確認と別欄に表示され、欠けた段階は`未確認`と示す。
6. 取得源ごとに無料閲覧・公式API/配布ファイル・手動URL登録を区別し、利用条件を満たす経路だけを実装する。
7. 情報源の欠測や遅延が分かるようにし、古い情報を「今週の新情報」と誤表示しない。

UC-012のシグナル判定や既存の株価取得・外部APIは今回変更しない。本人確認後の`holdings`・`watchlist_items`への受け渡しはGate 2承認済みで、実装はGate 4のテストケース承認後に行う。J-Quants Freeの12週遅延とAlpha Vantageの上位20件・無料枠により、株価ランキングを市場全体の発見源には採用しない。情報源の成果が低ければ自動取得の対象を減らす。

## 主なリスクと評価

- **網羅性**: 公的一覧も非網羅、専門家は扱う企業が偏る。最初の3テーマについて日本・米国別の発見数を測り、電力など未試行領域を明記して次の入替候補にする。
- **銘柄誤同定**: 補助先・子会社・製品開発者が上場主体と異なる。親子関係・ティッカーを公式資料で確認する。
- **過大評価**: プレスリリース、規制承認、落札は利益の証明ではない。収益への距離と反証を記録する。
- **取得条件**: TDnet公開画面、動画字幕、有料メルマガ、SNS全量取得には制限がある。条件確認前の自動収集を要件化しない。

テスト候補はGate 2で定める新UC「市場からの調査候補発見」のタイトルから命名する。ダイジェストが採用される場合のみ別UCを定義する。共通処理はUC-016として採番済み。既存UC-012については受け渡し後も現在の分析条件が保たれることを回帰確認する。
