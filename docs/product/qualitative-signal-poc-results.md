## J-Quants Lightの効果の見積もり（2026-10-09、開発PCで実施）

### 方法

- **対象**: アプリに取り込み済みの日本株150銘柄（`holdings.market='jp'`。ウォッチリストの銘柄も含む）。データを返さなかった1銘柄（2644）を除く149銘柄で集計した。
- **スクリプト**: [scripts/poc/jquants_light_effect.py](../../scripts/poc/jquants_light_effect.py)。アプリと同じ無料版のキーを使った。Lightの契約は不要だった。
  - 無料版は「2年12週前〜12週前」に開示された決算を返す。そのため、過去の各週について、Light版で見える決算（その週までの開示）と無料版で見える決算（その12週前までの開示）の両方を再現できる。
- **追加の確認**: 各銘柄の最新の開示行の種類（通期・四半期・予想の修正）と、空の項目を数えた（一時スクリプト。結果は`storage/app/qualitative-eval/newest_row.json`）。
- 出力: `storage/app/qualitative-eval/light_effect.json`（git管理外）

### 結果

| 項目 | 結果 |
|---|---|
| 無料版の決算の古さ（Light比、平均） | **82.5日** |
| 財務健全性の判定が食い違う週 | 0週（ただし比べられたのは11,874週中215週だけ。下記の限界を参照） |
| 業績予想の修正（純利益予想の変化がわかる行） | 2年分で35銘柄・59件。上方33・下方15・変更なし11。幅10%以上は40件 |
| 最新の開示行が予想の修正（実績が空） | 149銘柄中**3銘柄** |
| 最新の開示行が四半期決算 | 149銘柄中**52銘柄**。52銘柄すべてでROE・年間配当が空、41銘柄で1株純資産（BPS）が空 |
| 最新の開示行が通期決算 | 149銘柄中94銘柄（うち12銘柄は営業利益が空。銀行など） |

アプリのDB（`fundamental_indicators`、日本株149件、2026-10-01取得）でも、ROEが空70件・PERが空33件・自己資本比率が空25件・営業利益率が空30件だった。

### 読み取れること

- **変更要求案 §7.2の疑いは、当たっているが、主な原因ではない。**
  - アプリは`FundamentalIndicatorMapper::map()`で、種類を見ずに最新の開示行（`$statements[0]`）からPER・PBR・ROE・自己資本比率・営業利益率・配当利回りを計算している。最新の行が予想の修正だと、これらがすべて空になる（現時点で3銘柄）。
  - より大きいのは、**最新の行が四半期決算の場合**。J-QuantsのROE・年間配当は通期の行にしか入らず、BPSも四半期では空のことが多い。そのため、約3分の1の銘柄でROE・PBR・配当利回りが空になっている。
  - 「新しい順16件」の切り捨ては、実害がない。無料版が返すのは1銘柄あたり最大13行だった。
- **Lightに切り替えると、この問題が大きくなる。**
  - 無料版では12週遅れのため、3月決算の会社の最新の行は、多くの時期で通期決算になる（いまは5月の通期決算が見えている）。
  - Lightでは8月の第1四半期決算がすぐ見える。そのため、3月決算の会社の大半で、最新の行が四半期決算になる。**修正しないままLightに切り替えると、ROE・PBR・配当利回りが空の銘柄が大幅に増え、財務判定が崩れる。**
  - Lightを契約するなら、先に指標の計算元を直す必要がある（例: ROE・BPS・配当は最新の通期の行から取る。実績が空の行は飛ばす）。
- **Lightの直接の効果**: 決算が約12週早く見える。業績予想の修正は、2年間で35銘柄・59件あった（1銘柄あたり年に約0.2件）。上方33件・下方15件で、幅10%以上が40件と、注記として意味のある大きさのものが多い。

### 限界

- **財務健全性の判定が食い違う週の数（0週）は、判断材料にならない。** スクリプトはROEがある行同士だけを比べている。ROEは通期の行にしかないため、比べられたのは全体の約2%（215週）だけだった。通期の行同士の比較に限れば、12週の遅れで判定が変わることはほぼない、と言えるにとどまる。
- 無料版の2年分のデータでの見積もりで、Lightの実際の更新タイミング（毎日18時・24時半）は確かめていない。
- 対象はアプリに取り込み済みの銘柄だけで、市場全体ではない。

## 事前確認2: 投資仮説の形式（Q1）での判定と、対象の取り違え（2026-10-08、このPCで実施）

### 目的

- **形式の確認**: 本番の主用途である「この情報は投資仮説を損なうか」（Q1、Yesの確率）の形式で、Haikuを測る。
- **誤りの確認**: 事前確認1で見つかった「対象の取り違え」が、この形式でどう出るかを確かめる。
- **Jevとの比較の準備**: 別PCでJevを同じデータにかけて比べられるよう、組み合わせを固定して保存した。

### 方法

| 項目 | 内容 |
|---|---|
| データ | chABSAの文から、組み合わせ100件を作った（seed 20261008）。スクリプトは[scripts/poc/prescreen_thesis.py](../../scripts/poc/prescreen_thesis.py)、組み合わせはgit管理外の`storage/app/qualitative-eval/thesis/pairs.json` |
| 仮説 | 「『{対象}』の状況は良好で、改善が続いている。」（アプリが自動で作る仮説の代わり） |
| A_break／A_keep（各30） | **同じ文**に、良い対象と悪い対象が両方ある。悪い対象の仮説なら「損なう」、良い対象の仮説なら「損なわない」が正解（取り違えのテスト）。どちらの対象も、その文の中で極性が1つに定まるものだけを使った |
| B_irrelevant（20） | 仮説の対象が文に出てこない組み合わせ。正解は「損なわない」 |
| C_break（20） | 対象が1つで悪い文。正解は「損なう」 |
| 実行 | `claude -p --model haiku`（APIキーなし）。10件ずつ、3回。同じ文の2つの組み合わせは、別の呼び出しに分けた。計30呼び出し、エラー0件 |
| 確率 | 自己申告の「損なう確率」の3回平均 |

### 結果

| 指標 | 値 |
|---|---|
| ROC-AUC（95%信頼区間） | **0.946**（0.89〜0.99） |
| 0.5で区切ったときの正解率 | 85%（77〜91%） |
| Brier／ECE | 0.101／0.078 |
| 「損なう」の見逃し（A_break・C_break） | **50件中1件**。その1件（営業外費用が67%減）は、chABSAのラベル側が疑わしい |
| 誤報（A_keep・B_irrelevant） | **50件中14件**（A_keep 7件、B_irrelevant 7件） |
| 自動判定の領域（検証計画 §5の閾値 0.8／0.2） | p≧0.8が50件で適合率90.0%、p≦0.2が30件で見逃し1件。全体の80%を自動で判定できた |
| 自動判定の領域（参考: より厳しい 0.9／0.1） | p≧0.9が38件で適合率94.7%、p≦0.1が28件で見逃し1件。全体の66% |

### 読み取れること

1. **見逃しはほとんどない。** 仮説を損なう情報は、同じ文に良い記述が混ざっていても30件すべて検出した（A_break 30/30）。
2. **問題は誤報**で、2つの型がある。
   - **取り違え**（A_keep 7件）: 仮説の対象は好調なのに、同じ文の別の悪い記述に引っ張られて「損なう」とした。事前確認1の誤りと同じ種類。
   - **無関係の悪材料**（B_irrelevant 7件）: 仮説の対象が文に出てこないのに、文全体の悪い内容を理由に「損なう」とした。ただし7件の多くは、仮説の対象が「売上高」「販売量」のような一般的な語で、文と実際には関係があった。**テストの作り方の弱さ**も含む。
3. **実際の出現率では、誤報が多くなる。**
   - 本番では、仮説を損なう開示は全体の数%と見込む。
   - 検出率と誤報率を出現率3%に当てはめると、注記のうち本当に仮説を損なうのは、**閾値0.8で約22%**（検出率90%・誤報率10%）、**閾値0.9でも約36%**（検出率72%・誤報率4%）にとどまる。
   - 本番では、関連度の問い（Q5a）で先に絞り込むことと、注記を「確認待ち」として扱うこと（自動で売り判断にしない）が必要。変更要求案 §3.2の方針と合う。
4. **問いの文面の改善余地**: 誤報の多くは「仮説の対象についての記述だけで判断する」という指示が守られなかったもの。本検証では、対象を明示する入力の形（対象・仮説・文を別の欄にする）や、Jevの`criteria`のような判定基準の書き方を比べる。

### 限界

- 仮説は機械的な一文で、本番の仮説（成長・割安・テーマ）とは違う。文も開示ではなく有価証券報告書の1文。
- 正解はchABSAのラベルから機械的に作ったので、ラベルの付け方の揺れ（事前確認1）をそのまま引き継ぐ。
- B_irrelevantの作り方が粗い（一般的な語の対象は、文と関係してしまう）。
- 件数が少ない（各区分20〜30件）。

### Jevとの比較の準備（この環境では実行していない）

- **スクリプト**: [scripts/poc/jev_eval.py](../../scripts/poc/jev_eval.py)。事前確認1・2と同じ項目を、Jevにかける。
  - 事前確認1はChoice（3通りの並び順）、事前確認2はNoul（2回）で実行する。
  - 経路はOpenRouter（`typesafe/jev-1.13`）か本家（`jev-1.13.0`）。

- **この環境での確認**: 偽の応答（`--mock`）での動作と、キーがないときに止まることだけを確認した。実際のAPIの応答形との一致は、別PCでの初回実行で確かめる。

## 事前確認1: Claude Haiku 4.5 × 公開データchABSA（2026-10-07〜08、このPCで実施）

### 目的と位置づけ

- **目的**: 本人のデータで本検証をする前に、次の3点を安く確かめる。
  1. Haikuが日本語の業績説明文の向き（良い／悪い）を読めるか
  2. 確率の出し方（同じ問いの繰り返しでの回答の割合と、自己申告の確率）のどちらが使えるか
  3. Claude Codeのヘッドレス実行（APIキーなし）で評価を回せるか
- **合否には使わない**（検証計画 §3.5）。chABSAは2016〜2017年度の有価証券報告書の「業績等の概要」の文に、対象語ごとの極性を付けたデータで、開示の影響の判定とは課題が違う。
- **Jevは比較していない**。この環境ではJevを呼べないため。

### 方法

| 項目 | 内容 |
|---|---|
| データ | chABSA（CC BY 4.0、Hugging Faceのミラー`TheFinAI/jp-chABSA`）から、重複を除いて300文字以下の文を無作為に120件抽出した（positive 45・negative 45・neutral 30、seed 20261007） |
| 問い | 「文の中で対象語について述べられている状況は、会社・経済にとって好ましいか（positive／negative／neutral）」と、選んだラベルが正しい確率 |
| 変種 | V1 = 日本語の指示、V2 = 英語の指示（文は日本語のまま） |
| 実行 | `claude -p --model haiku --json-schema ...`（サブスクリプション、APIキーなし）。1回の呼び出しで10件をまとめて判定し、各まとまりを並び順を変えて5回実行した。計120呼び出し、エラー0件 |
| 確率 | (a) 5回の回答のうち多数派ラベルの割合、(b) 自己申告の確率（多数派ラベルの回の平均） |
| スクリプト | [scripts/poc/prescreen_chabsa.py](../../scripts/poc/prescreen_chabsa.py)、[scripts/poc/analyze_chabsa.py](../../scripts/poc/analyze_chabsa.py)。出力はgit管理外の`storage/app/qualitative-eval/chabsa/` |

### 結果

| 指標 | V1（日本語の指示） | V2（英語の指示） |
|---|---|---|
| 3分類の正解率（95%信頼区間） | **85.8%**（79.2〜91.7） | 81.7%（74.2〜88.3） |
| 3分類のmacro-F1（95%信頼区間） | 0.843（0.768〜0.905） | 0.798（0.714〜0.869） |
| 良い／悪いの2分類だけの正解率（neutralを除く90件） | **93.3%** | 90.0% |
| neutralの再現率 | 63.3%（30件中10件をnegativeと判定） | 56.7% |
| 5回の回答がすべて一致した項目 | 87.5% | 77.5% |
| ECE（回答の割合） | 0.132 | 0.122 |
| ECE（自己申告の確率） | **0.041** | 0.048 |
| 2分類で、自己申告の確率が0.9以上の項目 | **65.6%の項目で、正解率100%（59件中59件）** | 50.0%の項目で、正解率100%（45件中45件） |

所要時間は、10件をまとめた1呼び出しあたり中央値30秒。API料金に換算すると、120呼び出しで計$2.62（思考トークンを含む。サブスクリプションでの実行のため実費はなし）。

### 読み取れること

1. **日本語の業績説明文の向きは、かなり正確に読める。**
   - 良い／悪いの2分類で93%。
   - 誤りの多くは、chABSAが「先行き不透明」「リスク」をneutralとする付け方を、Haikuがnegativeと読んだもの。判定の誤りというより、ラベルの付け方の違いに近い。
2. **日本語の指示のほうが、英語の指示より少し良い。** ただし差は信頼区間の範囲内で、有意ではない。検証計画の変種比較（V1〜V3）は本検証でも行う。
3. **確率は、5回の回答の割合より自己申告の確率のほうが使える。**
   - **回答の割合**: Haikuは同じ問いにほぼ同じ答えを返すため、87.5%の項目で5回とも一致した。それでもその中の正解率は86.7%で、割合は過信側に偏る（ECE 0.13）。
   - **自己申告の確率**: 較正が良く（ECE 0.04）、「0.9以上だけを自動で判定する」とすると、2分類では65.6%の項目を誤りなく判定できた。
   - **検証計画の修正**: §4を、自己申告の確率を主とし、回答の割合を補助とするように改めた（2026-10-08）。
4. **Claude Codeのヘッドレス実行で、評価は問題なく回せる。** APIキーは不要だった。
5. **自動判定の目安（検証計画 §5の「自動で判定できる項目が50%以上」。精度90%は、ここでの参考の目安）は、この代用の課題では満たした。** ただし課題が本番より易しい（文単位・極性のみ）。本番の課題（仮説を損なうか、会社固有の悪化か）で同じ水準が出るかは、本検証で確かめる。

### 結果の正しさの確認（2026-10-08）

- **何を正解としたか**: chABSAに付いている人手のラベル（データ作成者による注釈）を正解とし、Haikuの5回の回答の多数派と一致した割合を正解率とした。本人や評価者（Claude）の判断ではない。
- **回答の対応付け**:
  - 1,200件の回答枠のうち、Haikuが答えを省いたのは8件（0.7%）。存在しないIDや、重複した回答は0件だった。
  - 各項目には4〜5回分の回答がある（V1は117件で5回・3件で4回、V2は115件で5回・5件で4回）。
- **集計の検算**: 2分類の正解率（V1 93.3%）を、集計スクリプトとは別のコードで再計算し、一致を確認した。
- **抜き取り確認**: V1から無作為に20件を選び、評価者（Claude Opus）が原文を読んで判断した。
  - **16件**: Haikuと正解ラベルが一致。読んでも妥当だった。
  - **2件**: 正解ラベルは「どちらでもない」、Haikuは「悪い」。「先行き不透明」の文で、ラベルの付け方の違い。読んだ限りではHaikuの判断も妥当。
  - **1件**: 判断が分かれる。売上は8.4%減、セグメント利益は20.5%増。正解ラベルは「悪い」、Haikuは「良い」。
  - **1件**: **Haikuの誤り**。対象の子会社については「営業損益の改善の遅れ・多額の為替差損」と書かれているのに、文全体の「増益」に引っ張られて「良い」と判定した。**対象を取り違える誤り**で、本番の投資仮説チェックでも起こりうる種類の誤り。
- **まとめ**: 正解ラベル自体にも、判断の分かれる項目が1割程度ある。Haikuの実力は、正解率の数字より少し高い可能性がある一方で、対象の取り違えという実質的な誤りもある。
- **未確認**:
  - ミラー（`TheFinAI/jp-chABSA`）が元のchABSAと同一か。元の配布リンクは切れていて照合できなかった。ミラーのライセンス表示はMITで、元のCC BY 4.0と異なる。
  - 抜き取りは20件だけ。

### 限界

- 課題が違う: 開示の影響の判定ではなく、文単位の極性。
- データが古い（2016〜2017年度）。
- 10件をまとめて判定しているので、1件ずつの判定とは結果が異なりうる。
- 正解ラベルは公開データのもので、本人の判断とは一致しない場合がある。
- Jevとは比較していない。Jevの売りである「較正された確率」がHaikuの自己申告より良いかは、別PCでの本検証で確かめる。
