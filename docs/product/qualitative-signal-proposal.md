## 0. 結論

| 観点 | 評価 | 根拠（詳細は各章） |
|---|---|---|
| 技術的な組み込み | **容易** | SDKは不要。LaravelのHTTPクライアントでJSONを1回POSTするだけ（§2.2）。既存の`app/Services/MarketData/*Client`と同じ型で書ける |
| API費用 | **ほぼゼロ** | 想定規模で、Jevは月$0.01〜$0.7、Haiku 4.5は月$0.2〜$12（§4） |
| 定性情報の取得 | **ボトルネック**（ただし数値の部分は安く取れる） | 開示の**本文**を正規に自動取得できる経路は、J-Quants Light＋TDnetアドオン（月約¥12,650）だけ。ただし**Light（¥1,650）だけでも、業績予想・配当予想の修正を開示日時と修正後の数値つきで遅延なく取れる**（2026-10-07確認）。アドオンは月単位で解約でき、5年分を遡れるので、決算期の後だけ契約する運用（年約4.4万〜5.1万円）もできる（§5） |
| 日本語での精度 | **未検証・最大のリスク** | Jevの公式も「英語以外は同等ではない」と明記している。日本語の公開ベンチマークはない。独立評価（英語）では、Haiku 4.5に正解率・較正とも劣った（§2.3） |
| 事業者の成熟度（Jev） | **低い** | 早期アクセス・SLAなし・非推奨化の方針なし。リリース直後に破壊的変更がすでにあった（§2.4） |
| AIを使わない代替 | **一部の用途はこれで足りる見込み** | 開示タイトルの正規表現＋XBRLの数値で、一過性利益・社長交代・決算延期・修正の方向はかなり判定できる（§3.1）。AIが必要なのは、文脈を読む投資仮説チェック・成長鈍化・見通しのトーンが中心と見込む |

**推奨**: 次の三点で進める。

- **段階0（PoC）を、アプリの外の検証スクリプトとして先に行う。** 結果がGOの用途だけ、アプリへの組み込み（段階1以降）をGate 1から進める（§7）。
- **既定のモデルはHaiku 4.5とする。** Jevは、主な用途（Q1）でHaikuより有意に良い場合だけ採用する。費用差は月数ドルしかないうえ、Jevは早期アクセスでSLAがないため。
- **すべての判定を、問い・確率・モデル版とともに保存する。** 既存のシグナル事後検証（ADR-0017）に乗せ、「定性判定は当たっていたか」を実測する。これが「定性情報の数値化」の最大の価値になる。

## 1. 目的

既存の判定は、数値（含み益率・PER・業種比較・テクニカル指標）だけで行っている。株価が動いた**理由**、つまり開示・ニュースの中身は扱っていない。この変更は、文章を「確率」や「段階評価」に変換して、次の三つを可能にする。

1. **既存のルール判定に、定性の注記を足す**（例: 投資仮説が崩れる兆候のある開示が出た保有銘柄に注記を付ける。整理検討などの区分への自動移動はしない）
2. **定性の判定を事後に検証できるようにする**（判定を保存し、その後の超過リターンと突き合わせる）
3. **週末に読むべき開示を絞る**（関連のない記事を除外する）

株価の予測、数値の閾値判定、日付の計算には使わない（§3.4）。

### 2.2 メモに書かれていない、重要な事実

- **呼び出し形式**: OpenAI互換のチャットAPIではない。どの経路も共通の独自JSONで呼ぶ（`state`に入力、`questions`に問いを並べる）。

  | 経路 | エンドポイント | モデル指定 |
  |---|---|---|
  | 本家 | `POST https://api.typesafe.ai/v1/systemone` | `jev-1.13.0` |
  | OpenRouter | `POST https://openrouter.ai/api/alpha/decisions`（経路名がalpha） | `typesafe/jev-1.13`（日付付きスナップショットに解決される） |
  | Vercel | `POST https://ai-gateway.vercel.sh/typesafe/v1/systemone` | `typesafe-ai/jev`（版の固定は不明） |

- **1リクエストに複数の問い**: 1回の呼び出しで複数の問いを投げられる。
- **応答の形**: 応答は`answers.<問い名>`の下に入る。Noulは`{"type":"noul","noul":0.96}`、Choiceは`choice`・`confidence`・`probabilities`、Scoreは`score`・`confidence`・`probabilities`を返す。
- **苦手なこと**: Choiceは**先頭に並べた候補に寄りやすい**。指示を字義どおりに読む。**入力内の敵対的な文に誘導されうる**（プレスリリース・ニュースを入れるので、実際にリスクがある）。無関係な文が多いと精度が落ちる。実行のたびに結果がわずかに揺れる。
- **日本語での評価**: 日本語の公開ベンチマークはない。Zennの記事（2026-09-17）では、サイコロの目をChoiceで選ばせると「1」に約83%偏った。
- **規約**: 金融・投資目的での利用を禁じる条項はない。出力の権利は利用者に帰属し、保存してよい。禁止されているのは「出力を使って同じ振る舞いのモデルを学習させること」。入力は学習に使われないが、**テレメトリとしての利用権は事業者が持つ**。ゼロデータ保持は企業契約のみ（Cloudflare経由はゼロデータ保持をうたう）。OpenRouter経由にすると、処理者がもう1社増える。

### 2.3 精度に関する外部の証拠

- **独立評価1件**: 英語のフィッシングメール2,000件の判定で、Jevの正解率は62.6%、Claude Haiku 4.5は81.3%だった。較正誤差もJev 0.154、Haiku 0.097とJevが劣った。一方、費用は約12分の1、速度は約3倍。
- **日本語の開示・決算短信**: これらに対する評価は、公開されたものが1件も見つからなかった。**自分のデータで測る以外に判断材料がない**。

### 2.4 成熟度のリスク（Jev）

- **保証**: SLAなしで、「AS IS」での提供。
- **非推奨化・変更の通知**: 非推奨化の方針は公表されていない。規約は60日前の通知で変更できる。
- **すでに起きた破壊的変更**: v0.6.0でScoreの`criteria`がdictから配列に変わった。v0.7.0ではPython SDKの直列化ライブラリが変わった。
- **OpenRouterでの版固定**: 経路名がalphaで、日付付きスナップショットを直接指定できるかは確認できなかった。
- **対策**: 判定APIをインターフェースの裏に隠し、`model`の値と問いの版を設定で固定し、応答の形を検査して想定外なら「判定不能」として扱う。

### 3.2 既存の判定への合流の仕方（共通）

- **最終判断は既存のルール判定が持つ。** AIの判定は「注記」と「確認待ち行列」にだけ影響させ、区分の自動移動・売買判断の自動変更はしない。
- **3つの区分で扱う。**
  - 自動で注記を付ける
  - ログのみ
  - 週末の人手確認の行列に入れる
- **区分の分け方は型で異なる。**
  - **Noul**: confidenceを返さないので、**確率pだけ**で分ける。初期値の案は「0.8以上で注記、0.2以下でログのみ、その間は確認行列」。
  - **Choice・Score**: pとconfidenceの両方を使う。
  - 閾値はPoCで決める。
- **判断要因の表示**（`requirements.md` 6章「出力の主要因開示」、CHG-0002）: 確率だけでは、CHG-0002が避けた「何も分からないブラックボックス」に近い。そこで次の三つを表示する。
  1. 判定に使った**問いの文面と確率**
  2. **対象の開示**（タイトル・日付・リンク）
  3. **根拠となる箇所の抜粋**: キーワードが一致した文、またはHaikuを使う場合は該当箇所の引用。Jevは抜粋を返さないので、Jevの場合は切り出した段落の冒頭を出す
- **承認の扱い**: PoCのGO判定や閾値の承認は、**画面の変更の承認ではない**。シグナル画面に注記を出すなどのユーザー向けの変更は、段階1のGate 2で、画面の具体案を本人が承認してから行う（`.claude/rules/00-global.md`）。

### 3.3 投資仮説の自動生成（手入力の代わり）

本人は手入力の仮説登録を「運用しない」として却下した（2026-10-07）。代わりに、アプリがすでに持つデータから、型どおりの仮説をコードで作る。

| 仮説の型 | 作る根拠（既存データ） | 仮説の文面の例 |
|---|---|---|
| 成長 | 買付時点のシグナル・指標で、売上・利益の成長率が高い。使えるのは`signal_occurrences`の根拠値（2026-09-27から）と`indicator_observations`（2026-10-04から）。**CHG-0033の売買とシグナルの紐付け（`trade_context_records`）はまだ実装されていない**（2026-10-08確認） | 「売上と利益が高い成長を続ける」 |
| 割安 | `per_undervalued`などの割安系シグナル、業種相対PER（ADR-0026） | 「業績が維持され、割安が解消される」 |
| 株主還元 | 配当利回り・配当性向 | 「配当と株主還元が維持される」 |
| テーマ | ウォッチリストのフォルダ名（ADR-0013）、メガトレンド調査のテーマ（UC-016） | 「{テーマ}向けの需要が伸び続ける」 |

- **型の扱い**: 1銘柄に複数の型が当てはまってよい。問いは型ごとに1つずつ投げる（1つの問いでは1つの性質だけを聞く）。
- **根拠がない場合**: 根拠が見つからない銘柄（買付前の記録がない古い保有など）は、仮説なしで使える問い（Q10・Q3・Q7）だけを対象にする。
- **主観は推測しない**: 本人の主観的な理由は推測しない（F-017の方針と同じ）。画面では「アプリが推定した仮説」と明示する。

### 3.4 使わないこと

- 数値の閾値（含み益率・PER・成長率）
- 業績予想の修正前後の比較、修正の方向。XBRL・J-Quantsの数値で判定する
- 株価の方向や目標株価
- 日付の比較
- 複数の文書にまたがる集計
- 売買の最終判断
- 構造化データで取れる業種コード
- 文章の生成（週次レポートの文章化は、引き続き外部のLLMとメモ欄で行う）

## 4. コスト

### 4.1 API費用（月あたり、4.33週換算）

**件数の前提**: 東証の会社は年20〜40件の適時開示を出す（§5.3）。これに合わせて規模を見積もり直した。

| 規模 | 内容 | 判定件数/月 | 入力トークン/月 |
|---|---|---|---|
| A | 保有20銘柄の開示のみ（決算期を均して週15件×3,000トークン） | 約65 | 0.19M |
| B | Aに加えて、保有20銘柄のニュース見出し（週20件/銘柄×300トークン） | 約1,800 | 0.71M |
| C | 保有とウォッチリストの150銘柄、開示（週0.6件/銘柄×3,000）＋見出し（週10件/銘柄×300） | 約6,900 | 3.1M |

| 規模 | Jev 1問 | Jev 5問 | Haiku 1問 | Haiku 5問（1回でまとめて） |
|---|---|---|---|---|
| A | $0.01 | $0.04 | $0.21 | $0.27 |
| B | $0.03 | $0.15 | $1.16 | $2.96 |
| C | $0.13 | $0.66 | $4.84 | $11.7 |

- **Jevの前提**: 問いごとに文書全体が課金されると仮定した（安全側）。OpenRouterのクレジット購入手数料5.5%は含めていない。
- **Haikuの前提**: 入力$1/M、出力$5/M、1判定あたり出力50トークン。同じ文書に複数の問いを別々の呼び出しで投げる場合は、プロンプトキャッシュで入力費用を下げられる。
- **メモの見積もりとの違い**: メモの「10銘柄×記事20本/週」は、1銘柄あたり週20本の開示・記事という上限側の想定だった。実際の開示件数はそれよりずっと少ない。
- **結論**: 費用差は月数ドル〜十数ドルにとどまる。**どちらを選ぶかは、費用ではなく精度と事業者の安定性で決める**。

### 5.2 本文の切り出し

- **決算短信**: 期首が2024-04-01以降の期は、XBRLのzipに添付資料（目次以降）のHTMLが入っている。その中の「経営成績等の概況」「今後の見通し」を、見出しの正規表現で切り出す。タグはDOMDocumentで除去する。zip内のファイル名は、実物で確認する。
- **業績予想の修正**: 短いPDFなので、「修正の理由」の段落を切り出す。
- **PDFは予備に回す**: 日本語のPDFはCIDフォントで文字化けしやすく、表も崩れる。PHPなら`spatie/pdf-to-text`（popplerの`pdftotext`をSailのイメージに追加）、Pythonなら`PyMuPDF`を使う。
- **長さの上限**: 1件あたり約4kトークンに収める。経路の上限は32kで、無関係な文が多いと精度が落ちるため。
- **ダウンロード前の絞り込み**: タイトルの正規表現（決算短信・業績予想の修正・自己株式・第三者割当・合併/TOB・月次・訴訟・リコール）で選び、定型的な開示（コーポレートガバナンス報告書・株主総会の招集通知）は除外する。

### 5.3 量の目安（推定、未実測）

- **日本株**: 1社あたり年20〜40件の適時開示がある。20銘柄なら通常週5〜15件、決算期（次は10月下旬〜11月中旬）は週40〜80件。
- **トークン数**: 切り出し後は1件2〜6kトークン。業績予想の修正や自己株式取得なら1〜2kトークン。

### 5.4 時間の粒度

- **今の運用**: アプリは週次のCSV取込で動いており、週足は週の月曜で管理している。15時以降に出た開示への反応は、週足ではならされる。
- **できること・できないこと**: 「落ちるナイフ」の除外（Q10）は、買いシグナルの判定時（取込時）に、その時点までの直近の開示を見る形なら実装できる。開示の直後に通知する使い方は、スケジューラがないのでできない。
- **今回の扱い**: 定期実行の導入は本CRの対象外とする（必要なら別ADR）。

## 9. リスク

| リスク | 影響 | 対策 |
|---|---|---|
| 日本語での精度が足りない | 用途が成立しない | PoCで「日本語の問い」「英語の問い」「英訳した文書」を比較する。AIを使わない代替で足りる用途はAIを使わない |
