## UC-017: 週次売買履歴の取込と保有変化の照合

**Actor**: 本人。**関連**: F-017、UC-001（保有CSVの週次取込）。

**前提**: 国内株・米国株の全期間取引履歴CSVを楽天証券から出力済み。初回は履歴の存在期間だけを復元し、履歴開始前の保有は推測しない。

**入力**: 国内株履歴CSV、米国株履歴CSV、既存の週次保有スナップショット。両履歴CSVを同じ週の組として受け取る案。履歴が未提出の週も既存UC-001の保有CSV取込は継続し、本UCの照合は履歴待ちと表示する案。ファイル種別、文字コード、ヘッダー、日付、銘柄、口座、取引区分、数量、価格、決済通貨、受渡金額を検証する。資産残高CSVと特定口座損益CSVは入力必須にしない。

**基本フロー**:

1. 本人が2本の全期間履歴CSVを選び、取込前に対象期間と行数のプレビューを確認する。
2. システムが取引行を原文との対応を保って読み取り、買付・売付・入庫・出庫・積立・分割入庫に分類する。元ファイル内で内容が完全に同じ行が複数ある場合も、その出現回数を保持する。
3. 既存取引と、ファイルをまたぐ同一内容行の**出現回数**を照合する。再提出された全期間履歴を再登録せず、新規行と消失・変更した行を区別して取込プレビューに表示する。取引ID・時刻がないため、同一内容行が後から差し替わった疑いは本人の確認待ちにする。
4. 本人が取込を確定すると、取引履歴を保存し、同じ期間の週次保有CSVについて市場・銘柄・口座区分ごとの数量変化と照合する。初回より前や片方の履歴だけが存在する期間は、照合範囲を明記する。
5. 「照合済み」「保有側のみ変化」「履歴側のみ変化」「分割・移管等の確認待ち」の件数と明細を表示する。数量減少だけで売却を確定しない。

**出力**: 取込週、対象期間、総行数、新規／既存／確認待ちの行数、取引区分別件数、口座別の数量照合結果、未照合の理由。ファイル名・行番号は追跡に残すが、取引IDの代用として一意と断定しない。

**異常時**: ファイル形式違い・必須列欠落・数値／日付不正は確定前にエラーを表示する。片方の履歴CSVだけを提出した場合と過去行が消失・変更した場合は、黙って履歴を削除しない。数量不一致は取込を成功扱いで隠さず、照合結果に残す。分割入庫は買付費用と扱わない。

**状態変更・権限**: 本人のみが取込を確定できる。履歴の追加と照合結果の記録を行う。過去取引の削除・修正はこのUCの通常フローに含めず、差異を確認待ちとして残す。単なるプレビューは状態を変えない。

## UC-018: 売買の対ガチホ比較と状況の自動記録

**Actor**: 本人。**関連**: F-017、UC-014（既存の週足価格。シグナル結果とは別集計）。

**前提**: UC-017で履歴が取込済み。2026-10-04本人指示により、理由・判断区分・買付代替先の手入力は設けない。CSVの明示的な積立区分等から分類し、根拠がなければ「裁量性不明」とする。国内株の「単元未満」やシグナルとの一致だけで裁量／定型を断定しない。

**入力**: 全期間売買履歴、保有スナップショット、売買前に保存済みのシグナル・指標・市場状況。年率目標は20％、上位目標は25％（本人選択。2026-10-04に当初の25％／30％から引き下げ）。本人の通常作業は従来どおり週次CSV追加と取込確認のみ。理由記入・取引ごとのタグ選択・乗換え先の手動紐付けを要求しない。

**基本フロー**:

1. 取込確定後、システムが売買事実を照合し、売買前に利用可能だった記録を自動で紐付ける。「利確シグナル発生後の売却」等の観測条件を表示し、「利確シグナルを理由に売った」とは断定しない。
2. 売却では、売却数量を持ち続けた仮想評価額と、売却受渡代金を現金で保持した仮想額を、売却日から+4／+13／+26週で比較する。「売却単独・現金保持との比較」と明示し、本人の実際の資金運用全体の成果とは扱わない。
3. 資金の対応を根拠付きで復元できる場合は、乗換え先の保有評価額・残った現金・費用を含めた一連の売買と、元の保有継続を同じ期間・元本で比較する。対応不明なら「乗換え全体は算出不可」とし、売却単独の結果は引き続き表示する。
4. 買付は期間リターンと、JP=日経225／US=S&P500の同期間リターンとの差を自動表示する（円換算等の基準を揃える）。指数は銘柄選択の参考基準。本人が実際に選んだはずの代替先とは断定せず、その記録がなければ本人の代替運用との比較は算出不可とする。
5. 運用全体の年率20％／25％の達成度と、対ガチホ差分を別項目で表示する。データ不足なら全体の達成判定は保留し、計算可能な個別売買の実績・期間目標との比較は表示する。
6. 比較相手、対象資金・資産範囲、実績／仮想／対応不明、円建て差額・差率、起点日・評価日、価格／為替の出典、含めた費用、未反映項目を表示する。配当・外貨預り金の為替損益・金利・譲渡益税を未反映の結果は「価格・売買コストベース」と明示する。

### 年率目標と比較単位（2026-10-04 本人選択・詳細算出規則は草案）

- **運用全体の絶対リターン**は年率20％を目標、25％を上位目標とする。算出可能なら「20％未達」「20％達成・25％未達」「25％達成」の3区分。対ガチホ差分が正か負かは別に表示し、年率目標をシグナル閾値や売買指示に転用しない。
- 全体の評価窓は直近1年を案とする。開始・終了の全保有と現金、途中の外部入出金、必要な評価額が揃う範囲で入出金の影響を除いた運用リターンを算出する。算出方法・評価時点はGate 3で確定する。投信等を欠く国内・米国株だけの結果はその範囲を明示し、全資産の年率と呼ばない。
- 現状の売買・保有CSVだけでは、全資産の現金・入出金・配当等を網羅できない。資産増加や売却利益の合計だけで年率を出さず、不足時は全体の「目標達成」を判定保留にする。追加CSVや理由入力を今回の週次運用の必須条件にはしない。
- 個別売買や一連の売買では、元本 `C > 0`、評価額 `V`、経過日数 `d > 0` が確認でき、期間中の追加投入・引出しがない場合に `V / C − 1` を表示する。途中の資金移動があればこの単純式を使わず、対応が復元できる範囲で別計算するか算出不可とする。
- 短い期間は年率20％・25％をそのまま当てず、期間目標 `T(g,d) = (1 + g)^(d/365) − 1`（`g=0.20 / 0.25`）との比較を参考表示する。「期間目標到達」であり、「年間20％を達成」とは表示しない。売却単独の差額は元本運用のリターンではないため、この期間目標を適用しない。
- 1年の実績22％、同じ資金・期間のガチホ30％なら「20％目標達成・25％未達、対ガチホ−8ポイント」。目標未達／達成と判断効果を一つの成功／失敗ラベルにまとめない。

### 乗換えの対応と二重集計の防止

- 売却・再購入の日付や金額が近いだけでは資金の対応を確定できない。現状CSVに資金の紐付け情報がなければ対応不明を維持し、手入力で埋めさせない。仮定による配分を後で導入する場合も参考シミュレーションとし、実績の乗換え評価から分ける。
- 対応が確認できた資金は起点・元本と配分先を一つの評価単位として管理し、分割購入では配分額＋残金が利用可能資金を超えないことを照合する。新規入金は元の売却資金と混ぜず、通貨変換・費用も対応が分かる範囲だけ反映する。
- 一連の売買の評価額は、評価時点の残存保有＋その資金に属する現金で求める。途中の売却代金を、その後の購入先の評価額に重ねて加えない。一連の売買を集計する場合、その内訳である売却単独・購入単独の差額や元本は合算しない。対応不明の単独売買も全体合計に足さない。
- +4／+13／+26週はそれぞれ別の評価断面とし、3期間の結果を合計しない。同じ資金が重なる評価単位を全体実績に二重計上せず、全体は資産・現金・外部資金移動から直接算出する。
- 計算例（架空、費用0、同一評価日）: 元の株を100万円で売り、保有継続なら90万円、再投資先が80万円なら、売却単独の差は+10万円、一連の売買は対ガチホ−10万円、元本に対する実績は−20％。+10万円を乗換え成果へ足して相殺しない。

### 手入力なしの状況記録

- 既存の `signal_occurrences.metrics` 等の保存済み記録を優先して再利用する。シグナル・RSI・相対力・業績指標・保有期間・配分等は、履歴が存在する項目だけ自動付与する。シグナルが出なかった週の指標や上書きキャッシュしかない項目を将来も残すための自動スナップショットはGate 3で設計する。
- 自動記録には元データへの参照、観測対象日、システムが利用可能になった日時、売買日からの経過、適用ルールを残す。週足のラベル日だけで売買前と判断しない。約定時刻がないCSVでは、約定日の開始より前に利用可能だった最新の記録に限り、同日取得や翌週取込の指標を売買前の根拠にしない。
- 当時保存した記録がない・更新間隔が空き過ぎている・後日移送で時点を保証できない場合は「当時の状況不明」。有効とする経過日数はGate 2で固定する。「シグナルなし」と「記録なし」は区別し、最新指標や後日の株価で理由を補作しない。
- 主観的な理由や代替先は自動推定で確定しない。既存メモ等を将来使う場合も出典・作成日時の条件を満たす資料だけとし、手動転記や毎取引の確認操作を必要にしない。初期段階ではAIによる理由生成を前提にしない。

**算出ルールの境界**: 分割は売却数量と分割調整済み週足の基準を合わせる。米国株は実際と仮想の双方を同じ換算規則で円建て比較する。決済通貨が円／ドルのどちらかも示す。週足の評価日と、約定日・約定価格の差は表示する。非保有・非ウォッチリスト銘柄の価格は下記の共通追跡で供給する。具体的な価格出典、端数、売却日の週への対応、売却代金の換算方法は Gate 3 で確定する。

### UC-014と共用する株価追跡（2026-10-04 本人追加指示）

- 対象は売却後+26週までの銘柄と、`signal_occurrences` に直近26週以内の発生記録がある銘柄の和集合。シグナルは全種別を対象とし、起点は登録日時ではなく `observed_week`。シグナルのみの対象はUC-017の取引履歴取込を前提としない。
- 銘柄ごとに「最終売却+26週」と「最後のシグナル発生+26週」の遅いほうまで追跡する。片方がなければ他方を使う。新しい売却・シグナルで期限を延長する。例: 第0週に売却、第3週にシグナルが出た銘柄は第29週の終点まで追跡する。
- 終点週の途中で取得を打ち切らない。直近26週の抽出条件から外れた後も、終点週の確定後の取得・保存が完了するまで対象を保持する。失敗を正常完了と扱わず、再試行と上場廃止等の取得不能理由を記録する。保持・再試行の具体的な保存設計は Gate 3 で確定する。
- 既存の株価取得経路と `WeeklyPriceRecorder::recordHolding` を再利用し、週1回、104週分を `weekly_prices` にUPSERTする。同じ銘柄を売却・シグナル・保有・ウォッチリストの各経路で重複取得しない。追跡だけの銘柄ではシグナル判定・発生記録を新たに実行しない。
- UC-014は同テーブルを読み直すため、起点・終点の株価と指数が揃えば既存処理で再計算できる見込み。確定済み期間の価格欠損は現行どおり「算出不可」とし、判定ロジック・画面・閾値は変えない。指数更新は既存の `index_weekly_prices` 保存経路と整合させる。詳細・取得量・ADR-0017 D2改訂は [ADR-0024](../adr/ADR-0024-trade-and-signal-price-tracking.md) を参照。

### UC-018の異常時・権限

**異常時**: 評価日未到来は「結果待ち」。売却後価格欠損、上場廃止、ティッカー変更、分割情報欠損、為替欠損、取引照合未解決は理由付きの「算出不可」。欠損を0円・0%にしない。価格取得失敗で既存保有分析を止めない。理由や裁量性が不明でも価格比較は表示できる。自動記録条件の集計では「裁量性不明」の区分を維持し、裁量判断の確定例と混ぜない。

**状態変更・権限**: 本人のみ閲覧でき、取込・自動更新に伴い状況記録と対応根拠を保存する。理由・区分・代替先の入力画面は設けない。CSV再取込やルール変更時は元記録と版を追跡し、過去の状況を最新値で上書きしない。具体的な保存形式はGate 3で決める。

## UC-019: 売買時の自動記録条件別の結果閲覧

**Actor**: 本人。**関連**: F-017、UC-018。

**入力**: 市場、売買方向、自動記録したシグナル・指標・保有状況、裁量／定型／不明、評価期間（+4／+13／+26週）の絞り込み。本人による理由・タグの入力は不要。自由に試す探索フィルタと、事前固定する分析条件を区別する。

**基本フロー**:

1. 本人が判断の一覧を開くと、裁量判断・定型積立・不明の件数、比較可能・結果待ち・算出不可の件数を確認する。
2. 自動記録条件・市場・評価期間ごとの対ガチホ差の件数、中央値、分布、期間目標への到達状況と個別売買へのリンクを表示する。裁量性不明の取引も別区分で探索できる。定型・不明を裁量判断の確定例の分母に混ぜず、条件欠損の件数も表示する。「本人の理由別」とは呼ばない。
3. 同日分割約定、評価期間が重なる同一銘柄の売買、同じ資金の乗換えは独立件数として水増しせずクラスタ単位で表示する。主観的な同一仮説を推測して束ねない。クラスタの束ね方と重なりの表示は Gate 2 でレビューする。
4. 初期段階では「探索的結果」と明記する。成功法則・自動売買ルールは表示・生成しない。仮説を判定する将来段階の最低条件候補は、評価済みクラスタ30件以上、3つ以上の暦年、条件の事前固定、別期間での前向き検証であり、件数だけ満たしても成功確定とはしない。UC-014のt値・`suspicious`判定は転用しない。

**出力**: 条件、評価対象と除外対象、観測期間、独立クラスタ数、結果待ち数、算出不可数、差分の分布、価格・為替・費用の扱い。全資産の厳密な対ガチホ差は、開始時の全保有・現金と外部資金移動等が揃う期間だけ別枠で扱い、現段階の画面では欠ける期間を算出不可とする。

**異常時**: 対象0件は空状態、結果待ちのみ／算出不可のみはその内訳を表示する。少数や特定年に偏る結果は「判断保留」とし、プラスの平均だけで有利と断定しない。

**状態変更・権限**: 本人のみ閲覧できる。探索フィルタは閲覧のみ。分析条件はシステム側で定義・版管理し、取引ごとの手入力フローを設けない。仮説検証に進む際は条件を将来の評価期間より前に固定する。

## Gate 2 レビューで確定する点

1. 週次アップロードは既存UC-001からリンクする履歴専用入口とし、履歴未提出でも保有CSV取込は続ける案でよいか。
2. 過去行の消失・変更時の確認方法、自動記録する条件と有効期間、当時の記録がない場合の表示、元データと再処理の版管理。理由・タグの手入力は本人指示により設けない。
3. 年率20％目標・25％上位目標は本人選択済み。全体の算出可能範囲、短期の期間目標表示、売却単独／乗換え全体／二重集計防止の規則を上記の案でレビューする。価格・為替・分割情報の欠損時は計算可能な期間だけ表示する。
4. 判断クラスタの定義と、30件／3暦年の最低条件を将来の仮説判定に採用するか。初期画面には探索的結果だけを載せる。
5. 新しい画面の配置・入力・表示をUC本文で確認する。モック作成・レビューは今回の本人指示により省略し、UC本文と具体的な計算例のレビュー結果を正本 `use-cases.md` に反映してから Gate 2 の最終承認を受ける。モックの省略はGate 2〜4の承認を意味しない。
