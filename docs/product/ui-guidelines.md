## レイアウト原則

- **グリッド**: 8px基準グリッド（個人利用の管理画面のため厳密な12カラムは採用しない）
- **利用環境**: 本人1人がPCブラウザから利用する想定。デスクトップ表示を優先し、モバイル対応は必須としない
- **ブレークポイント**:
  - Mobile: `< 768px`（レイアウト崩れ防止の最低限対応のみ）
  - Tablet: `768px〜1024px`
  - Desktop: `> 1024px`（主要ターゲット）
- **コンテナ最大幅**: `1200px`
- **標準余白**: `8px / 16px / 24px / 32px`

## ナビゲーション方針

- 個人利用の単一Actor向けツールのため、グローバルナビゲーション（タブ）の数は5〜6個程度を上限の目安とし、機能追加のたびに安易にタブを増やさない
- 目的が近い機能（例: システムが提案する候補一覧と、本人が個別銘柄を手動で調べる画面）は、可能な限り1つの画面・1つのメニュー項目に統合する（セクション分けで対応する）
  - 例: 新規投資候補レコメンド（F-008・システム主導の提案）と新規投資候補の重複チェック（F-006・本人主導の個別確認）は「新規投資候補」という1つの画面に統合し、上部セクション（おすすめ候補）→下部セクション（個別チェック）の流れで1つのタブから両方にアクセスできるようにする
- 逆に、目的が異なる一覧（例: 保有銘柄の全体把握=UC-002 と、利確アクションに絞った一覧=UC-004）は無理に統合せず、別画面として維持する
- 現在のグローバルナビゲーション構成（6タブ）: 保有一覧（UC-002、UC-007の市場全体指標ウィジェットを内包）／売買シグナル（UC-004・UC-010を統合）／セクター配分（UC-005）／新規投資候補（UC-006・UC-008を統合）／CSV取込（UC-001）／サマリーレポート（UC-009）。銘柄詳細（UC-003）は一覧からのクリック遷移のみで、ナビゲーションタブは持たない
  - 売買シグナルタブは、上部セクション（買い増し候補＝UC-010）→下部セクション（利確検討＝UC-004）の流れで1つのタブから両方にアクセスできるようにする（2026-08-23、ADR-0007。UC-006・UC-008統合と同じパターン）
  - サマリーレポートタブ（2026-09-05、CHG-0008）は既存タブ群の右端・CSV取込の直後に配置する。取込完了直後の自動遷移（UC-009フロー1〜6）とは別に、いつでも最新の取込バッチのレポートを再表示できる恒常的な導線として追加した。上限目安「5〜6個程度」の範囲内（6タブ目）

## コンポーネント方針

### ボタン
- Primary: メインアクション（1画面に1つまで）
- Secondary: サブアクション
- Danger: 削除・取り消し（確認ダイアログを必ず挟む）
- Ghost: ナビゲーション系

### モーダル
- 利用シーン: 確認ダイアログ・簡易フォーム入力
- 全画面遷移が必要な複雑操作にはモーダルを使わない
- モーダル内にモーダルを重ねない

### テーブル
- ページネーション: [例: 20件/ページ]
- ソート可能カラムには矢印アイコンを表示
- 空状態（0件）には必ずメッセージを表示
- 一覧に複数指標を圧縮表示する場合（例: 保有銘柄一覧の「主要指標」列）は、カテゴリごとの代表指標1つのみ（例: テクニカル→RSI、ファンダメンタルズ→PER、会社業績→売上高成長率）を小さなバッジ（`font-size: 11px`程度）で並べる。全項目の確認は詳細画面への遷移に委ね、一覧側では情報過多にしない
- シグナル・レコメンド系の一覧（利確シグナル一覧・セクターリバランス・新規投資候補レコメンド等）では、技術的なバッジ（RSI高値反落等）だけで終わらせず、その下に平易な言葉の判定根拠サマリを1〜2文で併記する（`font-size: 13px`程度、本文と同トーン）。判定の全背景・関連する全指標の内訳は一覧に出さず、行をクリックした先の詳細画面に集約する
  - **例外（2026-08-29、CHG-0007）**: 「基準点」と「その銘柄の実測値」「達成状態」をセットで示す判定チェックリスト（売買シグナル画面の`criteria`）は、基準との距離を数値で読ませることに意味があるため一覧に出してよい。ただし出すのは判定に直接使う項目に限り、個別指標の時系列・計算根拠の詳細は引き続き詳細画面に集約する
- 配分比率など「目安に対する現在地」を示す進捗バー（例: セクター配分ダッシュボード）は、バーの塗りに加えて目安ライン（縦線マーカー、`.sector-bar-target`）を重ねて表示し、目安との位置関係が一目でわかるようにする
- 1行に複数指標・複数バッジ・複数行テキストを詰め込む一覧（例: 売買シグナル画面の買い増し候補／利確検討テーブル）は、行の下線だけでなく**セルの縦罫線（グリッド線、`border-app-border`）**を引き、セル内容は `align-top` で上揃えにして列の対応関係を追いやすくする
- **シグナルバッジの色分け**（売買シグナル画面ほか、シグナル種別を並べる箇所）: 「買い（押し目・買い増し）系シグナル」は Success（緑, `variant="success"`）、「利確・警戒系シグナル」は Warning（琥珀, `variant="warning"`）で表示し、注目すべき良いシグナルと警戒シグナルを色で即座に区別できるようにする。中立的な補助情報（財務指標取得不可など）は neutral のまま
- **判定チェックリストのチップ**（売買シグナル画面の`criteria`、CHG-0007）: 1項目 = 1チップとし、チップ内に「項目名」「実測値」「基準ラベル（例: `≥70`）」を縦積みする。達成状態で塗り分ける — 達成: `bg-green-100 text-green-800`（`badge success`と同系）／あと一歩: `bg-green-50 text-green-700`（達成より淡い緑で「見づらくなりすぎない」程度に留める）／未達: `bg-slate-50 text-slate-500`／データなし: `bg-slate-50 text-slate-400`（実測値は「—」）
  - **配置（2026-09-05、CHG-0007実装中のレビューフィードバックで確定）**: 当初案（銘柄行直下のフル幅サブ行に1個の判定チェックリストパネルとして置く）は1銘柄=2行になり視認・スキャンしづらく、パネルを銘柄行の末尾に1列で集約する中間案もチップの折返し位置が銘柄ごとにずれて見づらかったため、最終的に**チップ1項目=テーブル1列**に分解する形で確定。ヘッダーは2段構成にし、1段目を「判定チェックリスト（テクニカル）」「判定チェックリスト（財務）」の`colspan`グループ見出し、2段目を各項目のラベル（RSI・PEGレシオ等）とする。1銘柄=1行を維持し、行が横に大きく伸びる分はテーブルを`overflow-x-auto`でラップして横スクロールを許容する
  - 技術群・財務群それぞれの項目構成は`SignalCriteriaEvaluator`の`evaluateBuy`/`evaluateTakeProfit`が銘柄によらず固定順・固定件数で返す前提に依存する（項目を可変にする場合は本レイアウトごと見直しが必要）
  - **達成数サマリの復活（2026-09-05、追加のユーザーフィードバックで再確定）**: 上記で「列見出しと冗長」として一度省略した「◯/N 達成」テキストサマリだが、判定チェックリスト列を横スクロールすると個々のチップの色分けが見えなくなり達成状況を把握できないとの指摘を受け、`x-signal-criteria-summary-badges`として復活。設置場所は列見出し直下ではなく、横スクロールしても常に見える**銘柄セル（sticky left-0）内、銘柄名の直下**（例:「技術 3/7」「財務 2/3」の2行）。達成率に応じて簡易に色分け（全達成=緑`text-green-700`／0件=グレー`text-slate-400`／それ以外=`text-amber-600`）し、チップの個別配色とは独立した一覧性優先の簡易表示と位置づける。値は`criteria.summary`（Action側で計算済み）をそのまま使う
  - **表の共通化・固定表示・縮小（2026-09-05、ユーザーフィードバックで追加確定）**: 利確検討・買い増し候補の2表は列数・列順は同じだが内容が異なる列（財務健全性／理由サマリ等）があり、個別にBladeを書くと対応列の実測幅が表ごとにずれて「フォーマットが統一されていない」ように見えていた。対処として、`<colgroup>`（`x-signal-table-colgroup`）・2段ヘッダー（`x-signal-table-head`）・判定チェックリストの`<td>`群（`x-signal-criteria-cells`）を共通Bladeコンポーネント化し、両表が同一の列幅定義を共有する形に統一。テーブルは`table-fixed`とし、`colgroup`で指定した幅を内容量に関わらず両表で完全に一致させる
    - **固定表示**: `<thead>`に`sticky top-0 z-20 bg-surface`を付与し縦スクロール時もヘッダーが常に見える状態にする。先頭列（銘柄）はヘッダー・本文セルとも`sticky left-0 z-10〜20 bg-surface`を付与し、判定チェックリスト列側へ横スクロールしても銘柄名が見える状態を維持する（ヘッダーの銘柄セルはヘッダー行・固定列の交点になるため`z-20`でどちらの固定要素より前面に出す）
    - **サイズ縮小**: 表全体のフォントサイズを`text-[13px]`→`text-[11px]`、セルのpaddingを`py-2 px-2`→`py-1.5 px-1.5`、判定チェックリストのチップ（`criteria-chip`）も`min-w-[88px]`固定幅をやめてセル幅（`colgroup`側の`w-[72px]`）に追従させ、内部フォントも1段階小さくした。列幅を固定した都合上、`[&_td]:break-words`を表全体に適用し、長いシグナル種別名（`peg_undervalued`等）がセル幅を超えて隣列に重ならないようにしている
    - **固定表示が効かない不具合と最終的な構造変更（2026-09-05、3段階で判明）**: 当初`<table>`1個を`overflow-x-auto`のdivでラップし、その中の`<thead>`に`sticky top-0`を付ける実装は実ブラウザで機能しなかった。`overflow-y-hidden`→`overflow-y-clip`と2回対処を試みたが、いずれも「`overflow-x-auto`な要素は`overflow-y`をどんな値にしてもそれ自体がスクロールコンテナになり、子孫の`sticky`の基準がページ本体ではなくこのdivになってしまう」という同じ問題を解消できなかった（`clip`は一見別物だが`overflow-x: auto`と組み合わせると`hidden`に補正されてしまう、というCSS仕様の詳細。詳しくは`docs/ai-context/known-pitfalls.md`「CSS `overflow-x: auto` + `position: sticky`」参照）。実際にPlaywrightで実ブラウザを操作して`getBoundingClientRect()`を計測するまでこの原因を確定できなかった
    - **最終的な構造**: 1個の`<table>`に固執するのをやめ、**ヘッダー用（`<colgroup>`+`<thead>`のみ）と本文用（`<colgroup>`+`<tbody>`のみ）で`<table>`を2つに分割**した。ヘッダー用`<table>`を包むdiv自身に`overflow-x-auto`と`sticky top-0`の両方を付与する（`sticky`は「このdivの祖先」を基準に解決されるため、div自身がoverflow-x-autoでスクロールコンテナになっていることとは無関係にページ本体への固定が効く）。本文用`<table>`は別の`overflow-x-auto`なdivに入れ`sticky`は付けない。2つのdivは横スクロール位置が独立してしまうため、本文側の`scroll`イベントでヘッダー側の`scrollLeft`を同期する数行のJS（`resources/js/app.js`、`data-scroll-sync-with="<ヘッダーdivのid>"`属性で対象を指定、`livewire:navigated`で初期化）を追加した。ヘッダー用の横スクロールバーは本文側と二重に見えるため`[scrollbar-width:none]`等で視覚的に隠している。この構造により、表が2つ縦に並んでいても各表が自分のヘッダーをページスクロールに対して独立にstickyさせ、1つ目の表を過ぎると自然に2つ目の表のヘッダーへ固定が引き継がれる（実ブラウザのスクリーンショットで確認済み）
    - **付随して修正した2つの不具合**: (1) `table-fixed`に`w-max`（`width: max-content`）を組み合わせると、折り返せない長いラベル（`52週安値からの距離`等）を持つ列だけ`<colgroup>`の指定幅を無視して広がり、ヘッダー用・本文用の実際の描画幅が食い違っていた。テーブルの`width`を`<colgroup>`合計値と一致する具体的なpx値（`w-[1296px]`）に変更し、ヘッダー側の`whitespace-nowrap`も`break-words`に統一して解消。(2) `<x-badge>`（`inline-block`）内の折り返せない1単語のシグナル種別名（`week52_high_pullback`等）が、親セルの`break-words`だけでは折り返されずセル幅を超えて隣接要素と重なって表示されていた。`badge.blade.php`自体に`max-w-full break-words`を追加し解消（詳細双方とも`known-pitfalls.md`参照）

## モック作成ルール（AI向け）

AIがモックを生成する際の指示：

1. このファイル（`ui-guidelines.md`）を読んでからHTMLを生成する
2. 対応するUC番号をファイル名に含める（例: `screen-UC006-filter.html`）
3. `docs/product/mockups/` に配置する
4. `docs/product/mockups/README.md` の画面一覧に追記する
5. 実データは使わず、ダミーデータで描画する
6. インタラクションは不要（静的HTMLで可）

### モック生成プロンプトテンプレート

```
docs/product/use-cases.md の [UC-XXX] と docs/product/ui-guidelines.md を読み、
[画面名]のHTMLモックを docs/product/mockups/screen-[UC-XXX]-[screen-name].html として生成してください。
実データは不要です。ダミーデータを使用してください。
```
