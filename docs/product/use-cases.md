### UC-001: CSV取込

**Actor**: 本人
**前提条件**: 楽天証券から国内株式CSV・米国株式CSVをダウンロード済み（両方必須）。投資信託CSVは任意でダウンロード済み
**関連要件**: F-001

#### 基本フロー
1. 本人がCSV取込画面で国内株式CSV・米国株式CSVを選択し（必須）、任意で投資信託CSVも選択してアップロードする
2. システムがCSVの種別（JP株/US株/投資信託）を判定する
3. システムがCSVをパースし、保有銘柄・数量・取得価格を抽出する
4. システムが取込結果を新しい週次スナップショットとして保存する（既存スナップショットは上書きせず、履歴として蓄積する）
5. システムが今回のスナップショットを直前の週次スナップショットと比較し、直前スナップショットに存在しなかった銘柄（銘柄コード＋市場区分の組み合わせ）を「新規検出銘柄」として記録する
6. システムが取込結果（成功件数・エラー件数・新規検出銘柄数）を表示する
7. システムが今回の取込バッチに含まれる銘柄（JP株・US株の個別株のみ、ADR-0004）について、外部データを同期的に取得し、テクニカル指標（RSI・MACD・ボリンジャーバンド・移動平均線・出来高・52週高値/安値・相対力）・ファンダメンタルズ指標（PER・PBR・ROE・売上高/営業利益成長率・自己資本比率・営業利益率・配当利回り/性向・EPS成長率・PEGレシオ）を計算し保存する。データソースはJP株がJ-Quants・Yahoo Finance相当、US株はYahoo Finance相当（株価）・Finnhub（ファンダメンタルズ指標、ADR-0009）を用いる。あわせて市場全体指標（日経平均・S&P500等）の週次スナップショットを取得・保存する（相対力〔対市場〕の算出に使用。F-007ダッシュボード画面自体はPhase2）
8. システムが上記指標をもとに利確シグナル（UC-004）を判定し保存する
9. システムが上記指標をもとに買い増しシグナル（UC-010）を判定し保存する。利確シグナル（フロー8）とは判定対象・保存先ともに独立しており、含み益率による対象銘柄の絞り込みは行わない（ADR-0007）
10. システムが取込完了と同時に取込後サマリーレポート（UC-009）を自動生成し表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| jp_stock_file | ファイル（CSV） | 必須 | 拡張子`.csv`、Shift-JISエンコード、最大サイズ5MB |
| us_stock_file | ファイル（CSV） | 必須 | 拡張子`.csv`、Shift-JISエンコード、最大サイズ5MB |
| mutual_fund_file | ファイル（CSV） | 任意 | 拡張子`.csv`、Shift-JISエンコード、最大サイズ5MB |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| import_batch_id | int | 取込バッチのID |
| status | string | `pending` / `processing` / `completed` / `failed`（`glossary.md`参照） |
| imported_count | int | 正常に取り込んだ銘柄数 |
| error_count | int | スキップした行数 |
| imported_at | datetime | 取込日時 |
| newly_detected_symbols | array<string> | 新規検出銘柄（銘柄コード＋市場区分）のリスト。保有銘柄一覧（UC-002）のNEWバッジ表示、および新規投資候補の重複チェック（UC-006）への自動遷移に用いる |

#### 業務ルール
- 国内株式CSV・米国株式CSVは両方揃って初めて取込を実行できる。どちらか一方のみアップロードされた場合は取込を実行せずエラーとする（投資信託CSVはこの必須条件に含まれない）
- 数値項目（数量・単価等）はカンマ区切り・クォート付き文字列として解釈し数値に変換する
- CSV内の個別行がパースできない場合、その行はスキップしてエラー件数に計上し、他の行の取込は継続する
- ファイル全体が読み込めない（文字コード不正・フォーマット全体が想定外）場合は取込全体を失敗とする
- 同一銘柄が複数のCSV種別（JP株/US株/投信）にまたがる場合、種別ごとに別レコードとして扱う
- 新規検出銘柄の判定は直前1回分の週次スナップショットとの比較のみで行う（それ以前の履歴は参照しない）。銘柄コード＋市場区分が完全一致する場合は「既存」とみなす
- 初回取込（比較対象となる直前スナップショットが存在しない）の場合は、判定基準がないため全銘柄を「新規検出銘柄」として扱わない
- 新規検出銘柄フラグは当該スナップショットが「直近」である間のみ有効とする（次回取込で新しいスナップショットが最新になった時点で、前回の新規検出銘柄フラグは表示上の意味を持たなくなる）
- 楽天証券のJP株/US株CSVはファイル内が口座区分（特定口座/一般口座/NISA成長投資枠等）ごとに複数セクションへ分かれている。投資信託CSVはセクション分割ではなく行ごとの`口座区分`列（値: `特定`/`NISAつみたて投資枠`等）で口座区分を表す。同一銘柄が複数の口座区分にまたがる場合、従来通り銘柄コード単位で保有数量を合算し、取得単価は加重平均で算出したうえでスナップショット（`holding_snapshots`）に保存する。加えて、口座区分ごとの内訳（数量・取得単価）を`holding_snapshot_accounts`に追記保存する（ADR-0002）。この内訳は利確シグナル一覧（UC-004）・セクター配分ダッシュボード（UC-005）でNISA区分（NISA成長投資枠/NISAつみたて投資枠）を除外する判定に使用する
- US株はCSVヘッダーに記載された参考為替レート（例: 159.32円/USD）を用いて取込時に円換算し、円建ての評価額・評価損益をスナップショットに保存する
- 銘柄の識別は「銘柄コード（JP株の証券コード／US株のティッカー／投資信託のファンド名）」+「市場区分（JP/US/投信）」の組み合わせで一意に扱う
- 外部データ取得（フロー7〜9、ADR-0004/ADR-0007）は個別銘柄単位で行い、特定銘柄の取得に失敗しても取込全体は失敗させない。失敗した銘柄は該当指標が`null`（「取得不可」）のまま保存し、取込結果（フロー6）自体は継続する（UC-003エラーケース「指標計算に必要な外部データが取得できない」と同じ扱い）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| ファイル未選択 | 422 | CSVファイルを選択してください |
| 国内株式CSV・米国株式CSVのいずれか一方のみアップロード | 422 | 国内株式・米国株式のCSVは両方アップロードしてください |
| 拡張子が`.csv`以外 | 422 | CSVファイルのみアップロードできます |
| ファイルサイズ超過 | 413 | ファイルサイズが上限（5MB）を超えています |
| ファイル全体がパース不能 | 422 | CSVの形式を確認してください（文字コード・列構成が想定と異なる可能性があります） |

#### 権限
- 本人: 実行可（他Actorなし）

### UC-002: 保有銘柄一覧表示

**Actor**: 本人
**前提条件**: 直近のCSV取込（UC-001）が1回以上完了している
**関連要件**: F-002

#### 基本フロー
1. 本人が保有銘柄一覧画面にアクセスする
2. システムが直近の週次スナップショットの保有銘柄を一覧表示する
3. システムが各銘柄の含み益率・利確シグナル有無を一覧内に表示する
4. システムが直近のCSV取込（UC-001）で新規検出された銘柄に「NEW」バッジを表示する
5. 本人が任意の銘柄（NEWバッジ部分を除く）を選択すると銘柄詳細（UC-003）に遷移する
6. 本人がNEWバッジを選択すると、対象銘柄コードが入力された状態で新規投資候補の重複チェック（UC-006）に遷移する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| sector（フィルタ） | string | 任意 | 既存セクター分類のいずれか |
| signal_only（フィルタ） | boolean | 任意 | シグナル発生銘柄のみ表示 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| symbol_code | string | 銘柄コード |
| symbol_name | string | 銘柄名 |
| market | string | 市場区分（JP/US/投信） |
| instrument_type | string | 銘柄種別（個別株/ETF/投資信託） |
| quantity | decimal | 保有数量（複数口座区分にまたがる場合は合算値） |
| average_cost | decimal | 取得単価（複数口座区分にまたがる場合は加重平均） |
| current_price | decimal | 現在値（投資信託は基準価額） |
| unrealized_gain_rate | decimal | 含み益率（%） |
| sector | string | セクター分類（未分類含む） |
| has_signal | boolean | 利確シグナル有無 |
| rsi | decimal | RSI（14期間）。テクニカル指標の代表値として一覧に簡易表示する |
| per | decimal | PER。ファンダメンタルズ指標の代表値として一覧に簡易表示する |
| per_verdict | object / null | PERの業種基準値との比較結果（`tier`／`ratio`／`benchmark`／`confidence`）。`tier`は`strong_cheap`＝強い割安／`cheap`＝割安／`fair`＝並み／`expensive`＝割高／`strong_expensive`＝強い割高。判定を付けない場合は null（CHG-0034、ADR-0023） |
| revenue_growth | decimal | 売上高成長率（%、前年同期比）。会社業績の代表値として一覧に簡易表示する |
| is_newly_detected | boolean | 直近のCSV取込（UC-001）で新規検出された銘柄かどうか（NEWバッジ表示に使用） |

#### 業務ルール
- 直近の週次スナップショットのみを表示対象とする（過去スナップショットの閲覧は本フェーズの対象外）
- 利確シグナルが立っている銘柄は一覧上で視覚的に強調表示する
- テクニカル/ファンダメンタルズ指標の計算・利確シグナル判定（UC-003/UC-004）はJP株・US株の個別株のみを対象とする。ETF・投資信託は一覧には表示するが、`has_signal`は常にfalse、指標欄（`rsi`/`per`/`revenue_growth`含む）は「対象外」として扱う
- 一覧では情報過多を避けるため、テクニカル・ファンダメンタルズ・会社業績それぞれの代表指標1つずつ（RSI・PER・売上高成長率）のみを小さなバッジ形式で表示する。指標の全項目（MACD・ボリンジャーバンド・ROE等）は表示せず、銘柄詳細（UC-003）への遷移で確認する構成とする
- **「売上成長」バッジの二段階の色付け（CHG-0034、ADR-0023 D9。2026-10-03 Gate 2 承認）**: 売上成長率に、UC-003と同じライン（強い良好は日本株15%以上・米国株25%以上、良好0%超、基準未満−10%以上0%以下、−10%未満は大きく下回る）で色とラベルを付ける。null のときは従来どおりバッジを出さない。色付けのみで判定には使わない。出力に`revenue_growth_tone`（UC-003の`metric_tones`と同じ段階、判定なしは null）を加える
- **PERバッジの割安・割高の色付け（CHG-0034、ADR-0023。2026-10-03 Gate 2 承認）**: PERバッジに、業種の基準PERとの比率（実際のPER ÷ 基準PER）に応じた色とラベルを付ける。段階と色は、強い割安（比率0.50未満、濃い緑）／割安（0.50以上0.80未満、緑）／並み（0.80以上1.25以下、色なし）／割高（1.25超2.00以下、黄）／強い割高（2.00超、濃いオレンジ）。境界値は穏やかな側に含める。PER・PBRの値は表示と同じ桁（小数1桁）、比率は小数2桁に丸めてから判定する（基準値は表の桁のまま使う。PERは小数1桁、PBRは小数2桁）。濃い色は基準値の信頼度が高い業種にだけ付け、信頼度が低い業種は通常の色までにする。**色付けのみで、財務健全性・利確シグナル・買い増しシグナルの判定には使わない**。基準値は日本株がJPX月次統計（東証17業種）、米国株がDamodaranとSPDR ETFの平均で、値・出典・信頼度は`docs/product/valuation-benchmarks.md`が正本。PERが null・0以下、業種が未分類・基準表にない、基準値の信頼度が`none`のときは判定を付けず従来どおりの無色のバッジにする。色だけでなくラベルの文字も添える
- `is_newly_detected=true`の銘柄は一覧上で「NEW」バッジを表示する。バッジのクリックのみ新規投資候補の重複チェック（UC-006）へ遷移し、行のその他の部分のクリックは従来通り銘柄詳細（UC-003）へ遷移する

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 取込データが1件も存在しない | - | 空状態として「CSV取込が必要です」を表示し、UC-001への導線を示す |

#### 権限
- 本人: 実行可（他Actorなし）

### UC-003: 銘柄詳細表示

**Actor**: 本人
**前提条件**: 保有銘柄一覧（UC-002）に対象銘柄が存在する
**関連要件**: F-003

#### 基本フロー
1. 本人が一覧から対象銘柄を選択する
2. システムが直近の株価推移チャート（デフォルト3年、MA20・MA75・取得単価の基準線を重ねて表示）を表示する。本人は表示期間（1年/3年/5年/10年）を切り替えられる
3. システムがテクニカル指標（RSI・MACD・ボリンジャーバンド・移動平均線）を計算し表示する
4. システムがファンダメンタルズ指標（PER・PBR・ROE・売上高/営業利益成長率・自己資本比率・営業利益率・配当利回り/性向）を表示する
5. システムが利確シグナルの判定結果と判定根拠を表示する
6. 本人がメモ欄に自由記述（LLMとの壁打ち内容の転記等）を入力し保存する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| chart_period | string | 任意 | `1y`/`3y`/`5y`/`10y`のいずれか。省略時は`3y`（デフォルト） |
| memo | text | 任意 | 最大2000文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| symbol_code / symbol_name | string | 銘柄基本情報 |
| average_cost | decimal | 取得単価。株価推移チャート上に基準線として表示する |
| price_history | list | `chart_period`で選択した期間の株価推移データ。各要素は`date`/`close_price`/`ma20`/`ma75`を持つ（週次スナップショット由来） |
| rsi / macd / bollinger_band / ma20 / ma75 | decimal等 | テクニカル指標一式（直近値） |
| volume / volume_ma20 | decimal | 直近出来高・20週平均出来高（ADR-0004） |
| week52_high / week52_low | decimal | 52週高値・52週安値（ADR-0004） |
| relative_strength_vs_market / relative_strength_vs_sector | decimal | 相対力（直近13週の騰落率と、対市場〔日経平均/S&P500〕・対セクター〔保有銘柄内の同一セクター平均〕の騰落率との差、%）。対セクターはJ-Quants無料プランに業種別指数がないため保有銘柄内平均で簡易算出する（ADR-0004） |
| per / pbr / roe / revenue_growth / equity_ratio / operating_margin / dividend_yield | decimal等 | ファンダメンタルズ指標一式 |
| metric_tones | object | 健全性指標ごとの段階（`strong_good`／`good`／`below`／`strong_below`）。キーは`roe`／`equity_ratio`／`operating_margin`／`revenue_growth`／`operating_income_growth`。値が null、または銀行・金融（除く銀行）の自己資本比率・営業利益率、不動産の自己資本比率、米国株の自己資本比率の強い良好は null/付けない（ADR-0023 D9） |
| per_verdict / pbr_verdict | object / null | PER・PBRの業種基準値との比較結果（`tier`／`ratio`／`benchmark`／`confidence`／`benchmark_as_of`／`source`、判定なしの場合は`reason`）。段階・判定なしの条件はUC-002と同じ（CHG-0034、ADR-0023） |
| eps_growth / peg_ratio | decimal | EPS成長率、PEGレシオ（PER÷EPS成長率）。EPS成長率が0以下の場合`peg_ratio`は`null`（算出不可）とする（ADR-0004） |
| signal_result | string | シグナル判定結果（例: 利確検討） |
| signal_reason | string | 判定根拠（例: RSIが72から65に反落） |
| memo_history | list | 保存済みメモ一覧（日付付き） |

#### 業務ルール
- メモは自由記述とし、保存時にシステムが日付を自動付与する（過去のメモは編集せず追記していく）
- **PER・PBRの割安・割高の色付け（CHG-0034、ADR-0023。2026-10-03 Gate 2 承認）**: PER・PBRの値の横に、業種の基準値との比率に応じたバッジ（強い割安／割安／並み／割高／強い割高、色はUC-002と同じ）と、基準値・基準日・出典を表示する。PERとPBRは別々に判定し、合成しない。PBRは日本株は全業種で判定し、米国株は簿価が意味を持たない業種が多いためUtilitiesのみ判定する（他は数値のみ）。基準値の信頼度が`low`の業種には「基準が不安定」と注記する。判定を付けない場合は、詳細画面に理由（業種が未分類／基準表にない業種／赤字などで値が0以下／基準の対象外）を表示する。**色付けのみで、財務健全性・利確シグナル・買い増しシグナルの判定には使わない**
- **健全性指標の二段階の色付け（CHG-0034、ADR-0023 D9。2026-10-03 Gate 2 承認、ラインは根拠調査のうえ同日改訂）**: ROE・自己資本比率・営業利益率・売上成長率・営業利益成長率の値の横に、強い良好（濃い緑）／良好（緑）／基準未満（黄）／大きく下回る（濃いオレンジ）のバッジを付ける。境界は「以上」で上の段階に含め、小数1桁に丸めた値で判定する。ライン（強い良好は日本株／米国株の順、他は共通）— ROE: 15%以上／25%以上、良好10%以上、基準未満0%以上、0%未満は大きく下回る。自己資本比率: 70%以上／強い良好なし、良好40%以上、基準未満20%以上、20%未満は大きく下回る。営業利益率: 20%以上／30%以上、良好10%以上、基準未満0%以上、0%未満は大きく下回る。売上成長率: 15%以上／25%以上、良好0%超、基準未満−10%以上0%以下、−10%未満は大きく下回る。営業利益成長率: 30%以上／30%以上、良好0%超、基準未満−20%以上0%以下、−20%未満は大きく下回る。良好の下限は財務健全性の現行の合格ラインと同じで、強い良好のラインは上場企業の分布の上位10〜25%を目安に外部の資料と保有銘柄の実データから決めた（根拠は`docs/product/valuation-benchmarks.md`7章。売上成長率・営業利益成長率と下側のラインは根拠が弱く叩き台）。値が null なら色を付けない。銀行・金融（除く銀行）は自己資本比率と営業利益率に、不動産は自己資本比率に色を付けない。**色付けのみで、財務健全性・利確シグナル・買い増しシグナルの判定には使わない**
- ファンダメンタルズ指標はJP株がJ-Quants由来のため最大12週間遅延する可能性がある旨を画面上に明示する。US株はFinnhub由来（ADR-0009）であり、この12週遅延の制約は適用されない（決算開示のタイミングに応じて更新される）
- 株価推移チャートは週次スナップショットに蓄積済みの終値データをそのまま用いて描画する（新規のリアルタイム取得・重い計算は行わない）
- 期間切り替え（`chart_period`）は表示範囲の絞り込みのみであり、RSI等の指標計算期間には影響しない（指標自体は`docs/architecture/data-model.md`（Gate 3）で定義する固定期間で計算する）
- チャートはあくまで人間が保有継続/利益確定を判断するための参考情報であり、チャート単体からの自動売買判定・シグナル生成は行わない（自動判定はUC-004の対象）
- `peg_ratio`はEPS成長率が0以下（減益・横ばい）の場合、指標として意味を持たないため算出せず`null`（「算出不可」）とする（ADR-0004）
- `relative_strength_vs_sector`は同一セクターの保有銘柄が本人以外1件も存在しない場合、比較対象がないため`null`（「算出不可」）とする。画面上は「保有銘柄内の同一セクター平均に対する相対力」である旨を明示する（J-Quants無料プランでは業種別指数が取得できないための簡易算出、ADR-0004）

### UC-004: 利確シグナル一覧

**Actor**: 本人
**前提条件**: 保有銘柄のテクニカル指標が計算済み（UC-003の計算処理に依存）
**関連要件**: F-004

#### 基本フロー
1. 本人が利確シグナル一覧画面にアクセスする
2. システムが含み益+20%超の銘柄を抽出する
3. システムが各銘柄のシグナル種別（RSI高水準からの反落・MACDデッドクロス等）を判定する
4. システムが分割指値の提案（例: +20%地点で1/3、+35%地点で1/3、残りはトレンド追従）を表示する
5. システムが各銘柄について、なぜ利確を検討すべきか（またはまだ検討不要か）を平易な一言サマリとして一覧に表示する
6. 本人が銘柄をクリックすると、銘柄詳細（UC-003）に遷移し、判定の背景・全指標を確認できる

#### 業務ルール
- 含み益が「利確検討ラインの閾値」を超えない銘柄は対象外（`requirements.md`のスコープに従う）。閾値は下記の動的分岐ルールにより銘柄ごとに決まる
- 対象はJP株・US株の個別株のみとし、ETF・投資信託は対象外とする（`UC-002`業務ルール参照）
- シグナル種別（`signal_type`）は以下7種とする。値は`docs/architecture/data-model.md`の初期パラメータ値と同様、叩き台として実装時に確定する（ADR-0004）
  - `rsi_reversal`（RSI高水準からの反落）
  - `macd_dead_cross`（MACDデッドクロス）
  - `bollinger_overheat`（ボリンジャーバンド上限付近での過熱）
  - `week52_high_pullback`（52週高値からの反落。初期値: 52週高値から-10%以上下落）
  - `peg_overvalued`（PEGレシオによる割高化。初期値: PEGレシオ2.0以上）
  - `relative_strength_weakening`（相対力の低下。初期値: 対市場の相対力が直近4週でプラスからマイナスに転換）
  - `volume_spike_decline`（出来高急増を伴う下落。初期値: 当該週の出来高が20週平均の1.5倍以上、かつ株価が前週比下落）
- 分割指値の提案は固定ルールではなく例示であり、具体的な閾値・比率のパラメータ化（銘柄ごとの調整可否を含む）は`docs/architecture/data-model.md`（Gate 3）で確定する
- **利確検討ラインの動的分岐（2026-08-28確定、CHG-0006）**: 中長期戦略の趣旨に反し、下落兆候が一切なく財務的にも健全な銘柄まで一律+20%で利確検討対象にしてしまう問題を解消するため、銘柄ごとに以下の2モードのいずれかを適用する
  - **通常モード**（下記の高水準モードの条件を満たさない銘柄）: 含み益+20%超で対象、分割指値は+20%地点で1/3・+35%地点で1/3・残りトレンド追従（従来通り）
  - **高水準モード**（「現在シグナルが0件」かつ「`docs/architecture/data-model.md`の財務健全性フィルタ〔UC-005/008/009/010と共通の基準〕を満たす」銘柄のみ）: 含み益+150%超で対象、分割指値は+100%地点で1/3・+150%地点で1/3・残りトレンド追従
  - 高水準モードに該当する銘柄の`signal_reason_summary`には、通常より高い水準まで利確検討を保留している旨（例:「シグナルなし・財務健全のため利確ラインを+150%まで引き上げています」）を含める
  - 本ロジックは`signals`テーブルへの永続化タイミング・判定対象（含み益+20%超という既存のシグナル判定条件）には影響しない。UC-010（買い増しタイミングレコメンド）の対象抽出は`signals`の有無を参照するため、本変更によるUC-010への影響はない
- 一覧では技術的なシグナル種別バッジ（RSI高値反落等）に加えて、`signal_reason_summary`を1行で表示し、判断軸が一目でわかるようにする。全指標の内訳・判定の詳細背景は一覧には出さず、銘柄詳細（UC-003）に集約する
- シグナルが発生していない銘柄（含み益+20%超のみ）も一覧の対象に含め、他の銘柄と同様に銘柄詳細（UC-003）への遷移導線を設ける
- **NISA区分（NISA成長投資枠/NISAつみたて投資枠）を除外する（ADR-0002）**: 保有がすべてNISA区分の銘柄は、非課税メリットを維持するため利確シグナル一覧の対象外とする（売却提案できる課税口座保有分が存在しないため）。特定口座/一般口座とNISA区分の両方にまたがる銘柄は、`unrealized_gain_rate`・シグナル判定は引き続き保有数量全体（合算値）を基準に行うが、`split_limit_suggestion`はNISA区分を除いた課税口座保有数量を上限とする
- 含み益が薄い/マイナスの既存保有銘柄への買い増し判断はUC-010（既存保有株の買い増しタイミングレコメンド）で提供する。判定対象・保存先（`buy_signals`）ともに本UCの利確シグナル（`signals`）とは独立しており、同一銘柄に利確シグナルと買い増しシグナルが同時に成立することはない（UC-010業務ルール参照、ADR-0007）
- **判定チェックリスト（2026-08-29追加、CHG-0007）**: `signal_reason_summary` の文章だけでは「基準にどれだけ近いか」「7項目のうち何項目を満たしているか」が読み取れないため、一覧の各銘柄行に、判定に使う項目の「基準点」と「その銘柄の実測値」「達成状態」を並べた表（`criteria`）を表示する。表示のみの機能であり、`signals` の判定・永続化ロジックには一切影響しない
  - **テクニカル9項目**（利確を後押しする方向を「達成」とする）: ①含み益率（>利確ライン。通常+20%／高水準モード時+150%）②RSI（≧70）③52週高値からの下落率（≦-10%）④ボリンジャーバンド上限乖離率（≧0%）⑤MACD−シグナル線（<0）⑥PEGレシオ（≧2.0）⑦相対力〔対市場〕（<0）⑧PER・⑨PBR（2026-09-21追加、CHG-0019）。基準値①〜⑦はいずれも `docs/architecture/data-model.md` で確定済みのシグナル判定閾値をそのまま用い、新しい基準値は設けない。**成長率〔売上高・営業利益の高い方〕が低い（5%以下、暫定閾値）銘柄はPEGレシオ項目（⑥）を判定対象から除外する（2026-09-19改訂、ADR-0015 D3。セクター分類には依存しない）**。低成長銘柄はPEGが構造的に高くなりやすく、財務健全性が良好でも本項目のみで`met`扱いになり`signalCount`が非ゼロに保たれ続け、下記の高水準モードに到達できなくなるため。**⑧PER・⑨PBRは利確を後押しする判定ロジックが存在しない（割安であることは利確を後押ししない）ため、買い増し候補〔UC-010〕のPERとは異なりmet/near/unmet閾値を持たせず、両方とも基準なしの参考表示（`status`＝`info`）とする（ADR-0016 D4、CHG-0019）**
  - **財務健全性4項目**（`FundamentalHealthEvaluator` の4条件をそのまま数値展開。2026-09-06、CHG-0012／ADR-0011 で営業利益率を追加し3→4項目）: ROE（≧10%）／自己資本比率（≧40%）／成長率〔売上高・営業利益の高い方〕（>0%）／**営業利益率（≧10%）**。財務が健全であることは利確側では「まだ売らなくてよい」という保留材料であり、テクニカル9項目とは意味の向きが逆になるため、別グループとして区切り、達成件数もテクニカルと分けて集計する。高水準モード該当銘柄では、財務グループの見出しに利確ライン引き上げの根拠である旨を紐づける。**成長率項目は次のいずれかを満たせばOR判定で`met`とする（2026-09-19追加・改訂、ADR-0015 D1/D2）**: ①単年度の売上高/営業利益成長率のいずれかプラス、②直近3〜5期平均成長率>0%（`financial_statements`、JP株のみ・3期未満は対象外）、③ROE≧15%かつ自己資本比率≧50%（成長率を問わない財務指標のみの救済経路、全銘柄対象。配当利回りは判定条件には使わず参考表示のみ——無配当・低配当でも資本効率の高い銘柄〔米国株に多い〕を除外しないため）。景気の谷の年に単年度だけマイナスでも財務が健全なら救済する。銘柄のセクター分類には依存しない
  - **達成状態**: 各項目は「達成（`met`）」「あと一歩（`near`）」「未達（`unmet`）」「データなし（`unavailable`）」の4値。`near` の判定バッファは `docs/architecture/data-model.md`（Gate 3）で定める（基準値の±20%手前。基準値が0の項目は比率が定義できないため達成／未達の2値とする）。実測値が未取得（外部データ取得の失敗等、ADR-0009によりUS株のファンダメンタルズ指標も通常時は取得できる）の項目は `unavailable` とし、実測値欄は「—」と表示する
  - **表示上の扱い**: 「判定の全背景・関連する全指標の内訳は一覧に出さず詳細画面に集約する」という `ui-guidelines.md` テーブル方針の例外として、基準点つきの本チェックリストに限り一覧に表示する。個別指標の時系列・計算根拠の詳細は引き続き銘柄詳細（UC-003）に集約する
- **一覧の並び順の切替（2026-10-01追加、CHG-0027）**: 売買シグナル画面の3テーブル（UC-004/010/011）は共通の切替で「評価額順（既定。評価額の大きい順、同額は下記おすすめ順で決着）」「おすすめ順（下記の透明マルチキー）」を選べる。切替は画面のみで、JSON APIとUC-013のバケツ内並びは従来の（おすすめ順の）ままとする
- **PER・PBRチップの業種比較の色付けと財務チップの二段階（CHG-0048、ADR-0026。2026-10-04 Gate 2 承認）**: 利確検討表のPER・PBRチップ（従来は基準なしの参考表示）に、業種の基準値との比率に応じた色とラベル（強い割安／割安／並み／割高／強い割高。色・境界・信頼度による濃色の制御はUC-002のPERバッジと同じ、ADR-0023 D3〜D6）を付ける。達成数には数えない従来どおりの参考表示で、判定には使わない。判定なし（業種未分類・基準表にない・値が0以下など）は従来のグレー表示。あわせて、財務健全性チップ（ROE・自己資本比率・営業利益率・成長率）が達成のとき、強い良好のライン（ADR-0023 D9）を超えたものだけ濃い緑にし、ラベル「強い良好」を添える。判定ロジックは変更しない
- **NISA保有区分のバッジ（2026-10-04追加、CHG-0047、Gate2承認済み）**: 売買シグナル画面の4テーブル（利確検討・買い増し候補・整理検討〔含み損〕・キープ）の銘柄セル（左端の固定列）で、銘柄名の下に口座区分の保有内訳（`holding_snapshot_accounts`）に基づくバッジを出す。内訳がすべてNISA（成長投資枠・つみたて投資枠を区別しない）なら「NISAのみ」（info）、NISAと課税口座（特定・一般）が混在するなら「NISA一部」（neutral）、課税口座のみ・内訳なし（旧スナップショット）は何も出さない。株数の内訳は出さない。利確検討はNISAのみの銘柄を対象外にしているため（既存ルール）、出るのは「NISA一部」のみ。各行データに `nisa_holding`（`nisa_only` / `nisa_partial` / null）を1項目追加する（UC-004/UC-010のJSON APIにも同じ項目が加わる。既存キーは不変）。表示のみで、抽出条件・判定・並び順は変更しない
- **一覧の並び順（おすすめ順、2026-09-17追加、F-013/ADR-0014 D10-1）**: ①シグナル数（多い順）②判定チェックリストのテクニカル達成数（多い順）③含み益率（高い順）の優先順位で並べる。従来は並び順の定義がなく取込順のまま表示されていた既存の穴を、F-013（ポートフォリオ分類ダッシュボード）の`take_profit`バケツ設計にあわせて埋めたもの。新しい閾値・重み付けは設けず、いずれも既存の算出値のみを用いる
- **`valuation_zone_badge`（2026-09-19追加、ADR-0015）**: 成長率〔売上高・営業利益の高い方〕が低い（5%以下、暫定閾値）銘柄が、現在のバリュエーション（PERの条件かつ配当利回り≧3%。PERの条件は2026-10-04から買い増し判定と同じく業種の基準PERとの比率〔信頼度high/mediumは0.80未満、lowは0.70未満、業種のない銘柄だけPER≦15〕、CHG-0048・ADR-0026 D3）でもなお割安と判定される場合、`valuation_zone_badge`に「絶対バリュエーション上は割安ゾーン」を表示する。**判定基準は成長率のみを参照し、銘柄のセクター分類には依存しない**（2026-09-19改訂、実データで`sector_classification_id`がほぼ未整備と判明したためセクターベースの分岐を撤回）。判定の主軸（含み益率）は変更しないため、この銘柄をUC-010（買い増し候補）へ同時掲載することはしない

### UC-005: セクター配分ダッシュボード

**Actor**: 本人
**前提条件**: 保有銘柄にセクター分類情報が付与されている（J-Quants等由来）
**関連要件**: F-005

#### 基本フロー
1. 本人がダッシュボード画面にアクセスする
2. システムが保有銘柄をセクター別に集計し配分比率を表示する
3. システムが各セクターの配分状態（健全/やや偏り/偏り警告の3段階）を判定し、配分バー上に目安ライン（40%）とあわせて表示する
4. システムが偏り警告となったセクターについて、目標配分まで下げるための売却額・株数の目安を算出し表示する
5. システムが保有比率が低い/未保有のセクターの中から、注目テーマ合致＋財務健全性フィルタ（F-008と同じロジック）でリバランス候補銘柄を抽出し、推薦理由と購入額の目安を添えて表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| なし | - | - | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| market | string | 市場区分（`jp`=日本株 / `us`=米国株 / `mutual_fund`=投資信託）。画面では市場ごとに区切って表示する（ADR-0020） |
| sector_name | string | セクター名（未分類を含む。米国株はFinnhubの業種名、投信は「投資信託」） |
| allocation_rate | decimal | 配分比率（%）。画面表示は小数1桁 |
| allocation_amount | decimal | セクターの評価額合計（円）。画面には市場ごとの小計と全体の合計額も表示する（ADR-0020） |
| allocation_status | string | 配分状態（`健全`/`やや偏り`/`偏り警告`の3段階） |
| is_overweight | boolean | 偏り警告フラグ（`allocation_status`が`偏り警告`の場合true） |
| rebalance_candidates | list | 提案する他セクターの候補銘柄。各要素は`symbol_code`/`symbol_name`/`sector_name`/`reason`（推薦理由の一言サマリ）/`suggested_purchase_amount`（購入額の目安）/`nisa_recommended`（NISA枠での購入推奨フラグ、UC-008参照）を持つ |
| suggested_sell_amount | decimal | 目標配分まで下げるための売却額の目安（円）。NISA区分（NISA成長投資枠/NISAつみたて投資枠）を除いた課税口座保有分のみを対象に算出する |
| suggested_sell_quantity | int | 同、現在値ベースの株数換算の目安（NISA区分を除く） |

#### 業務ルール
- 配分状態は2段階の目安ラインで判定する（初期値・叩き台）: 40%未満=健全、40%以上70%未満=やや偏り、70%以上=偏り警告。両閾値のパラメータ化・変更可否は`docs/architecture/data-model.md`（Gate 3）で確定する
- 配分バーには40%の目安ラインを表示し、現状が目安に対してどの位置にあるか視覚的にわかるようにする
- `健全`のセクターにはバッジを表示しない（情報過多を避けるため）。`やや偏り`/`偏り警告`のみバッジで強調する
- セクター分類が取得できていない銘柄は「未分類」として集計に含める（市場ごとに別行。ADR-0020）
- **米国株・投資信託の分類（ADR-0020）**: 米国株はFinnhubの業種で、投資信託は固定カテゴリ「投資信託」で分類する。日本株・米国株・投資信託は市場別に区切って表示し、日米の業種は統合しない。偏り判定（40%/70%）は従来どおり全体に対するセクター単位の比率で行う
- 売却額の目安は「（現在配分率−目標配分率〔初期値は偏り判定閾値と同一の70%〕）×保有評価額合計」のシンプルな計算式で概算する。複数銘柄への配分方法・端数処理・銘柄選定ロジックの詳細は`docs/architecture/data-model.md`（Gate 3）で確定する
- リバランス候補銘柄の`reason`・`suggested_purchase_amount`は、F-008（UC-008）の抽出ロジック（本人が登録した注目テーマへの合致＋財務健全性フィルタ、購入額目安はポートフォリオ全体の1〜2%程度）を流用する。候補は`健全`または`やや偏り`のセクターの中から選ぶ（`偏り警告`セクターは対象外）
- あくまで「目安」であり、自動発注は行わない（`requirements.md`のOUTスコープに従う）
- **NISA区分（NISA成長投資枠/NISAつみたて投資枠）を除外する（ADR-0002）**: `allocation_rate`（配分比率）自体はNISA区分を含む保有全体で算出する（保有の全体像を示す指標のため除外しない）。一方`suggested_sell_amount`/`suggested_sell_quantity`の算出・対象銘柄選定は特定口座/一般口座の保有分のみを対象とし、NISA区分の保有分は非課税メリットを維持するため売却提案の対象から除外する。偏り警告セクターの保有がすべてNISA区分の場合、`suggested_sell_amount`/`suggested_sell_quantity`は0（「NISA区分のみ保有のため売却提案なし」として表示）とする
- **集中度画面との行き来（UC-015、ADR-0021 D5）**: タイトルの下に「セクター配分 | 集中度」の切替を置き、集中度ダッシュボード（`/concentration-dashboard`）へ移れる
- `rebalance_candidates`の`nisa_recommended`はUC-008と同じ基準で判定する（詳細はUC-008業務ルール参照）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| セクター分類データが未取得の銘柄がある | - | 該当銘柄は「未分類」として表示を継続し、画面の表示自体は止めない |

#### 権限
- 本人: 実行可（他Actorなし）

### UC-006: 新規投資候補の重複チェック

> **2026-09-06、ADR-0013（F-012）で UC-012 に統合・刷新**: 本UCの価値ある部分（同セクター保有比率＝`overlap_rate` の可視化、テクニカル/ファンダ指標一式、過去業績推移、ウォッチステータス／メモの記録・履歴）は UC-012 の一覧・行展開に引き継ぐ。**「銘柄コードを手入力して1銘柄をチェックする」入口は廃止**し、お気に入りCSV由来のウォッチリストが候補の供給源になる。以下の記述は UC-012 実装までの経緯として残す。

**Actor**: 本人
**前提条件**: 以下のいずれかによって対象銘柄が定まっている
  - (a) 本人が新規投資候補の銘柄コードを把握している（手動入力での利用）
  - (b) 直近のCSV取込（UC-001）で新規検出銘柄として記録されている（保有銘柄一覧UC-002のNEWバッジ経由での利用）
  - (c) おすすめ候補（UC-008）の一覧から選択した（同一画面内での連携）
**関連要件**: F-006

#### 基本フロー
1a. 本人が新規投資候補チェック画面に直接アクセスし、銘柄コードを入力する（手動入力）
1b. 本人が保有銘柄一覧（UC-002）でNEWバッジを選択し、対象銘柄コードが入力された状態で本画面に遷移する（自動検出経由。入力値は変更可能）
2. システムが該当銘柄のセクター分類を取得する
3. システムが既存保有との重複度・分散への影響を判定し表示する
4. システムがテクニカル指標・ファンダメンタルズ指標（銘柄詳細UC-003と同じ項目セット）を判定結果にあわせて表示する
5. システムが直近3〜5期分の売上高・営業利益の推移を表示する
6. システムが対象銘柄について過去に保存されたウォッチステータス・メモがあれば、判定結果とあわせて表示する
7. 本人が判定結果を踏まえてウォッチステータス（様子見/買い時/次回購入候補/リバランス対象）とメモ（任意）を入力し保存する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| symbol_code | string | 必須 | 証券コード形式（4桁数字等、市場に応じた形式）。UC-002のNEWバッジ経由の場合は初期値として自動入力される |
| watch_status | string | 任意 | `様子見`/`買い時`/`次回購入候補`/`リバランス対象`のいずれか |
| watch_memo | text | 任意 | 最大2000文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| symbol_name | string | 銘柄名 |
| sector | string | セクター分類 |
| overlap_rate | decimal | 既存保有の同セクター内比率（重複度） |
| diversification_comment | string | 分散影響に関するコメント |
| rsi / macd / bollinger_band / ma20 / ma75 | decimal等 | テクニカル指標一式（UC-003と同一項目） |
| per / pbr / roe / revenue_growth / equity_ratio / dividend_yield | decimal等 | ファンダメンタルズ指標一式（UC-003と同一項目） |
| historical_performance | list | 直近3〜5期分の決算期・売上高・営業利益・前年比増減のリスト |
| watch_status | string | 直近保存されたウォッチステータス（`様子見`/`買い時`/`次回購入候補`/`リバランス対象`）。未保存の場合は未設定 |
| watch_memo_history | list | 保存済みウォッチステータス・メモの履歴（日付・その時点のステータス・メモ本文付き） |

#### 業務ルール
- どの銘柄が有望かという選定自体はシステムの対象外とし、既存保有との分類上の重複・分散影響の可視化に限定する。ウォッチステータスはこの方針の例外ではなく、本人が自分の判断を記録するための項目であり、システムによる自動判定・推奨は行わない
- 重複度は「対象銘柄と同一セクターの既存保有比率」を基準に算出する
- 新規に買付した銘柄は少額から様子見で保有を始めるケースが多いため、購入前の事前チェック（フロー1a）だけでなく、CSV取込後に「気づいたら新規銘柄が増えていた」という事後チェック（フロー1b）も主要な利用経路として想定する
- 本画面は単一銘柄をじっくり確認する用途のため、保有銘柄一覧（UC-002）のように代表指標のみへ絞り込まず、銘柄詳細（UC-003）と同等のテクニカル/ファンダメンタルズ指標一式を表示する
- 過去の業績推移（`historical_performance`）はJ-Quantsの財務諸表データに基づく。件数（3〜5期）・具体的な項目は`docs/architecture/data-model.md`（Gate 3）で確定する。ファンダメンタルズ指標と同様、最大12週間遅延する可能性がある旨を画面上に明示する
- 対象銘柄の指標算出に必要なデータが取得できない場合（新規上場間もない等）、該当指標のみ「取得不可」と表示し、他の判定結果（重複度・分散影響等）は通常通り表示する
- 画面はUC-008（新規投資候補レコメンド）と統合し、「新規投資候補」という単一のメニュー項目の下部セクションとして提供する（タブ数を増やさないため。詳細は`ui-guidelines.md`参照）
- ウォッチステータス・メモは銘柄コード単位で保存し、同一銘柄を再度本画面でチェックした際（手動入力・NEWバッジ経由・おすすめ候補経由のいずれでも）に過去の記録を参考情報として表示する
- メモは自由記述とし、保存時にシステムが日付とその時点のウォッチステータスを自動付与する（過去の記録は編集せず追記していく。UC-003のメモ機能と同様の運用とする）
- ウォッチステータスのみの更新（メモ本文なし）も許可する

|---|---|---|
| 銘柄コードが存在しない/セクター分類が取得できない | 422 | 銘柄コードを確認してください |
| ウォッチメモが2000文字超 | 422 | メモは2000文字以内で入力してください |

3. システムが画面上部のセクションに、登録済みテーマに合致するセクター・銘柄群の中から、財務健全性の基準（自己資本比率・ROE等）を満たす中長期銘柄を抽出して表示する
4. システムが該当銘柄と、小口購入額の目安（ポートフォリオ全体の1〜2%相当）を一覧表示する
5. 本人が気になる候補銘柄を選択すると、同一画面下部の重複チェック（UC-006）セクションに銘柄コードが自動入力され、詳細を確認できる

#### 出力
| 項目 | 型 | 説明 |

#### 業務ルール
- 「注目テーマ・セクター」の登録・更新は本人が手動で行う。ニュース・社会的要因等からのテーマの自動発見・自動抽出は行わない（`requirements.md`のOUTスコープに従う。メタトレンド自体の予測はシステムの対象外）
- 財務健全性の基準は、ROE・自己資本比率・成長率（売上高成長率または営業利益成長率のいずれか）・営業利益率が一定水準を満たすこととする（2026-08-27、CHG-0005でUC-010と同一基準に統一。2026-09-06、CHG-0012／ADR-0011で営業利益率を4条件目として追加）。具体的な閾値は`docs/architecture/data-model.md`（Gate 3）で確定する
- 購入額の目安は保有評価額合計に対して1〜2%程度の小口を想定した簡易計算とする。具体的な計算式は`docs/architecture/data-model.md`（Gate 3）で確定する
- 本機能はあくまで候補の絞り込み支援であり、最終的な銘柄選定・購入判断は本人が行う
- 対象はJP株・US株の個別株のみとし、ETF・投資信託は対象外とする（`UC-002`業務ルール参照）
- 表示場所はUC-006（新規投資候補の重複チェック）と同一の「新規投資候補」画面の上部セクションとし、UC-008専用の独立したメニュー項目は設けない（`ui-guidelines.md`参照）
- **NISA推奨（`nisa_recommended`、ADR-0002）**: 財務健全性フィルタの基準に加えて、より高い健全性・成長性を示す候補（自己資本比率・ROE等の具体的な追加閾値は`docs/architecture/data-model.md`〔Gate 3〕で確定する）については`nisa_recommended=true`とし、中長期（5〜10年程度）の保有に適した銘柄として「NISA枠での購入」を推奨する理由を`nisa_recommended_reason`に表示する。この推奨はあくまで参考情報であり、実際にNISA枠・課税口座のどちらで購入するかは本人が判断する

### UC-010: 既存保有株の買い増しタイミングレコメンド

**Actor**: 本人
**前提条件**: 保有銘柄のテクニカル指標が計算済み（UC-003の計算処理に依存）
**関連要件**: F-010

#### 基本フロー
1. 本人が売買シグナル画面（買い増し候補セクション）にアクセスする
2. システムが押し目買いシグナルが1件以上発生している保有銘柄を抽出する
3. システムが各銘柄にファンダメンタルズ健全性フィルタ（ROE・自己資本比率・成長率・営業利益率）を適用し、基準を満たさない銘柄を除外する
4. システムが分割買い下がりの指値提案（例: 現在値／-7%地点／-15%地点で3分割）を表示する
5. システムが各銘柄について、なぜ買い増しを検討すべきかを平易な一言サマリとして一覧に表示する
6. 本人が銘柄をクリックすると、銘柄詳細（UC-003）に遷移し、判定の背景・全指標を確認できる

| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| なし | - | - | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| symbol_code / symbol_name | string | 銘柄基本情報 |
| current_price | decimal | 現在値 |
| market_value | decimal | 評価額（保有数量 × 現在値）。US株はCSVヘッダーの参考為替レートで円換算済みの `current_price` を用いるため円建て（2026-09-05追加、CHG-0011）。一覧では銘柄名の右隣に表示する |
| unrealized_gain_rate | decimal | 含み益率（%）。マイナスも含む |
| buy_signal_types | list | 発生している買い増しシグナル種別のリスト |
| buy_signal_reason_summary | string | 判定根拠の一言サマリ（例: "RSIが28から34へ反発しました、終値がボリンジャーバンド下限を下回りました"） |

| nisa_recommended | boolean | 中長期保有前提のNISA枠での購入推奨可否 |
| nisa_recommended_reason | string | NISA枠推奨理由の一言サマリ（`nisa_recommended=true`の場合のみ） |
| suggested_amount | decimal | 追加投資額の目安（ポートフォリオ評価総額に対する小口の目安） |
| split_buy_down_suggestion | list | 分割買い下がりの提案（価格帯・数量） |
| criteria | object | 判定チェックリスト（下記業務ルール参照）。UC-004の `criteria` と同一構造（`technical` 9項目〔2026-09-19、CHG-0018でPER/PBRを追加し7→9〕・`fundamental` 4項目〔2026-09-06、CHG-0012で3→4〕・`summary`） |
| per / pbr | decimal | 判定チェックリストのテクニカル項目内に含める実測値（2026-09-19、CHG-0018）。PERは判定基準（≦15）を持つ通常項目、PBRは基準を持たない参考表示（下記業務ルール参照） |

#### 業務ルール
- 対象はJP株・US株の個別株のみとし、ETF・投資信託は対象外とする（`UC-002`業務ルール参照）
- 買い増しシグナル種別（`signal_type`）は以下8種とする（2026-09-19、CHG-0018で`per_undervalued`を追加し7→8）。UC-004の7種と面対称の設計とし、値は`docs/architecture/data-model.md`の初期パラメータ値と同様、叩き台として実装時に確定する（ADR-0007）
  - `rsi_oversold_rebound`（RSI低水準からの反発。初期値: RSI30以下からの反発）
  - `macd_golden_cross`（MACDゴールデンクロス）
  - `bollinger_oversold`（ボリンジャーバンド下限付近での売られすぎ）
  - `week52_low_proximity`（52週安値圏。初期値: 52週安値から+10%以内）
  - `ma_deviation_oversold`（移動平均線からの下方乖離。初期値: MA20から-10%以上の乖離）
  - `volume_spike_rebound`（出来高急増を伴う反発。初期値: 当該週の出来高が20週平均の1.5倍以上、かつ株価が前週比上昇）
  - `peg_undervalued`（PEGレシオによる割安化。初期値: PEGレシオ1.0以下）。**成長率〔売上高・営業利益の高い方〕が低い（5%以下、暫定閾値）銘柄は本シグナルを判定対象から除外し、PER≦15かつ配当利回り≧3%（暫定閾値）の絶対閾値判定に置き換える（2026-09-19追加、ADR-0015 D3。判定は成長率データのみを参照し、銘柄のセクター分類には依存しない）**
  - `per_undervalued`（PERによる割安化。初期値: PER15.0以下。2026-09-19、CHG-0018／ADR-0016で追加。上記`peg_undervalued`の低成長代替条件とは独立した別シグナル。UC-004には対応するシグナルを設けない〔面対称ではない、下記参照〕）
- ファンダメンタルズ健全性フィルタは、ROE・自己資本比率・成長率（売上高成長率または営業利益成長率のいずれか）・営業利益率（2026-09-06、CHG-0012／ADR-0011で追加）が一定水準を満たす銘柄のみを対象とする。具体的な閾値は`docs/architecture/data-model.md`（Gate 3）で確定するが、UC-009の新規投資候補フィルタと同一値を用いて一貫性を保つ。**成長率項目は`FundamentalHealthEvaluator`を共有するため、UC-004業務ルールの「直近3〜5期平均成長率>0%」OR救済分岐（ADR-0015 D2）の影響を自動的に受ける**
- **全シグナル共通の前提条件（2026-08-23追加、2026-09-19 CHG-0018／ADR-0016でA改訂・ADR-0015 D4でB改訂・D5でC追加）**: 本機能の意図は「健全で好調だった銘柄が、市場全体・セクター全体の調整で一時的に下げた場面」を拾うことに加え、「財務が健全なのに市場評価が長期間追いついていない銘柄（52週高値には長らく接近していないが、収益力自体は高い銘柄）」も拾うことである。8種のシグナルいずれも以下3条件をすべて満たした場合のみ検出対象とする（具体的な閾値は`docs/architecture/data-model.md`〔Gate 3〕で確定するが、初期値は以下を叩き台とする）
  - **(A) 直前まで好調だった証拠、または財務健全性が優れている証拠（OR条件）**: 次のいずれかを満たすこと
    - 直近13週以内に52週高値（`week52_high`）の-15%以内に到達していたこと。52週高値に一度も接近せず下げ続けている長期低迷銘柄を除外しつつ押し目買いを拾う目的
    - ファンダメンタルズ健全性フィルタが`passed`であること。実データ検証（ADR-0016）で、52週高値から-35〜-48%も乖離した財務健全な銘柄が複数存在することを確認しており、これらを「万年低迷株」ではなく「市場評価が追いついていない優良株」として拾う目的
  - **(B) 市場全体・セクター全体の連れ安であることの確認（2026-09-19改訂、ADR-0015 D4）**: `relative_strength_vs_sector`（対セクター相対力）が算出済みの銘柄はそちらを、未算出（null）の銘柄は従来通り`relative_strength_vs_market`（対市場）を用い、-5pt以上であること。個別銘柄固有の悪材料（業績下方修正等）により市場・セクター平均を大きく下回って下落している銘柄は、財務健全性の有無に関わらず対象外とする（(A)をOR条件で満たしても(B)は独立して必須）
  - **(C) 中期トレンドが健在であることの確認（2026-09-19追加、ADR-0015 D5）**: 週足MA75の傾きが上向き（直近値が13週前の値を上回る）であること。下降トレンドが継続中の銘柄を「押し目」として誤検出しないための条件
- ファンダメンタルズ指標が未取得（JP株・US株いずれも外部データ取得に失敗した銘柄）の場合は`fundamental_status=unavailable`として一覧に含める（除外はしない）。US株はFinnhub（ADR-0009）をデータソースとしており、通常時はJP株と同様にファンダメンタルズ健全性フィルタで判定する
- 利確シグナル（UC-004）が同時に成立している銘柄は対象外とする（同一銘柄に「売れ」と「買え」を同時に提示しないため）
- **NISA区分は除外要因にしない（ADR-0002/ADR-0007）**: 利確シグナル一覧（UC-004）と異なり、NISA区分の保有であっても買い増し対象から除外しない。ファンダメンタルズ健全性フィルタより高い基準（ROE・自己資本比率がより高い水準）を満たす銘柄には、中長期保有前提のNISA枠での購入推奨（`nisa_recommended`）を付与する。ただしNISA枠の年間/生涯の残量情報はCSVに含まれないため、推奨は残量を考慮しない参考情報にとどまる
- 分割買い下がりの提案は固定ルールではなく例示であり、具体的な閾値・比率のパラメータ化は`docs/architecture/data-model.md`（Gate 3）で確定する

### UC-011: 整理検討（含み損）候補一覧

**Actor**: 本人

**関連要件**: F-011

#### 基本フロー
1. 本人が売買シグナル画面（整理検討セクション）にアクセスする

#### 業務ルール
- 対象はJP株・US株の個別株のみとし、ETF・投資信託は対象外とする（`UC-002`業務ルール参照）
- 対象抽出は直近の週次スナップショットの含み益率が整理検討ライン（叩き台: -20%）を下回る銘柄とする。閾値は`docs/architecture/data-model.md`（Gate 3）で確定する
- **本機能は「整理（売却検討）の踏ん切りをつけるための判断材料の提示」であり、機械的な損切り指示・分割売却の指値提案・自動発注・ナンピン推奨は行わない（`requirements.md` 2章、ADR-0010）**。画面上に「自動売却は行いません。最終判断は本人が行います」を明示する
- `recovery_required_rate` は含み益率がプラスの銘柄は対象外のため常に正の値になる。「この上昇率を、この銘柄が過去どれくらいの期間で達成し得たか」を本人が考える材料として提示する
- **ファンダメンタルズ健全性フィルタが不合格（`failed`）の銘柄も一覧から除外しない（UC-010とは逆）**。財務の毀損は整理を後押しする材料であり、隠すと本機能の意味がなくなるため。`fundamental_status` には `passed` / `unavailable` / `failed` の3値を出力する
- **押し目買いシグナル（`buy_signals`、UC-010）が発生している銘柄も除外しない**。一覧に含めたうえで「押し目買いシグナル発生中・買い増し候補にも掲載」と明示し、並び順で最後尾に回す。「切れ」と「買え」を矛盾提示しないための順序制御であって、情報の抑制はしない
- 一覧の並び順（おすすめ順。画面は評価額順が既定でUC-004に定める切替で選べる、CHG-0027）は、判定の透明性を優先し合成スコアリングを用いない。①押し目買いシグナルなし→あり、②ファンダ状態（`failed`→`unavailable`→`passed`）、③整理テクニカル該当数の多い順、④含み損率の深い順、という単純な複数キーでソートする（ADR-0010。ADR-0003が定めるF-009の合成スコアリング方針とは別の設計とする）
- 一覧では、`loss_review_reason_summary`を1行で表示し、判断軸が一目でわかるようにする。全指標の内訳・判定の詳細背景は一覧には出さず、銘柄詳細（UC-003）に集約する（UC-004/UC-010と同じ方針）
- **判定チェックリスト（`criteria`）**: UC-004/UC-010と同じ方針で、一覧の各銘柄行に判定項目の「基準点」「実測値」「達成状態」を並べた表を表示する。表示のみの機能で、対象抽出・並び順のロジックには影響しない
  - **テクニカル9項目**（整理を後押しする方向を「達成」とする。UC-004の9項目と面対称）: ①含み損率（≦整理検討ライン、叩き台-20%）②52週高値からの下落率（≦-30%、叩き台）③52週安値からの距離（≦+10%）④MA75乖離率（≦-10%）⑤MACD−シグナル線（<0）⑥相対力〔対市場〕（≦-5）⑦押し目買いシグナル件数（=0件）⑧PER・⑨PBR（2026-09-21追加、CHG-0019）。基準値のうち①②⑦は`docs/architecture/data-model.md`（Gate 3）で新規確定する叩き台、③④⑤⑥は既存の確定済み閾値（`BuySignalDeterminationService`等）をそのまま可視化するもので新しい基準値は設けない。**⑧PER・⑨PBRは整理を後押しする判定ロジックが存在しない（割安であることは整理の後押しにならない）ため、財務健全性4項目の反転契約とは独立に、両方とも基準なしの参考表示（`status`＝`info`。反転しない）とする（ADR-0016 D4、CHG-0019）**
  - **財務健全性4項目**（2026-09-06、CHG-0012／ADR-0011で3→4項目。営業利益率を追加）: 閾値の値はUC-004/UC-010と同一（ROE 10%／自己資本比率 40%／成長率 0%／営業利益率 10%）。成長率項目のOR救済分岐（ADR-0015 D2）は`FundamentalHealthEvaluator`共有のため本UCにも適用される（整理検討では判定が反転するため、救済により`unmet`〔健全〕側に動く銘柄が増える方向）。**整理検討テーブルでは判定の向きを反転**し、「基準割れ（＝投資根拠の毀損）」を「達成（`met`）」とする（2026-09-06、ADR-0010 D6 改訂。営業利益率も同じ反転フラグに乗せ、10%未満で `met`）。整理検討テーブルの判定チェックリストは「テクニカル9項目・財務4項目のいずれも、整理を後押しする事実が成立していれば `met`」で統一する（PER・PBRはinfoのため対象外）。健全な財務は `unmet` として扱い、実測値（例「ROE 15.2%」「営業利益率 18.3%」）は表示する。テクニカル9項目とは集計を分け、サマリは「投資根拠の毀損 ◯/4」と表示する。「まだ売らなくてよい（保留材料）」は `fundamental_status`（`passed`/`unavailable`/`failed`）・`fundamental_summary`・`loss_review_reason_summary` の散文で伝える
  - **達成状態**: 各項目は「達成（`met`）」「あと一歩（`near`）」「未達（`unmet`）」「データなし（`unavailable`）」の4値。`near` バッファ・基準値0の項目の扱い・`unavailable` の扱い・`ui-guidelines.md` テーブル方針の例外扱いはUC-004と同一。**チップの配色のみ整理検討テーブル専用**とし、達成＝赤系／あと一歩＝淡い赤／未達・データなし＝グレーとする（利確検討・買い増し候補テーブルの緑チップと視覚的に区別し、1テーブル内に赤と緑を混在させない。`ui-guidelines.md` 参照）
- **PER・PBRチップは、ラベル文字のみ（色なし）（CHG-0048、ADR-0026。2026-10-04 Gate 2 承認）**: 整理検討表のPER・PBRチップに、業種比較のラベル（強い割安／割安／並み／割高／強い割高）を文字で添える。色は付けない（ADR-0010 D6の「赤の単一極性」を維持）。財務チップの二段階も付けない。判定なしは従来どおり。判定には使わない
- **推定保有期間（`continuous_holding_weeks`）**: 対象銘柄が直近スナップショットから連続して何週分の `holding_snapshots` に出現しているかで算出する。楽天証券CSVに取得日が含まれないための代替であり、正確な保有期間ではない。最古のスナップショットまで連続して出現していた場合は `continuous_holding_weeks_is_truncated=true` とし、画面上は「N週以上（観測開始まで遡及）」と表示する。取込回数が少ない時期は情報量が限られる旨を画面に注記する
- **NISA区分の扱い**: 含み損は損益通算・非課税メリットの観点が利確（UC-004）とは逆になる（NISA口座の含み損は損益通算できない）。本フェーズではNISA区分による対象銘柄の絞り込み・除外は行わず、全口座区分の含み損銘柄を一覧表示する。画面上に「NISA区分の含み損は損益通算できない点に留意」の注記を表示する
- 対象銘柄の指標算出に必要なデータが取得できない場合、該当のチェックリスト項目のみ `unavailable`（値「—」）と表示し、他の項目・行の表示は継続する

3. システムが各銘柄を銘柄マスタ（`holdings`）に find-or-create し、ウォッチリスト（`watchlist_items`）に登録する（既存の銘柄は再利用し重複を作らない。フォルダ名・取引所ラベルを更新する。`is_starred` は保持する）
4. 今回のCSVに含まれない既存のウォッチリスト銘柄は削除しない（`last_seen_in_csv_at` を更新しないことで「楽天側のお気に入りからは外れている」ことを表示できる）
5. システムが取込完了後、未保有のウォッチリスト銘柄に対する一括更新（下記「基本フロー（一括更新）」のフロー2以降）を自動でキュー投入する
6. システムが取込結果（登録件数・スキップ件数）を表示する

#### 基本フロー（調査候補からの登録、CHG-0031）
1. 本人がUC-016の「監視に追加」で確定すると、未保有・未登録の銘柄は銘柄マスタ（`holdings`）に find-or-create し、ウォッチリスト（`watchlist_items`）へ★ONで登録する。登録経路は「調査候補」とし、楽天CSVの取込実績・フォルダ名は作らない
2. 既にウォッチリストにある銘柄は既存行に関連付けるだけで、★・フォルダ・メモを上書きしない。保有済みの銘柄は新しい行を作らない（UC-016参照）
3. 調査候補のみから登録した銘柄が後からお気に入りCSVに現れた場合は同じ行を再利用し、CSV経路を追加する。調査経路と確認履歴は保持する
4. 指標は初期状態で「未取得」と表示し、本人が「一括更新」を実行すると既存の指標・シグナル処理で評価する

#### 基本フロー（一括更新）
1. 本人が取込バーの「一括更新」ボタンを押す
2. システムが更新ジョブをキューに投入し、即座に画面へ戻る（同期的に待たせない）。実行状態を `watchlist_refresh_runs` に記録する
3. ワーカーが、直近スナップショットに保有として存在しないウォッチリスト銘柄を対象に、1銘柄ずつ次を実行する
   - 週足株価履歴を取得（JP株: Yahoo Finance相当、US株: Yahoo Finance相当）
   - JP株は業種分類・財務諸表（J-Quants）、US株は業種（Finnhubの`finnhubIndustry`）・ファンダメンタルズ指標（Finnhub）を取得し、`holdings.sector_classification_id` に反映する（CHG-0044、ADR-0020追補。業種の取得に失敗・業種不明の場合は未分類のまま既存値を保持し、銘柄の更新は続行する。業種の取得失敗は`failed_count`に数えない）
   - テクニカル指標（`technical_indicators`）・ファンダメンタルズ指標（`fundamental_indicators`）・過去業績（`financial_statements`、JP株のみ）を UPSERT する
   - 押し目買いシグナル（`BuySignalDeterminationService`）を判定し `watchlist_buy_signals` に保存する（銘柄単位で delete → 再作成）
   - 1銘柄終えるごとに `watchlist_refresh_runs.processed_count` を加算する
   - 銘柄単位の取得失敗はログに記録してスキップし、その銘柄は「取得不可」表示にフォールバックする（他の銘柄の処理は継続する）
4. 画面は実行中、`watchlist_refresh_runs` をポーリングして「更新中 42/150」のように進捗を表示する
5. 完了後、一覧が最新の指標・シグナルで再描画される
6. **保有銘柄の指標は本フローの対象外**（週次CSV取込 UC-001 フロー7で更新済みのため）。`signals` / `buy_signals`（UC-004／UC-010）テーブルには一切書き込まない

#### 基本フロー（一覧の閲覧・★お気に入り）
1. 本人が「新規投資候補」画面にアクセスする
2. システムが未保有のウォッチリスト銘柄を一覧表示する（保有済み銘柄は一覧から除外）
3. システムが各銘柄について、現在値・52週レンジ内位置・同セクター保有比率・押し目買いシグナル件数・財務健全性の総合判定バッジ・主要指標（PER／PBR）・判定チェックリスト（UC-010と同一構造）を表示する。**RSI・ROE・自己資本比率・営業利益率は判定チェックリストのチップ（実測値・基準・達成色を持つ）に統合表示し、素の数値列としては重複掲載しない**（2026-09-12、CHG-0016。財務健全性の内訳サマリ文も同じ理由でチップ側に一本化し、一覧では総合バッジのみ表示する）
4. システムが一覧を透明マルチキーでソートする（下記業務ルール）
5. 本人がフォルダで絞り込む／★お気に入りのみ表示するフィルタを操作できる
6. 本人が銘柄行を展開すると、過去の業績推移・分散への影響コメント・ウォッチステータス／メモ（記録と履歴）を確認・入力できる（UC-006 相当）
7. 本人が★アイコンをクリックすると、その銘柄の `watchlist_items.is_starred` が反転する（お気に入りの手動登録・解除）
8. 本人が銘柄名をクリックすると銘柄詳細（UC-003）に遷移する

#### 業務ルール
- 対象はJP株・US株の個別株のみとする。お気に入りCSVの `CFD` 行、および `USS` に含まれる実質ETF（例: SPYD/HDV/VYM）はファンダメンタルズが疎になり判定チェックリストの財務項目が `unavailable` に寄るが、除外はしない（実測後に除外要否を判断する）
- **一覧に表示するのは未保有銘柄のみ**。「未保有」＝直近の週次スナップショット（`holding_snapshots`）に当該 `holding_id` が存在しない、と定義する。保有済みになった銘柄は自動的に一覧から外れる（`watchlist_items` の行は消さない）
- **候補の絞り込みはしない**。押し目買いシグナル・財務健全性フィルタは表示項目とソートキーに用いるだけで、これらを満たさない銘柄も一覧に残す（ADR-0013 D4。押し目買いシグナルの共通前提〔直近13週で52週高値の85%以内〕は保有銘柄の買い増し向けに設計されており、高値更新中の優良銘柄を取りこぼすため、新規候補では絞り込み条件に使わない）
- 一覧の並び順（おすすめ順）は合成スコアリングを用いず、透明な複数キーでソートする（ADR-0013 D4、ADR-0010 D8 と同方針）: ①財務状態（`passed`→`unavailable`→`failed`）、②押し目買いシグナル件数の多い順、③同セクター保有比率の低い順（分散に効く順）、④52週レンジ内位置の低い順（高値から離れている順）。**2026-10-04、CHG-0045で①②を入れ替え**（従来は押し目シグナル件数が先頭で、財務基準割れの銘柄がシグナル件数だけで財務健全な銘柄より上に来ていたため。ADR-0013 D4追補）
- **判定チェックリスト（`criteria`）**: UC-010（買い増し候補）の判定チェックリストをそのまま流用する（`SignalCriteriaEvaluator::evaluateBuy()`）。配色も UC-010 と同一（達成＝緑系）。整理検討テーブル（UC-011）の赤の単一極性とは別扱い
- **判定チェックリストの業種比較の色付け（CHG-0048、ADR-0026。2026-10-04 Gate 2 承認）**: 買い増し候補（UC-010）と同一構造のため、PERチップの基準の業種相対化（UC-010の業務ルール）、PBRチップの色付け、財務チップの二段階を、UC-010と同じ内容で適用する。押し目買いシグナル（`buy_signals`相当の判定）のPERの条件もUC-010と同じ置き換えになる
- **同セクター保有比率（`overlap_rate`）・分散コメント**: UC-006 と同一で `SectorAllocationCalculator` の `allocation_rate` / `allocation_status` を流用する。対象銘柄のセクター名に一致する保有セクターが無い場合は `overlap_rate=0`
- **ウォッチステータス・メモ**: UC-006 と同一運用（`watch_records` に追記のみ、最新1件を現在ステータスとして表示、銘柄コード単位で履歴表示）。行展開UIから記録する
- **★お気に入り（`is_starred`）**: 画面上で本人が任意に付け外しする。`watch_records`（追記のみで「外す」が表現できない）とは別の独立した boolean として `watchlist_items` に持つ。楽天証券側のお気に入り（CSV由来）とは独立で、CSVから消えても `is_starred` は保持される
- **データ取得タイミング**: お気に入りCSVアップロード時に自動で、または「一括更新」ボタンで手動で、未保有ウォッチリスト銘柄の指標を取得する。保有銘柄の指標は週次CSV取込（UC-001）で更新されるため本機能の対象外。取得は約100〜150銘柄への外部API呼び出しを伴いFinnhub無料枠（60req/分）の律速で数分かかるため、キュー（非同期ジョブ）で実行し画面に進捗を表示する
- **買いシグナルの保存先**: 未保有銘柄は `holding_snapshots` 行を持たないため、`holding_snapshot_id` 外部キーを持つ `buy_signals` を流用できない。`holding_id` をキーとする専用テーブル `watchlist_buy_signals` に保存する（`buy_signals` とは値域が同一。ADR-0013 D3）
- **`signals` / `buy_signals` テーブルには一切書き込まない**。これらは保有銘柄の週次シグナル（UC-004／UC-010）の領分であり、本機能はウォッチ専用テーブルで完結する
- 対象銘柄の指標算出に必要なデータが取得できない場合、該当項目のみ「取得不可（—）」と表示し、他の項目・行の表示は継続する（UC-006 業務ルールと同じ方針、ADR-0009 D5）
- 小口購入額の目安（`suggested_amount`）・NISA推奨（`nisa_recommended`）は UC-008 と同一基準・同一算出（`docs/architecture/data-model.md` の「保留・確定が必要な初期パラメータ値」表を参照）
- CSV再アップロード時は追加のみ（前回あって今回無い銘柄も `watchlist_items` に残す）。楽天側でお気に入りから外した銘柄は `in_rakuten_favorites=false` として一覧に残り、本人が行から★を解除して監視終了として扱える（ウォッチリスト行の物理削除は行わない）
- **ウォッチリストの棚卸し（候補D、2026-09-27）**: 月1回を目安に★付き銘柄を軽量確認し、四半期に1回（3・6・9・12月末を目安）全件を確認する。四半期棚卸しでは最新のお気に入りCSVを取り込み、一括更新の完了後に、各★付き銘柄について「監視を続ける理由・想定する保有期間・前提が崩れる条件」を日付付きのウォッチメモへ追記する。継続理由を説明できない銘柄、投資テーマや分散目的から外れた銘柄は★を外す。決算・業績予想の大幅修正、上場廃止・買収等、投資前提を変えるイベントを把握した場合は定期日を待たず見直す
- **棚卸しの位置づけ**: ★は「継続して監視する銘柄」、★なしは「CSV由来の候補母集団または監視終了」を表す。棚卸しによる自動除外・自動売買判断・DB行の自動削除は行わない。楽天側で解除済みかつ★なしの銘柄も履歴保全のため行を残す。指標が未取得または古い場合は、一括更新を完了してから継続・解除を判断する
- **調査候補（UC-016）経由の登録（CHG-0031）**: 既存の★・フォルダ・シグナル条件・一括更新のトリガーは変えない。CSV再取込でも調査経路と確認履歴を消さない。調査中（未確定）の候補は一括更新の対象に含めない
- 本機能は候補の絞り込み支援であり、最終的な銘柄選定・購入判断は本人が行う（`requirements.md` 1章）
- **一覧テーブルの表示構造（2026-09-12、CHG-0016）**: 縦スクロール時もヘッダー行が、横スクロール時も★・銘柄の2列が常に見えるよう固定表示する。判定チェックリストは1項目=テーブル1列に分解して表示する（UC-010の売買シグナル画面と同一パターン）。判定チェックリストのチップと同じ指標を素の数値列としても表示すると情報が完全重複するため、重複する列（RSI・ROE・自己資本比率・営業利益率・財務健全性の内訳サマリ文）は一覧から外す（詳細は `docs/product/ui-guidelines.md`「テーブル」節）

### UC-013: ポートフォリオ分類ダッシュボード

**Actor**: 本人
**前提条件**: CSV取込（UC-001）が1回以上完了し、直近の週次スナップショットに保有銘柄が存在する
**関連要件**: F-013（ADR-0014）

> **位置づけ**: UC-004（利確検討）/ UC-005（セクター配分）/ UC-010（買い増し候補）/ UC-011（整理検討）/ UC-012（ウォッチリスト）の抽出結果を**銘柄起点で1つのバケツに束ね直し**、ポートフォリオ全体を「減らす / 保つ / 増やす」の構成比とともに俯瞰する画面。新しい抽出条件・閾値は設けず、既存UCの対象抽出ロジックをそのまま再投影する（ADR-0014 D2）。第1段階は表示レイヤー完結（DBスキーマ変更なし・永続化なし）。先週からの遷移表示は第2段階（別CR）。UC-009（取込後サマリーレポート）の旧・上位10〜20件レコメンドを置き換える画面でもある（2026-09-17確定、ADR-0014 D9）。

#### 基本フロー
1. 本人がグローバルナビの「サマリーレポート」タブを開く
2. システムが画面最上部に「分類俯瞰」セクションを表示する（**2026-09-17確定: UC-009の旧・上位10〜20件レコメンドはこのセクションに完全に置き換わり、併存しない**）
3. システムが直近スナップショットの各保有銘柄を、下記の優先順位でちょうど1つのバケツに分類する

#### 業務ルール
- **バケツ定義（ADR-0014 D2）**: 以下6種。所属条件はいずれも既存UCの対象抽出条件の再利用であり、本UCで新しい閾値・判定ロジックを定義しない
  - `core_accumulation`（保つ）: `instrument_type` が ETF または 投資信託、あるいは保有がすべて NISAつみたて投資枠
  - `loss_review`（減らす）: UC-011 の対象抽出条件（含み益率 ≤ 整理検討ライン、叩き台 -20%）
  - `take_profit`（減らす）: UC-004 の対象抽出条件（含み益率 > 動的利確ライン、かつ シグナルあり or 高水準モード該当）
  - `add_on`（増やす）: UC-010 の対象抽出条件（押し目買いシグナルあり ＋ 財務 `passed`/`unavailable` ＋ 全シグナル共通の前提条件）
  - `hold`（保つ）: 上記いずれにも該当しない個別株（JP/US）
  - `new_entry`（増やす）: UC-012 の未保有ウォッチリスト銘柄。**評価額構成比には算入しない**（保有していないため）。参考リストとして併置する
- **優先順位（排他解決、ADR-0014 D3、確定）**: 1銘柄はちょうど1つのバケツに属する。`core_accumulation` を `instrument_type`／口座区分で最初に確定し、以降は `loss_review` > `take_profit` > `add_on` > `hold` の順で最初に一致したバケツを採る。`take_profit` と `add_on` は ADR-0007 により元データで既に排他。`take_profit` と `loss_review` は含み益・含み損が同時成立しないため競合しない
- **落ちなかったバケツの注記（ADR-0014 D3、確定）**: `loss_review` に分類されたが押し目買いシグナルも発生している銘柄は、行内に「押し目買いシグナル発生中・買い増し候補にも掲載」と注記する（UC-011 の既存挙動と同一）。情報自体は抑制しない
- **リバランスの扱い（ADR-0014 D4、確定：バッジ止まり）**: セクター偏りは個別銘柄のバケツを動かさない。偏り警告セクターに属する銘柄の行に「偏り警告セクター」バッジを付し、画面上部に `sector_overweight_summary` を表示する。セクター単位の売却額目安は従来どおり UC-005 で提供する。`rebalance` サブバケツは作らない
- **評価額構成比（ADR-0014 D6）**: 各バケツの `Σ market_value ÷ 全保有 Σ market_value`。`market_value` は UC-004/UC-010 と同じ算出（保有数量 × 現在値、US株はCSVヘッダーの参考為替レートで円換算済み、投資信託は評価額）。基本は全口座ビューとし、課税口座のみビューは第2段階。`new_entry` は分母・分子に含めない
- **キープのヘルスラインと要観察（ADR-0014 D5、確定：第1段階から表示）**: `hold` バケツの各行に、含み益率・RSI帯・財務健全性の合否・相対力〔対市場〕の符号を簡易表示する。加えて「要観察（`hold_watch`）」フラグ（財務 failed・相対力継続マイナス等での早期警戒。既存の評価値の組み合わせのみで判定し、新しい閾値は作らない）を**第1段階から**表示する。「好調で優先的に強調したいキープ銘柄」の判定は、判定基準（相対力・RSI健全域等の組み合わせ）が現時点でどのUCにも存在せず新規閾値の発明になるため本CRでは見送り、`docs/product/accuracy-improvement-backlog.md` に将来検討事項として記録する
- **バケツ内ソート順（ADR-0014 D10、2026-09-17新規確定）**: 新しい閾値・重み付けは作らず、既存の算出値のみを用いる
  - `add_on`：既存流用（`ShowBuySignalListAction`）。①財務健全性（`passed`優先）②買いシグナル数（多い順）③含み益率（低い順）
  - `loss_review`：既存流用（`ShowLossReviewListAction`）。①押し目買いシグナル有無（無→優先）②財務ランク（failed優先）③テクニカル達成数（多い順）④含み損率（深い順）
  - `new_entry`：既存流用（`ShowWatchlistAction`）。①財務健全性②押し目買いシグナル数（多い順）③同セクター保有比率④52週レンジ内位置（2026-10-04、CHG-0045でUC-012に合わせ①②を入れ替え）
  - `take_profit`：**新規設計**。①シグナル数（多い順）②判定チェックリストのテクニカル達成数（多い順）③含み益率（高い順）。UC-004本体（`ShowSignalListAction`）に実装し、UC-004画面自体もこの並び順になる（2026-09-17新規追加、下記「対象範囲」参照）
  - `hold`：**新規設計**。① `hold_watch` フラグが立っている銘柄を先頭に ② 残りは含み損益率が低い順
  - `core_accumulation`：**新規設計**。評価額（`market_value`）が大きい順
  - セクター偏りサマリ：**新規設計**。配分率の超過幅（`allocation_rate` − 70%）が大きい順
- **売買シグナル画面へのキープ表の掲載（2026-10-01、CHG-0028、Gate2承認済み）**: 売買シグナル画面（UC-004/UC-010/UC-011の3テーブル）の末尾に、`hold` バケツの銘柄を4つ目のテーブル「キープ（ホールド）」として表示する。`core_accumulation`（積立・インデックス）は含めない。データは本UCの分類結果（`hold` バケツ）をそのまま再利用し、新しい抽出条件・閾値は設けない。列は 銘柄 → 評価額（`market_value`）→ 含み損益率 → 要観察（`hold_watch` バッジ）→ ヘルスライン（`health_line`）→ セクター とする（`bucket_reason` は `hold` では固定文言のため列にしない）。表の上に補足説明文「いずれのシグナルにも該当しない保有銘柄です（積立・インデックスコアは除く）」を表示する（2026-10-01、実装時に追加）。並び順は他3テーブルと共通の切替（CHG-0027）に従い、既定は評価額順、おすすめ順は上記 `hold` のバケツ内ソート順（要観察が先頭→含み損益率の低い順）。画面のみの変更で、JSON API・DBスキーマ・分類ロジック（バケツ所属・優先順位）は変更しない。行データにセクター名（`sector_name`）を1項目追加する（既存キーは不変）
- **キープ表の列拡充と判定チェックリストの両方向色分け（2026-10-04、CHG-0046、Gate2承認済み）**: 売買シグナル画面のキープ表を、他3テーブルと同じ「固定列＋判定チェックリスト（チップ1項目＝1列）」形式に拡充する。固定列は 銘柄（保有銘柄詳細へのリンク。銘柄名の下に達成数サマリ「利確寄り n／押し目寄り m」「財務 x/4」）→ 評価額 → 含み損益率 → 要観察（`hold_watch` バッジと該当理由：財務健全性 基準割れ／相対力マイナス／含み損-15%以下）→ 財務健全性（他3テーブルと同じ内訳サマリ文。未取得時は「財務指標 取得不可」、基準割れ時は「財務健全性 基準割れ」バッジ）→ セクター とする。ヘルスライン列は内容がチップと重複するため廃止する（ui-guidelines.md CHG-0016の教訓）。判定チェックリストはテクニカル10項目（含み益率／RSI／52週高値からの下落率／52週安値からの距離／MA20乖離率／MACD-シグナル線／相対力〔対セクター優先、未算出時は対市場〕／PEGレシオ／PER／PBR）と財務4項目（ROE／自己資本比率／成長率／営業利益率）。キープはシグナルの方向を持たないため、テクニカル各項目を利確検討（UC-004）と買い増し候補（UC-010）の**既存閾値の両方**に照らし、利確側を満たす＝黄（利確寄り）、買い増し側を満たす＝緑（押し目寄り）、あと一歩はそれぞれ淡色、どちらでもない＝グレー、データなし＝薄いグレーで表示する。閾値は既存定数を流用し新設しない：含み益率 利確≥利確検討と同じ利確ライン（`TakeProfitThresholdEvaluator`。通常+20%、シグナル0件かつ財務健全性合格の高水準モードは+150%。基準ラベルも実際のラインを表示。片側。2026-10-04 `/review` 指摘で「一律+20%」から訂正）／RSI 利確≥70・押し目≤30／52週高値からの下落率 利確≤-10%（片側）／52週安値からの距離 押し目≤+10%（片側）／MA20乖離率 押し目≤-10%（片側）／MACD-シグナル線 利確<0・押し目>0／相対力 利確<0（片側）／PEGレシオ 利確≥2.0・押し目≤1.0（正の値のみ）／PER・PBR は基準なしの参考表示（業種基準値との比較色はCHG-0034の実装後に別途検討）。財務4項目は利確検討・買い増し候補と同じ向き（健全＝緑）。色分けは表示のみで、バケツ所属・シグナル判定・`hold_watch` 判定・並び順は変更しない。DBスキーマ・JSON API・`ClassifyHoldingsAction` の出力は変更しない（行の拡充は `ShowHoldListAction` 側で行う）。分類と行の拡充の間に取り込みが重なって最新スナップショットに行が見つからない場合も画面はエラーにせず、指標を「—」として表示する（2026-10-04 `/review` 指摘）

### UC-014: シグナル結果の前向き記録・集計

**Actor**: 本人
**前提条件**: CSV取込（UC-001）またはウォッチリストの一括更新（UC-012）で、週次のシグナル判定が1回以上実行済み
**関連要件**: F-014（ADR-0017）

> 本UCは判定ロジックを変えない。既存の判定（UC-004 利確検討／UC-010 買い増し／UC-012 ウォッチリストの押し目買い）が**実際に出したシグナル**を記録し、その後の値動きで「当たっていたか」を測るだけである。過去データで判定をやり直すこと（バックテスト）は行わない（`requirements.md` 2章OUT）。

#### 基本フロー（記録: 自動、画面操作なし）
1. CSV取込（UC-001）の分析処理、またはウォッチリスト一括更新（UC-012）が銘柄ごとに週足株価（104週）と市場指数（日経平均・S&P500）の週足を取得する（既存処理）
2. システムが取得した週足を週次価格履歴として保存する（同じ週の値は最新の取得値で上書き）
3. システムが既存どおりシグナルを判定・保存する（既存処理、変更なし）
4. システムが出たシグナルごとに、発生週・シグナル種別・発生時点の判定根拠値を「シグナル発生記録」として追記する（同じ銘柄・種別・週の記録は1件のみ）

#### 基本フロー（集計の閲覧）
1. 本人が売買シグナル画面（UC-004、`/signals`）のタイトル下の「シグナル検証」タブからシグナル検証画面（`/signal-outcomes`）にアクセスする（2026-10-03 上部リンクから切替タブに置換）
2. システムがシグナル種別×評価期間（+4週／+13週／+26週）ごとに、発生件数・結果到来件数・平均超過リターン・t値・的中率・中央値・判定区分を一覧表示する
3. 本人が行を展開すると、その種別の個別発生（銘柄・発生週・発生時点の根拠値・各期間の超過リターン）を新しい順に確認できる

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| source（絞り込み） | string | 任意 | `take_profit` / `buy` / `watchlist_buy` のいずれか。未指定なら全件 |
| market（絞り込み） | string | 任意 | `jp` / `us` のいずれか。未指定なら全件 |

#### 出力（集計行）
| 項目 | 型 | 説明 |
|---|---|---|
| source | string | `take_profit`（利確検討）／`buy`（買い増し）／`watchlist_buy`（ウォッチリスト押し目買い） |
| signal_type | string | 既存のシグナル種別（`signals`／`buy_signals`／`watchlist_buy_signals` の値域と同一） |
| horizon_weeks | integer | 評価期間（4／13／26） |
| occurrence_count | integer | 発生件数 |
| matured_count | integer | 評価期間が経過し結果が出た件数 |
| matured_week_count | integer | 結果が出た発生の発生週の数（同じ週の発生は1週と数える。CHG-0020 Cycle5） |
| mean_excess_return | decimal | 平均超過リターン（%）。発生週ごとに超過リターンを平均し、その週平均をさらに平均した値（CHG-0020 Cycle5） |
| t_value | decimal | 週平均（1週＝1標本）から求めた平均超過リターンのt値（matured_week_countが2週未満なら null） |
| hit_rate | decimal | 的中率（%）。個々の発生のうち、買い系は超過リターン>0、利確系は超過リターン<0の割合 |
| median_excess_return | decimal | 個々の発生の超過リターンの中央値（%） |
| verdict | string | `working`（機能している）／`pending`（判断保留）／`not_working`（機能していない）／`suspicious`（異常を疑う） |

#### 業務ルール
- **超過リターンの定義**: 発生週の終値から+N週後の終値までの騰落率から、同期間の指数騰落率を引いた値。JP株は日経平均、US株はS&P500を使う（UC-003の相対力〔対市場〕と同じ対応）。株価・指数とも週次価格履歴の同一系列から取り、CSVの現在値（未調整）とは混ぜない
- **株価の前提**: 週次価格履歴は分割遡及調整済み・配当は含まない価格（ADR-0017 D5）。指数も配当を含まない価格指数のため、配当を除いた価格同士の比較になる
- **同じ週の発生は1件として判定する（2026-10-03 本人承認、CHG-0020 Cycle5）**: 同じ週に出たシグナルは同じ相場の動きにまとめて左右され、互いに独立しない。そのまま件数を数えるとt値が過大になり、1週分の相場で「機能している／していない」を言い切ってしまう（実例: 導入直後、利確検討`week52_high_pullback`の+4週が8/24週の30件だけで`not_working`になった）。そのため平均超過リターン・t値・判定区分は、発生週ごとの平均（1週＝1標本）から求める。中央値・的中率は個々の発生の値のまま表示する（「何件中何件当たったか」の実感に合わせるため）
- **期待される符号**: 買い系（`buy`／`watchlist_buy`）はプラス、利確系（`take_profit`）はマイナス（利確シグナル後に市場を下回るなら「売って正解」だったとみなす）
- **判定区分（事前固定、ADR-0017 D7）**:
  - `suspicious`（異常を疑う）: 平均超過リターンの絶対値が過大（+26週で30%超、+13週で20%超、+4週で10%超）。他の区分より優先して表示し、成功ではなくデータ不備・計算誤りを疑う
  - `pending`（判断保留）: matured_countが30件未満、matured_week_countが評価期間の3倍の週数未満（+4週は13週〔最低13週〕、+13週は39週、+26週は78週。連続する週の評価期間が重なるため、重なりのない相場局面を約3回分見てから判定する。CHG-0020 Cycle5、2026-10-03 本人選択）、またはt値の絶対値が2.0以下
  - `working`（機能している）: 符号が期待通りかつt値の絶対値が2.0超。蓄積が3年未満の間は「（暫定）」を付けて表示し、3年以上たまった後は「直近3暦年のうち2年以上で年平均の符号が一致」も満たす場合のみ `working`
  - `not_working`（機能していない）: 符号が期待と逆でt値の絶対値が2.0超、または3年以上たまった後に年ごとに符号が反転している
- 評価指標にRMSE・決定係数は使わない
- **残る限界（画面の注記に表示する）**: +13週・+26週では、連続する発生週の評価期間が重なるため、週平均どうしも完全には独立しない。重なりを補正する手法（Newey-West等）は使わず、判定は控えめに読む前提とする
- 評価期間が経過していない発生は集計から除き、「結果待ち n件」として件数だけ表示する
- **確定とみなす週（2026-10-03 本人承認、CHG-0020 `/review`指摘対応）**: 週次価格履歴はCSV取込のときにしか更新されないため、最後の取込が週の途中なら、その週の終値は途中の値である。そこで、評価期間の終点の週が「今週」または「その市場の指数の週次価格履歴で最新の週」以降なら「結果待ち」とし、それより前の週だけを確定値として集計する。取込を飛ばした週も、次の取込で埋まるまで「結果待ち」のままにし、「算出不可」にはしない（算出不可は、確定済みの週なのに株価・指数が欠けている場合に限る）
- 週次価格履歴が欠けていて超過リターンを計算できない発生（上場廃止・銘柄コード変更・取得失敗など）は集計から除き、「算出不可 n件」として件数だけ表示する
- 既存6スナップショット（2026-08-28〜09-20）のシグナルは、本機能の導入時に一度だけ発生記録へ移送する。これらは判定根拠値が残っていないため、個別発生の展開表示で根拠値欄を「記録なし」と表示する
- 本画面の結果をもって自動で閾値・判定ロジックを変更しない。閾値や前提条件の変更は、本画面の実測を根拠に別CRとして本人が判断する
- **画面配置（2026-09-27 Gate2確定）**: 新ルート`/signal-outcomes`とし、売買シグナル画面（`/signals`）の上部にリンクを置く（2026-10-03 切替タブに置換、下記参照）。グローバルナビのタブは増やさない（`docs/product/ui-guidelines.md` のタブ数6を維持）

- **根拠値の表示（2026-10-03 本人承認、CHG-0020 Cycle5）**: 個別発生の根拠値は日本語の項目名で、数値は小数2桁に丸め、真偽値は「はい／いいえ」で表示する

#### 業務ルール
- **計算窓**: 直近52週の週次リターン（2026-09-30 本人確認）。窓の終点は計算対象候補の銘柄が持つ週足の最新週とし、窓内の53週の終値がすべてそろった銘柄だけを計算対象にする（銘柄ごとに期間を変えない。ADR-0019 D1）
- **計算対象**: 最新スナップショットの保有のうち個別株（`instrument_type`=`stock`）。ETF・投資信託は週足を保存していないため計算対象外とし、「株式以外」として一覧に出す。窓内の週足が1週でも欠ける銘柄（上場から52週未満・直近の取得失敗など）は「週足不足」として一覧に出す

- **リターンの通貨**: 各銘柄の現地通貨建て（JP株は円、US株はUSD）。円建ての為替要因は含まない。この旨を画面に注記する（ADR-0019 D5）
- **株価の前提**: 週次価格履歴は分割遡及調整済み・配当は含まない価格（ADR-0017 D5）。SOX指数も配当を含まない価格指数
- **指標の定義**: ADR-0019 D3 のとおり。PC1寄与率は相関行列、実効ベット数は共分散行列で計算する
- **推定誤差の注記**: 計算対象の銘柄数が52週を上回る場合、相関・PC1寄与率・実効ベット数の推定誤差が大きい旨を画面に注記する
- **指標ごとの判定（ADR-0021、2026-10-01 本人承認。ADR-0019 D6を置き換え）**: PC1寄与率・実効ベット数・上位5銘柄ウェイト・ポートフォリオの対SOXベータの4指標に、それぞれ3段階の判定（分散OK／やや集中／集中、緑・黄・赤のバッジ）を付ける。しきい値は叩き台で、境界値は悪い側に含める — PC1寄与率: 25%未満／25〜45%未満／45%以上、実効ベット数: 8以上／3以上8未満／3未満、上位5銘柄ウェイト: 30%未満／30〜50%未満／50%以上、対SOXベータ（絶対値）: 0.5未満／0.5〜0.8未満／0.8以上。算出できない指標には判定を付けない。相関行列は値に応じた背景色のヒートマップにする（0.7以上＝濃い赤、0.5以上＝赤、0.3以上＝薄い赤、−0.3より大きく0.3未満＝色なし、−0.3以下＝緑。対角と算出不可のセルは色なし）。色だけでなくラベルの文字も添える。**5指標を1つのスコアにまとめたり、銘柄のランキングを作ったりはしない**（ADR-0019 D7を維持）。銘柄別ベータ・計算対象数・カバー率には判定を付けない
- **判定の丸め（ADR-0021 D2、2026-10-03 `/review`指摘）**: 判定と相関の区分は、画面に表示する桁に丸めた値で行う（PC1寄与率・上位5銘柄ウェイトは小数1桁、実効ベット数・対SOXベータ・相関は小数2桁）。表示が「25.0%」なら「やや集中」になり、表示と色が食い違わないようにするため。判定の対象でない指標・非有限値（NaN・無限大）は判定なし（null）とする
- **ヒートマップの凡例**: 相関行列の近くに「赤＝同じ方向に動く（濃いほど強い）／緑＝逆方向に動く／色なし＝ほぼ無関係」の1行を表示する
- **リバランス提案はしない**: 売却・購入の提案はUC-005の役割であり、本画面は値を見せるだけとする
- 相関行列は評価額上位20銘柄のみ表示する（2026-09-30 本人確認）。全銘柄の行列は保有が多く画面で読めないため。表示しなかった銘柄数を添える
- **画面配置（ADR-0021 D5で改訂、2026-10-01）**: 新ルート`/concentration-dashboard`とし、セクター配分画面（UC-005、`/sector-dashboard`）と集中度画面の**両方のタイトルの下に「セクター配分 | 集中度」の切替（サブタブ）を同じ見た目で置く**。いまの画面が選択中として強調される。グローバルナビのタブは増やさない（`docs/product/ui-guidelines.md` のタブ数6を維持）。集中度画面でも、グローバルナビの「セクター配分」が選択中になる。セクター配分画面上部にあった文字リンクは切替に置き換える
- 値はアクセスのたびに週次価格履歴から算出し、保存しない

| 主張と根拠、証拠段階、反証・未確認事項 | 主張ごとに根拠URLと「未確認／確認済み／不一致」を持つ。研究・採択、製品、規制承認、導入計画、稼働、受注、売上を区別。見つからない売上等は未確認のまま残す |

#### 基本フロー（記録・確認）

1. 本人が「新規投資候補」の「調査候補」を開き、公開記事・動画等から見つけた企業を入力する。登録済み候補にない法人も、銘柄コードが未確定のまま法人名と必須の出典情報で記録できる。
2. システムが同一URL・既知の元発表ID・既知の上場主体に該当する記録を示す。本人が既存の出来事へ関連付けるか、異なる出来事として記録するか確認する。同じ元発表と法人の組は重ねて作らず、追加の発見経路を残す。タイトル類似だけで別発表を統合しない。
3. 本人が紹介元から一次資料へ戻り、主張・元発表日・企業の役割を確認する。紹介元の主張に根拠がなければ未確認、不一致があれば反証として残す。URLの存在だけでは確認済みにしない。
4. 本人が上場主体と市場・銘柄コードを公式資料で同定する。非上場、同名法人、親子関係不明、上場廃止・コード変更の疑いは保留にする。日米以外にしか上場していない企業は対象外とし、メモを保持する。
5. システムが最新のアプリ内ウォッチリスト、直近に取り込んだお気に入りCSV、保有スナップショットと照合し、それぞれの参照時点と結果を示す。比較元がない場合や同定未了の場合は未登録と断定しない。
6. 本人が「調査継続」「保留」「見送り」を選ぶ。確認事項が揃った場合は次の監視登録へ進める。銘柄や証拠の入力だけでは監視登録しない。

#### 基本フロー（監視への受け渡し）

1. 本人が「監視に追加」を選ぶと、上場主体・市場・銘柄コード、企業の役割、元資料・元発表日、確認済みの主張、反証・未確認事項、最新の重複照合とその参照時点をまとめた確認欄を表示する。
2. 上場主体の同定、テーマとの関係、企業の役割、少なくとも1件の一次資料により確認済みの事実と元発表日、反証の確認記録が必須。「未確認事項が残る」こと自体は拒否理由にしないが、売上等の未確認を確認済みと表現しない。本人が資料と照合時点を確認して確定する。
3. 確定時に再照合する。未保有・未登録なら銘柄マスタとウォッチリストへ登録し、調査候補・確認した版・登録日時を関連付ける。登録経路は「調査候補」とし、楽天CSVの取込実績やフォルダ名を捏造しない。新規登録の★はONとする。
4. 既にウォッチリストにあればその行に関連付け、★・フォルダ・メモを上書きしない。★がOFFなら「既存候補に関連付け済み・監視は未選択」と案内し、調査状態は調査中に保ってUC-012での★選択へ案内する。保有済みなら新しいウォッチリスト行は作らず、保有銘柄の確認へ案内する。二重クリック・再送でも重複登録しない。
5. 登録後はUC-012へ遷移できる。初期状態の指標は「未取得」と表示し、本人がUC-012の「一括更新」を実行すると既存の指標・シグナル処理で評価する。調査中の候補を市場データの一括取得対象に含めない。

キャンセル時は登録しない。確認欄の表示後に候補・根拠・上場主体が更新された場合は旧版で確定させず、最新内容を表示して再確認する。登録または関連付けと履歴記録の一部だけを成功扱いにしない。

### UC-017: 週次売買履歴の取込と保有変化の照合

> **Gate 2承認済み（2026-10-04、本人）**。詳細・根拠・計算例は[CHG-0033 UC草案](trade-decision-effect-gate2-uc-draft.md)。本人指示によりモックは作成しない（既存3モックは旧仕様の参考資料）。

**Actor**: 本人（認証済み）。**関連要件**: F-017、CHG-0033。**関連UC**: UC-001。

**目的**: 楽天証券の国内株・米国株の全期間売買履歴を取り込み、週ごとの保有株数を復元して保有CSVと照合する。

**入力**: 国内株・米国株の全期間売買履歴CSV（同じ週の2本組）。UC-001の取込画面から履歴専用の取込画面へリンクする。履歴が未提出の週もUC-001の保有CSV取込は続ける。資産残高CSV・特定口座損益CSVは必須にしない。

**基本フロー**:

1. 本人が2本のCSVを選び、対象期間と行数のプレビューを確認する（プレビューは状態を変えない）。
2. システムが買付・売付・入庫・出庫・積立・分割入庫に分類する。元CSV内の完全に同じ内容の行は出現回数で保持する。
3. 全期間履歴の再提出では既存行を再登録せず、新規行と消失・変更した行を区別して表示する。取引ID・約定時刻がないため、差し替えの疑いは確認待ちにする。
4. 本人が確定すると履歴を保存し、週ごとの保有株数を復元して、市場・銘柄・口座区分ごとに最新の保有CSVと照合する。CSVに約定時刻がないため、約定日Dの行は、保有CSVの取込時刻がその市場のD日の取引終了（国内株 15:30 東京、米国株 16:00 ニューヨーク）以降のときだけ積み上げに含める（日付だけで判定すると、市場が開く前の取込で当日の約定まで数えて不一致になるため。2026-10-04 本人承認）。投資信託は対象外。
5. 「照合済み／保有側のみ変化／履歴側のみ変化／分割・移管等の確認待ち」の件数と明細を表示する。数量減少だけで売却と確定しない。

**異常時**: 形式違い・必須列欠落・数値／日付不正は確定前にエラー表示。片方だけの提出や過去行の消失・変更では履歴を黙って削除しない。数量不一致は成功扱いで隠さない。

**状態変更・権限**: 本人のみ取込を確定できる。過去取引の削除・修正は通常フローに含めない。

### UC-018: 売買の対ガチホ比較と成績

> **Gate 2承認済み（2026-10-04、本人）**。算出式・境界・計算例は[CHG-0033 UC草案](trade-decision-effect-gate2-uc-draft.md)の「実装する機能と段階」決定1〜5。

**Actor**: 本人（認証済み）。**関連要件**: F-017、CHG-0033、ADR-0024。**関連UC**: UC-017、UC-014（週足を共用。判定・画面・閾値は変更しない）。

**目的**: 実際の売買がガチホより良かったかと、株式部分の成績が年率20％目標・25％上位目標に届いたかを、手入力なしで別々に示す。

**前提**: UC-017で履歴取込済み。週足はADR-0024の共通追跡と初回一括補完（2021-07以降）で供給する。理由・区分・代替先の手入力は設けない。

**基本フロー**（画面「売買の振り返り」の「成績」「売買一覧」タブ）:

1. **成績**: 国内・米国株の株式部分について、売買の受渡金額を資金の出入りとした直近52週の時間加重リターン（修正ディーツ法・配当除く）を表示し、「20％未達／20％達成・25％未達／25％達成」を判定する。入庫・出庫は時価で資金の出入り、分割入庫は株数調整のみ。52週未満は期間目標との参考比較に留める。
2. **対ガチホ**: 52週前の保有を持ち続けた場合の変化率との差を、年率判定と別項目で表示する（例: 実績22％・ガチホ30％なら「20％達成・25％未達、対ガチホ−8ポイント」）。
3. **過去の暦年**: 同じ方法で一覧する。2022年は判定しない、2023年は国内株のみ、2024年は米国株8月以降を含む、と対象範囲を明記する。
4. **売却単独**: 売却数量を持ち続けた場合と、売却代金を現金で持った場合を+4／+13／+26週で比較する。
5. **推定乗換え（参考）**: 同じ市場で売却から5営業日以内の買付（定型以外）に売却代金を約定日順に割り当て、割り当てた買付の評価額＋余った現金と、元の株を持ち続けた場合を比較する。売却単独・成績と合算しない。
6. **買付**: 推定乗換えに割り当てなかった新規資金部分を、買付前週末の同じ市場の保有構成比どおり（買った銘柄自体を含む）に買い増した場合と比較する。指数（日経225／S&P500）との差は参考として併記する。
7. 各行に比較相手・評価日・価格／為替の出典・費用の扱い・「価格・売買コストベース」を表示する。売買前に保存済みのシグナル・指標・保有状況を自動で紐付けて表示し、本人の動機とは断定しない。

**業務ルール**: 区分は「定型（CSVの取引区分「積立」の明示あり）」と「その他」の2区分。定型は推定乗換え・買付比較・状況別集計から外し、年率では資金出入りとして中立化する。年率目標をシグナル閾値や売買指示に使わない。+4／+13／+26週の結果を合計しない。

**異常時**: 評価日未到来は「結果待ち」。価格欠損・上場廃止・ティッカー変更・分割情報欠損・為替欠損・照合未解決は理由付きの「算出不可」。欠損を0にしない。価格欠損銘柄の評価額比率が5％を超える期間は年率・対ガチホを判定保留にする。同じ市場に保有がない週の買付は比例買増しを算出不可とし、指数比較のみ表示する。

**状態変更・権限**: 本人のみ閲覧。取込・自動更新に伴い、比較の根拠（売買履歴・推定乗換えの割り当て・状況記録）を保存する。比較結果は根拠から読み取り時に算出し、過去の状況を最新値で上書きしない（ADR-0027）。入力画面は設けない。

### UC-019: 売買時の状況別の振り返り

> **Gate 2は保留**（2026-10-04 本人承認の進め方）。UC-018の段階3まで実装し、実際のクラスタ数・結果待ち・算出不可の件数を見てから承認する。本文は現時点の案。

**Actor**: 本人（認証済み）。**関連要件**: F-017。**関連UC**: UC-018。

**目的**: どんな状況（シグナル・価格系指標・保有状況）で売買すると結果が良かったかを探索的に振り返る。

**基本フロー**（画面「売買の振り返り」の「状況別」タブ）:

1. 状況の出所（当時記録／事後再計算〔価格系〕）、対象件数（定型は除外件数として別表示）、比較可能・結果待ち・算出不可の件数を表示する。
2. 状況・市場・評価期間ごとに、対ガチホ差の件数・中央値・分布と個別売買へのリンクを表示する。区分の境目は既存シグナルの閾値を使い、結果を見て探さない。
