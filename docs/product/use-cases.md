### UC-001: 公開サイト・コンテンツ閲覧

**Actor**: サイト訪問者（匿名）
**前提条件**: なし（未認証で閲覧可能）
**関連要件**: F-001

#### 基本フロー
1. 訪問者がトップページまたは記事/アクティビティ詳細ページへアクセスする
2. システムが公開済み（`status = published`）のコンテンツのみを表示する
3. 訪問者が記事一覧・アクティビティ一覧・モデルプラン・FAQ・規約類のページを回遊する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| slug（記事/アクティビティ詳細） | string | 任意（URLパスパラメータ） | 存在するslugであること |
| カテゴリフィルタ（一覧） | string | 任意 | 定義済みカテゴリ値のみ |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 記事一覧/詳細 | Article[] | 公開済み記事のみ。SEOタイトル・ディスクリプションを含む |
| アクティビティ一覧/詳細 | Activity[] | 公開済みアクティビティのみ（料金帯・所要時間・注意事項含む） |
| モデルプラン | 静的/CMSコンテンツ | アンヘレス4泊5日等の代表プラン紹介 |

#### 業務ルール
- 非公開（下書き）状態の記事・アクティビティは一般訪問者に表示しない
- ナイトライフ情報は一次資料4.4節「提供する範囲」のみ掲載し、「提供しない範囲」の内容は掲載しない
- サイト上の表現は一次資料15.1節の「推奨/避ける」表現ガイドラインに従う

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 存在しないslugへのアクセス | 404 | ページが見つかりません |
| 非公開コンテンツへの直接アクセス | 404 | ページが見つかりません（公開済み記事と同じ404を返し、存在有無を推測されないようにする） |

#### 権限
- 訪問者（未認証）: 閲覧のみ可
- 編集・作成・削除は不可（UC-009, UC-008参照）

### UC-002: 旅行相談申込（事前アンケート含む）

**Actor**: サイト訪問者（見込み客）
**前提条件**: なし（未認証）。相談申込ページへアクセスしていること
**関連要件**: F-002

#### 基本フロー
1. 訪問者が「Zoom相談申込」ページを開く
2. 事前アンケート項目を入力する（下記「入力」参照）
3. Zoom希望日時を選択する
4. 利用規約・免責事項に同意する
5. 訪問者が申込を送信する
6. システムが入力内容を検証し、`Consultation` と `TravelProfile` を作成、`Consent` を記録する
7. システムが申込完了メールを送信する（UC-004）
8. システムが管理者へ通知する
9. 完了ページを表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| 氏名 | string | 必須 | 1〜100文字 |
| メールアドレス | string | 必須 | メール形式 |
| 電話番号 | string | 必須 | 電話番号形式 |
| 年齢帯 | enum | 必須 | 定義済み選択肢 |
| 性別 | enum | 必須 | 定義済み選択肢 |
| 旅行人数 | integer | 必須 | 1以上 |
| 出発日／帰国日 | date | 必須 | 出発日 ≦ 帰国日、出発日は本日以降 |
| 出発空港／到着空港 | string | 必須 | - |
| フライト番号／到着時刻／帰国時刻 | string | 任意 | - |
| フィリピン渡航回数 | integer | 必須 | 0以上 |
| 海外旅行経験 | enum（初回/少ない/普通/多い） | 必須 | 定義済み選択肢 |
| 英語力 | integer（1〜5） | 必須 | 1〜5の範囲 |
| 旅行目的 | string | 必須 | - |
| 予算帯 | enum（〜15万/15〜20万/20〜30万/30万以上） | 必須 | 定義済み選択肢 |
| 希望ホテルエリア | string | 任意 | - |
| 希望アクティビティ | enum複数選択（Puning/ATV/バギー/乗馬/セスナ/カート/ゴルフ/スパ/マニラ観光/クラーク観光/ショッピング/グルメ） | 任意 | 定義済み選択肢のみ |
| Grab利用経験・不安 | string/enum | 任意 | - |
| 空港送迎の希望有無 | boolean | 必須 | - |
| 深夜移動予定 | boolean | 必須 | - |
| 緊急連絡先 | string | 必須 | - |
| 体力／夜型度／ナイトライフ関心度 | enum（低/普通/高、なし/少し/高い等） | 任意 | ナイトライフ関心度は必須化しない（[[project-summary]] プライバシー方針） |
| 自由記述（不安なこと／絶対やりたいこと／避けたいこと／その他要望） | text | 任意 | 最大2000文字程度 |
| Zoom希望日時 | datetime（複数候補可） | 必須 | 未来日時であること |
| 利用規約同意 | boolean | 必須 | true であること |
| 免責事項同意 | boolean | 必須 | true であること |

> 全項目の正式定義は一次資料 10節「事前アンケート仕様」を参照。

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 申込完了メッセージ | string | 完了ページに表示 |
| Consultation.status | enum | `pending`（初期状態） |

#### 業務ルール
- 利用規約・免責事項への同意は必須（同意なしでは送信不可）
- ナイトライフ関心度・飲酒習慣等の機微になり得る項目は任意項目とし、必須化しない（一次資料14.5節、`docs/ai-context/project-summary.md` プライバシー方針）
- 送信された `TravelProfile` の内容は管理者のみ閲覧可能（UC-006）
- 同意記録（`Consent`）には同意日時・同意バージョン・IPアドレスを保存する

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 必須項目未入力 | 422 | 入力内容に誤りがあります（項目別エラーメッセージ） |
| 利用規約/免責事項未同意で送信 | 422 | 利用規約と免責事項への同意が必要です |
| 出発日が過去日 | 422 | 出発日は本日以降の日付を指定してください |
| メール送信失敗（UC-004） | - | 申込自体は完了扱いとし、管理者へ送信失敗を通知（キューリトライ） |

#### 権限
- 訪問者（未認証）: 申込可
- 申込データの閲覧・編集は管理者のみ（UC-006）

### UC-003: 問い合わせ送信

**Actor**: サイト訪問者
**前提条件**: なし（未認証）
**関連要件**: F-003

#### 基本フロー
1. 訪問者が問い合わせフォームを開く
2. 氏名・メール・件名・本文を入力する
3. 送信する
4. システムが管理者へ通知する
5. 完了メッセージを表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| 氏名 | string | 必須 | 1〜100文字 |
| メールアドレス | string | 必須 | メール形式 |
| 件名 | string | 任意 | 最大200文字 |
| 本文 | text | 必須 | 1〜2000文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 送信完了メッセージ | string | フォーム送信後に表示 |

#### 業務ルール
- 問い合わせはUC-002の相談申込とは別データとして扱う（`Consultation`とは分離）
- スパム対策として送信頻度制限（レート制限）を設ける

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 必須項目未入力 | 422 | 入力内容に誤りがあります |
| 短時間の連続送信 | 429 | しばらく時間をおいてから再度お試しください |

#### 権限
- 訪問者（未認証）: 送信可
- 閲覧は管理者のみ（UC-006の一覧に統合表示）

### UC-004: 申込完了メール通知

**Actor**: システム（キュー経由の非同期処理）
**前提条件**: UC-002の相談申込、またはUC-003の問い合わせが正常に登録されていること
**関連要件**: F-004

#### 基本フロー
1. UC-002またはUC-003の登録完了をトリガーに、システムがメール送信ジョブをキューへ投入する
2. ワーカーがジョブを処理し、訪問者宛の完了メールと管理者宛の通知メールを送信する
3. 送信結果（成功/失敗）をログに記録する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| Consultation ID または問い合わせID | id | 必須 | 存在するレコードであること |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 訪問者宛メール | email | 申込内容の確認・今後の流れの案内 |
| 管理者宛通知メール | email | 新規申込のアラート |

#### 業務ルール
- メール本文にパスワード・APIキー等の機微情報を含めない
- 送信失敗時は最大N回リトライし、最終失敗時は管理画面にエラー表示する（具体的なリトライ回数はGate 3のアーキテクチャ設計で確定）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| メール送信プロバイダ障害 | - | ジョブを失敗としてキューに残し、管理者へエラー通知（画面表示） |

#### 権限
- システム内部処理のためユーザー操作なし

### UC-005: 管理者ログイン

**Actor**: 管理者
**前提条件**: 管理者アカウントが発行済みであること
**関連要件**: 全管理UC（UC-006〜UC-012）の前提

#### 基本フロー
1. 管理者がログイン画面でメールアドレス・パスワードを入力する
2. システムがLaravel Sanctumで認証する
3. 認証成功時、管理画面ダッシュボードへ遷移する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| メールアドレス | string | 必須 | メール形式 |
| パスワード | string | 必須 | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| セッション/認証トークン | - | HttpOnly Secure Cookie |

#### 業務ルール
- ログイン試行回数を制限する（レート制限、`.claude/rules/40-security.md`）
- 管理者アカウントはPhase 1では事業者本人の1アカウントのみを想定（[[project-summary]]）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| メール/パスワード不一致 | 401 | メールアドレスまたはパスワードが正しくありません |
| 試行回数超過 | 429 | しばらく時間をおいてから再度お試しください |

#### 権限
- 未認証ユーザー: ログイン試行のみ可
- 認証済み管理者: 管理画面全体へアクセス可（Policy/Gateにより機能別に制御、`.claude/rules/40-security.md`）

### UC-006: 相談・問い合わせ一覧管理

**Actor**: 管理者
**前提条件**: UC-005でログイン済みであること
**関連要件**: F-005

#### 基本フロー
1. 管理者が相談一覧画面を開く
2. システムがConsultation一覧（申込日時・氏名・ステータス等）を表示する
3. 管理者が個別の相談を選択し、事前アンケート（TravelProfile）の詳細を閲覧する
4. 管理者が相談ステータスを更新する（例: `pending` → `scheduled` → `completed`）
5. 問い合わせ一覧も同一画面または別タブで閲覧できる

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| ステータス更新値 | enum | 必須（更新時） | 定義済みステータス遷移のみ許可 |
| 管理者メモ | text | 任意 | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 相談一覧 | Consultation[] | ステータス・申込日時等でソート/フィルタ可能 |
| 事前アンケート詳細 | TravelProfile | UC-002で登録された全項目 |

#### 業務ルール
- ステータス遷移は事前定義された順序に従う（不正な遷移は拒否）
- 事前アンケートの機微になり得る項目（ナイトライフ関心度等）も管理者は閲覧できるが、第三者へ共有しない（一次資料14.5節）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 未認証アクセス | 401 | ログインが必要です |
| 不正なステータス遷移 | 422 | 指定されたステータスへは変更できません |
| 存在しないConsultationへのアクセス | 404 | データが見つかりません |

#### 権限
- 管理者: 閲覧・ステータス更新可
- 訪問者: アクセス不可（403、実際は認証必須のため401）

### UC-007: 旅行プラン作成・編集

**Actor**: 管理者
**前提条件**: UC-005でログイン済み。対象の相談（Consultation）が存在すること
**関連要件**: F-006

#### 基本フロー
1. 管理者が対象の相談（事前アンケート）を確認する
2. 管理者が新規旅行プラン（Trip）を作成し、日程（TripDay）ごとに固定項目・柔軟項目・代替候補を設定する
3. アクティビティ（Activity）をTripActivityとして各日に紐づける
4. 予算目安・全体メモを設定する
5. 管理者がプランをメール/PDFでユーザーへ共有する（共有自体は手動運用、システムはプラン内容の出力を提供）
6. 必要に応じてプランを再編集する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| Trip タイトル | string | 必須 | 1〜200文字 |
| 開始日／終了日 | date | 必須 | 開始日 ≦ 終了日 |
| TripDay ごとの固定項目 | text/JSON | 任意 | - |
| TripDay ごとの柔軟項目・代替候補 | text/JSON | 任意 | - |
| TripActivity（activity_id, 開始/終了時刻, 料金） | - | 任意 | activity_idは存在するActivityであること |
| 総予算目安 | decimal | 任意 | 0以上 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 作成/更新されたTrip | Trip | 日程別の詳細を含む |
| 共有用出力（PDF/メール本文） | - | 具体的な出力方式はGate 3で確定 |

#### 業務ルール
- 固定項目は全体の60〜70%、柔軟項目は30〜40%を目安とする（一次資料5.3節、運用ガイドラインでありシステム制約ではない）
- Puning・セスナ等、予約/天候依存のアクティビティは変更制限がある旨をプラン内にメモできる
- Tripは特定のConsultationに紐づく（Trip単体では作成しない）
- 対象の相談がプレミアムプラン（requirements.md 7節）の場合、プラン共有時に管理者のオンサイトサポート連絡先（電話/LINE等）をあわせて案内する。これは運用上の案内であり、システムによる自動送信・チャット機能の追加は伴わない

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 開始日 > 終了日 | 422 | 終了日は開始日以降の日付を指定してください |
| 存在しないactivity_idの指定 | 422 | 指定されたアクティビティが存在しません |
| 未認証アクセス | 401 | ログインが必要です |

#### 権限
- 管理者: 作成・編集・閲覧可
- 訪問者: アクセス不可（プランはメール/PDFで個別共有、UC-002参照）

### UC-008: アクティビティ管理（CRUD）

**Actor**: 管理者
**前提条件**: UC-005でログイン済み
**関連要件**: F-007

#### 基本フロー
1. 管理者がアクティビティ一覧画面を開く
2. 新規アクティビティを登録、または既存アクティビティを編集・削除（公開停止）する
3. 名称・カテゴリ・所在地・説明・所要時間・料金帯・体力レベル・天候依存・要予約フラグ・法務/安全注意事項・公開ステータスを設定する
4. 保存すると公開サイト（UC-001）に反映される

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| 名称 | string | 必須 | 1〜100文字 |
| slug | string | 必須 | 一意、URL安全文字列 |
| カテゴリ | enum（Relax/Adventure/Executive等） | 必須 | 定義済み選択肢 |
| 説明 | text | 必須 | - |
| 所要時間 | integer（分） | 任意 | 0以上 |
| 料金帯（最小/最大） | decimal | 任意 | 最小 ≦ 最大、0以上 |
| 体力レベル | enum | 任意 | 定義済み選択肢 |
| 天候依存フラグ | boolean | 任意 | - |
| 要予約フラグ | boolean | 任意 | - |
| 法務/安全注意事項 | text | 任意 | - |
| 公開ステータス | enum（下書き/公開） | 必須 | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 作成/更新/削除結果 | Activity | 公開ステータスに応じてUC-001に反映 |

#### 業務ルール
- 削除は物理削除ではなく非公開化（論理削除/ステータス変更）を基本とする（TripActivityから参照されている場合の整合性を保つため）
- 一次資料1.4節・15.2節の対象外行為（性的サービス関連等）に該当する内容は登録できない（運用ルールとして管理者が遵守。システム上のバリデーションは対応しない）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| slug重複 | 422 | このURLは既に使用されています |
| 必須項目未入力 | 422 | 入力内容に誤りがあります |

### UC-011: 簡易売上管理

**Actor**: 管理者
**前提条件**: UC-005でログイン済み。対象のConsultationが存在すること
**関連要件**: F-010

#### 基本フロー
1. 管理者が売上管理画面を開く
2. Consultationに紐づく料金（requirements.md 7節の料金プランに基づく）・支払いステータスを記録する
3. 期間別の売上集計を閲覧する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| 料金プラン | enum（ライト/スタンダード/プレミアム） | 必須 | requirements.md 7節の3プランのいずれか |
| 金額 | decimal(15,2) | 必須 | 0以上。通常はrequirements.md 7節の料金プラン固定額（ライト5,000円/スタンダード25,000円/プレミアム40,000円）を初期値とし、個別事情がある場合のみ管理者が金額を変更可能 |
| 支払いステータス | enum（未払い/支払済み） | 必須 | - |
| 支払日 | date | 任意（支払済み時は必須） | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| 売上一覧 | Consultation[]（fee/payment_status付き） | 期間・ステータスでフィルタ可能 |
| 期間集計 | decimal | 月次等の合計金額 |

#### 業務ルール
- Phase 1ではオンライン決済を行わないため、支払いステータスは管理者が手動で更新する（銀行振込等のオフライン決済を前提）
- 金額は`decimal(15,2)`を使用し、float/doubleは使用しない（`.claude/rules/20-mysql.md`）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 支払済みなのに支払日未入力 | 422 | 支払日を入力してください |
| 未認証アクセス | 401 | ログインが必要です |

#### 権限
- 管理者: 閲覧・更新可
- 訪問者: アクセス不可
