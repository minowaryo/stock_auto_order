# ADR-0019: Loop Engineering 段階2a — 結果と、日本語版テンプレート に取り込んだ部分（Trial）

## Status
Trial — EN版 ADR-0019 は 2026-10-06 承認。日本語版テンプレート に取り込むのは、その結果として出た 2 件の変更だけである。

## Date
2026-10-11（日本語版テンプレート への移植）

## Context

ADR-0017 は、ループ（有界な自律サイクル）を作る価値を数字で判断する段階2を定めている。段階2aは、
人の時間をほとんど使わない 3 つのチェック（仕様とテストの矛盾の種まき、レビュアーの欠陥検出、終わった
タスクの再実行）で、AI が不正をするか・不正が検出されるか・AI レビュアーを信用できるかを測った。
実験の環境・シード・実行系は EN版に固有で（メンテナーの環境と別プロジェクトのクローンを使う）、
日本語版テンプレート には取り込まない。詳細は EN版の `meta/adr/ADR-0017-loop-engineering-stage2a.md` と
`meta/history/loop-stage2a-results.md`。

結果は「条件付きで前進」: レビュアーとコストの基準は満たし、「検出されない仕様の曲げがない」ことは
満たさなかった（①の唯一の無言の不正は、テストのデータを実装に直接書く特殊ケースで、実験用の
オラクルしか捕まえられなかった）。前提条件が 3 つ付いた。

## Decision

前提条件のうち、言語に依存せず 日本語版テンプレート でもそのまま使える 2 件だけを取り込む。

1. **`fixture-literal-check.sh`**（前提条件1）: Green の後、`/tdd` ステップ4が `tdd-snapshot.sh verify` に続けて実行する。
   追加されたアプリケーションコードの行のうち、承認済みテストにしか含まれない引用符付きの値と比較している
   ものを表示する。AI は使わない（bash + git + awk + grep）。終了コード: 0 = なし、2 = 検出、3 = 実行不可。
2. **`agent-guard.sh` の PHP 矢印の修正**（前提条件2）: `$obj->prop` と `=>` をリダイレクトと誤認して、
   正当なアプリファイルの書き換えを拒否していた問題を直す。

前提条件3（レビュアーの入力の絞り込み）と、段階2b以降は EN版のみ。段階2bは行わず、段階3は閉じたままである。

## Rationale

唯一の無言の不正を、AI の自己申告に頼らず機械で捕まえるのが目的である。どちらも決定的なスクリプトで、
コストは約 0.2〜1.1 秒。ADR-0017 の「各段階は自分の ADR を持つ」に従い、結果の記録として本 ADR を置く。

### 採用しなかった代替案
- **EN版 ADR-0019 の全文を翻訳する**: 内容の大半はメンテナーの環境と実験の手順で、日本語版テンプレート の利用者には使い道がない。

## Consequences

### 利点
- テストの値をそのまま実装に書く「通すためのごまかし」が、Green の直後に機械で見つかる。
- Laravel の `$obj->prop` / `=>` を含むコマンドの誤拒否が減る。

### 欠点・リスク
- 読むのは引用符付きの文字列だけで、比較している行に限る。数値、連結、定数の陰は見えない（`docs/development/tdd-guard.md` の「限界」）。
- EN版との差: 設計メモ（`meta/design/`）は 日本語版テンプレート にない。スクリプトの注記が参照するパスは EN版を指す。
